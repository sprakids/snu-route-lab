### 실제 한 시간 읽어 보기

11월 18일 18~19시 제2공학관에서 타고 낙성대역 또는 낙성대입구에서 내린 카드 승객은 **141명**이었습니다. 같은 조건의 예측은 V12 **25.5명**, V13 **48.4명**이었습니다. V13의 절대오차는 둘의 차이인 **92.6명**입니다. 반대로 같은 시간·같은 정류장의 서울대입구역 방면은 실측 **54명**에 V12 **51.4명**, V13 **94.5명**이었습니다. 평균이 좋아져도 시간과 방면에 따라 오차가 커질 수 있습니다. [시간·정류장·방면별 원표](shuttle_analysis/261127183058/boardings.csv)

모의 인원에 소수가 나오는 이유는 통행 표본 하나가 일정한 인원 몫을 대표하기 때문입니다. 예측 48.4명은 그 가중치를 합한 값입니다. 평균절대오차(MAE)는 각 칸의 ‘예측과 실측의 차이’에서 부호를 없앤 뒤 평균낸 값입니다. 적게 예측한 낙성대행과 많이 예측한 서울대입구역행이 서로 상쇄되지 않습니다.

## 학생 한 명의 하교를 어떻게 그리나요?

1. **어디서 언제 출발하는지 정합니다.** 수업의 종료 시각, 건물, 수강 인원에서 출발 후보를 만들고 시간대에 따라 바로 하교하거나 더 머물 확률을 적용합니다. 수강편람은 한 학생의 하루 전체 시간표나 실제 퇴실 시각을 보여 주지 않으므로 하교 인원은 모형으로 추정합니다. [수업 자료와 초기 계산](shuttle_analysis/course_demand_2026-11-06/시뮬레이션_결과와_가정.md)
2. **목적지와 가는 방법을 정합니다.** 서울대입구역·낙성대·대학동·기숙사·관악산역 접근을 구분합니다. 걸어갈 거리와 경사, 배차, 셔틀 선호에 따라 정류장까지 걸어가거나 목적지까지 걷습니다. 대학동의 개인형 이동장치는 도보 몫에 포함합니다. 신림선 수요는 카드 자료에서 추정한 시나리오입니다. [신림선 수요의 근거](shuttle_analysis/sillim_ridership_2026-11-24/신림선_학생_하교수요의_범위.md)
3. **버스와 사람이 만나는 순서대로 계산합니다.** 승객은 정류장에서 기다리고, 빈자리가 있는 만큼 차례로 탑니다. 줄이 길거나 만차를 반복해서 만나면 일부는 다른 노선이나 도보를 선택합니다. 행정관에서는 정차 중에 미리 탄 인원과 밖에 남은 인원을 따로 셉니다. 따라서 승차지 선택을 바꾸면 인근 정류장의 대기도 바뀔 수 있습니다. [행정관 셔틀 운행·승차 기준](shuttle_analysis/261125170855/README.md)
4. **실제 승차와 비교합니다.** V13은 같은 버스·같은 하차 정류장에 닿을 수 있는 제1·제2공학관 선택을 소폭 바꾸고, 17~21시 302동에서 출발할 비중을 조정했습니다. 여섯 조건을 네 날짜에서 비교해 한 조건을 고른 뒤, 위의 다른 두 날짜에 그대로 적용했습니다. 두 배차 × 평일 5일 모두 하루 총인원을 보존했고, 모의 차량 정원 위반·목적지 미도착·한 정류장의 20분 초과 연속 대기는 0이었습니다. [조건과 선택 근거](shuttle_analysis/261127183058/설계.md) · [요일별 인원과 최장 대기](shuttle_analysis/261127183058/weekday_checks.csv)

카드에는 학생 신분, 출발 건물, 귀가 목적이 없습니다. 정류장에서 기록된 것은 일반 승객을 포함한 승차이고, 모형의 출발 집단은 수업 자료에서 추정한 하교생입니다. 특히 제2공학관 저녁의 낙성대 방면은 아직 크게 적게 예측합니다. 두 날짜로 학기 전체의 정확도를 판단하기는 어렵습니다.

## Windows에서 결과를 확인하는 방법

### 용량이 왜 큰가요?

정리 전에는 요일·배차별 재생 파일이 **16.11GB**, 승객별 이동과 차량별 승차 순서를 검산하는 원장(`audit-*.json.gz`)이 **14.49GB**였습니다. 목요일 저녁의 정류장 선택을 조금 바꿔도 누가 먼저 타고 누가 다음 버스를 기다리는지가 달라져 조건마다 기록이 생겼기 때문입니다.

**V10·V11·V12·V13은 평일 5일 × 두 배차, 총 40개 정식 원장을 보존했습니다.** 각 R 실험의 코드·설정·결과표와 현장 실측도 보관합니다. 내용이 같은 비압축 재생 파일 513개(11.35GB), 다시 만들 수 있는 R 상세 기록 1,167개(13.53GB)를 정리해 원래 작업 폴더가 **46.32GB에서 21.44GB**로 줄었습니다. 로컬 크기에는 제공처에서 받은 교통카드 원본도 들어갑니다. 정식 V13의 채점이 직접 참조하는 대조 원장은 함께 제공합니다. [정리 내역](archive/cleanup.json) · [정식 원장과 재실행 검산](archive/cleanup-verification.json)

| 하려는 일 | 받으면 되는 자료 |
|---|---|
| 프로젝트를 이해하고 실측·예측을 비교 | GitHub에서 이 문서와 결과표 열기 |
| 목요일 피크 등 V13을 직접 재계산 | 저장소 + `v13-inputs.zip` **약 192MB**. 저장소의 연구 파일은 펼친 크기 약 469MB |
| 정식 원장과 연구 자료 전체 복원 | 저장소 + 릴리스 ZIP 13개, 합계 **5.33GB**. 이 합계에 `v13-inputs.zip`도 포함 |

**표만 보려면** 위 링크를 열면 됩니다. 내려받은 저장소에서 예제 한 시간을 확인하려면 Python 3.12가 설치된 PowerShell로 아래 명령을 실행하세요. 결과 조회에는 추가 패키지와 대용량 자료가 필요 없습니다.

```powershell
py -3.12 shuttle_analysis/261127183058/example.py 20261118 18
```

**시뮬레이션을 직접 다시 계산하려면** 저장소를 짧은 경로에 내려받고 아래 순서를 따르세요. 릴리스의 `v13-inputs.zip`에는 평일 열 조건의 재실행에 필요한 대용량 입력이 모여 있습니다. 저장소의 작은 원본 파일과 함께 사용합니다. [다운로드할 릴리스 파일](https://github.com/sprakids/snu-route-lab/releases/latest)

1. `v13-inputs.zip`을 내려받아, 예를 들어 `C:\snu-data`에 둡니다. 압축 파일 자체를 복원 도구에 넘깁니다.
2. 엔진의 수치 검산과 지도 자료 읽기에 쓰이는 NumPy와 Pillow를 설치합니다. 이어서 목요일 피크 배차 입력을 복원하면 도구가 파일 지문(SHA-256)을 확인합니다. 마지막 명령은 새 결과를 `rerun\runs\V13\peak-thu`에 만듭니다.

```powershell
py -3.12 -m pip install numpy pillow
py -3.12 archive/restore.py C:\snu-data --inputs peak-thu
py -3.12 shuttle_analysis/261127183058/v13.py thu peak --output rerun
```

**이전 버전까지 전체 자료를 복원하려면** 같은 릴리스의 모든 ZIP을 한 폴더에 모은 뒤 `py -3.12 archive/restore.py C:\snu-data`를 실행하세요. 버전별 원장과 배포 사본은 용량이 커서 릴리스에 담았고, 중복 파일은 같은 내용으로 복원합니다. 파일별 위치와 지문, 제외한 원자료와 사유도 기록했습니다. 개인별 교통카드 원본은 제공처에서 내려받도록 출처와 집계 방법을 넣었습니다. 현장 관측은 인원과 시각으로 공유하며 개인 대화·계정 화면과 인증 정보는 보관본에서 제외했습니다. ### 옛 R 상세 기록이 다시 필요할 때

- **압축본이 남은 원문 JSON**은 같은 폴더의 `.json.gz`를 복원한 뒤 `py -3.12 archive/restore_replays.py "프로젝트/상대경로.json"`으로 꺼냅니다. 원래 파일과 바이트가 일치하는지 자동으로 검사합니다. [바로 복원할 수 있는 원문](archive/replay_copies.csv.gz)
- **R의 상세 모의 기록**을 다시 만들 때에는 해당 실험 폴더의 입력·실행 코드와 보존된 결과표를 사용합니다. 예를 들어 `py -3.12 shuttle_analysis/261127183058/v13.py wed peak r40g20 --output rerun`은 최종 보정 때의 수요일 R을 별도 폴더에 생성합니다. 예전 `261116161819` 실험에서는 `run_case.py anchor-combined-regular-fri --attempt 99`처럼 사용하지 않은 회차를 지정합니다. 옛 실험은 전체 자료 복원 후 실행하세요. 이 금요일 사례를 다시 계산해 승객 이동 원장과 지도 재생 파일 모두 압축 해제 후 원래 SHA-256과 일치함을 확인했습니다. [다시 계산하는 기록의 경로와 기존 지문](archive/regenerable_runs.csv.gz)
