# 8개 노선 수집 확장과 현재 운영 한도

2026-11-07 사용자 최종 선택: 15,000회 증량은 더 진행하지 않고 기존 승인 한도 10,000회에서 8개 노선을 운영한다.

## 적용 상태

- 공개 앱: https://snu-route-lab.vercel.app, v0.7.0.
- 대상: 5511·5513·5516·관악02-1·관악02-2·5515·5528·6515.
- 추가 ID: 5515=100100252, 5528=100100263, 6515=100100521.
- 공식 노선 응답으로 세 노선의 서울대학교 120000029/ARS21128 → 서울대입구역2번출구 120000150/ARS21252 방향을 확인했다. 6515의 반대편 정류장과 구분한다.
- 추가 3개 노선을 포함한 8개 노선의 첫 관측이 2026-11-07 23:10 KST 회차에 오류 없이 저장됐다. 수집시간 밖에는 마지막 관측 시각을 표시하며 차량 운행 종료로 단정하지 않는다.
- 공개 앱에도 8개 노선의 공식 도로 좌표와 경로 후보를 반영했다. 실제 혼잡 등급이 없는 차량은 정보 부족으로 유지한다.

## 현재 갱신 정책

수집시간은 매일 11:20~23:10 KST다. 노선별 위치 요청 1회를 1건으로 계산한다.

| 구분 | 정기 호출 | 재조회 예비 | 앱 상한 |
|---|---:|---:|---:|
| 평일: 15~19시 16초, 그 외 120초 | 9,088 | 712 | 9,800 |
| 주말: 120초 | 2,848 | 352 | 3,200 |

평일 계산: 피크 14,400초/16초×8=7,200회, 나머지 235회×8=1,880회, 마지막 8회. 원본 시각 반복·저장소 보호 조건에서는 실제 호출을 줄인다. 화면 카운트다운과 지도 애니메이션은 위치 API를 호출하지 않는다.

향후 승인 한도가 15,000회로 확인되고 사용자가 증량 운영을 다시 요청하면 15초 정책을 적용할 수 있다. 이 경우 정기 9,568회+예비 832회=10,400회다. 현재는 활성화하지 않았다.

## 저장소 검증

기존 원본은 보존하고, 최신 위치와 원본 바이트 계수를 한 행에 함께 저장하도록 개선했다. 중복 장부 쓰기를 제거하고 사용량 체크포인트를 묶었다. 일별 원본 크기 조회는 최초 마이그레이션 후 누적값을 사용하며, 노선·날짜 집계 조회에는 인덱스를 추가했다. 요청 전 영구 호출 예약은 유지한다.

현재 9,800회보다 부하가 큰 가상 10,400회/일·8개 노선·노선당 80대·서로 다른 정류장과 혼잡등급 조건으로 검증했다.

| 항목 | 보수적 모의 추정 |
|---|---:|
| 수집 쓰기 | 64,190행 |
| 부가 캐시·기록 쓰기 | 8,991행 |
| 예약 작업·만료 정리 여유 | 10,000행 |
| 합계 | 83,181행/일 |
| 모의 읽기 | 111,148행 |
| 압축 원본 | 약 17.47MB/일 |
| 일별 위치 통과·혼잡 집계 | 약 2.52MB/일 |
| 구간속도 집계 | 약 0.15MB/일 |
| 원본 30일+집계 365일 투영 | 약 1.50GB |

테스트 어댑터의 쓰기 추정은 변경 행 수의 3배를 사용하며, 알람 쓰기도 별도 가산했다. 이는 실제 서울시 API 10,400회 호출이나 계정 전체 청구량 측정이 아니다. 보관량은 인덱스·SQLite 여유공간·다른 프로젝트를 제외한 합성자료 투영이며, 2배 여유를 적용하면 약 3.00GB다.

[Cloudflare 무료 한도](https://developers.cloudflare.com/durable-objects/platform/pricing/)는 쓰기 100,000행/일, 읽기 5,000,000행/일, 저장 5GB이며 UTC 자정에 일일 한도가 초기화된다. 이 앱은 주요 쓰기 목표 70,000행, 부가 쓰기 9,000행 제한, 전체 추적 쓰기 85,000행 중단 및 저장량 보호를 적용한다. 다른 프로젝트까지 포함한 무료 이용량을 보장하지 않는다.

## 과거 자료와 분석

- 기존 5개 노선의 과거 예측 파일 바이트를 보존했다.
- 이미 보관한 T-data 전체 서울 응답에서 추가 3개 노선의 223개 구간·20개 기존 학습 날짜를 재사용했다. 새 API 호출과 새 계수 선택은 없었다.
- 추가 구간의 요일·시간 예측값 12,265개를 독립 산술 검산했고 최대 반올림 차이는 4.29e-7이다.
- 전체 과거 예측 대상은 482개 구간이다. 시간당 재차합은 차량 한 대의 혼잡 등급이나 대기 인원이 아니다.
- 과거 GPS 위치를 T-data 재차합에서 복원하지 않는다. 새 위치·혼잡 관측은 이번 수집 시작 이후 기록을 쌓는다.
- 시간 지정 계산은 완료된 이전 날짜 기록과 시간표를 사용하며 최신 차량 위치를 사용하지 않는다.

## 신청 상태를 구분

기존 운영계정의 실제 승인 한도는 10,000회다. 정식 변경 버튼이 빈 운영계정 신청서로 연결됐고, 조회 기능을 하나만 선택해도 일일 트래픽은 수정 불가능한 10,000회 표시였다. 따라서 15,000회 정식 변경 신청이나 승인은 완료하지 못했다.

사용자 승인으로 별도 '오류신고 및 담당자 문의'에 증량·정식 절차 안내 요청이 접수됐다(88269). 포털 분류는 오류신고이며, 정식 트래픽 변경 신청을 대신하지 않는다. 이후 사용자는 현재 한도에서 8개 노선 운영을 선택했다. 문의를 자동 취소하거나 추가 증량 신청을 진행하지 않았다.
