# 윗공대 하교 인원과 제2공학관 승차 선택을 따로 바꾸는 실험

정식 V12(V261125170855)를 대조군으로 삼는다. 앞선 체류 실험에서 제2공학관의 시간대별 승차 비중을 옮길 수 있었지만 하루 승차 건수를 설명하기 어려웠다. 이번에는 V12의 체류와 배차를 기준으로 삼아 수요의 크기와 승차지 선택을 분리한다. 윗공대는 300·301·302동에서 끝나는 수업이다.

| 조건 | 윗공대 하교 생성 | 제2공학관 첫 승차 선택 |
|---|---|---|
| V12 | 기존 | 기존 |
| 인원 | 하교 오즈 2배 | 기존 |
| 승차 선택 | 기존 | 선택 오즈 2배 |
| 결합 | 하교 오즈 2배 | 선택 오즈 2배 |

오즈는 확률을 그 여사건의 확률로 나눈 값이다. 두 배로 하면 확률 p는 2p/(1+p)가 된다(예: 50%→66.7%). 두 배는 효과를 비교하려고 사전에 고른 민감도이며 실측 추정치가 아니다.

1. **인원.** 각 수업의 기존 하교 통행 무게를 수강인원으로 나눈 확률을 기준으로 윗공대 통행을 늘린다. 같은 수업 종료 시간대(정시 단위)·같은 목적지에서 다른 권역의 통행을 기존 무게에 비례해 줄인다. 해당 셀의 다른 권역에서 확보할 수 있는 범위를 초과해서 옮기지 않는다. 원장에 있는 모든 수업의 수강인원 상한과 요일별 캠퍼스 총량, 목적지별·종료시간대별 총량을 검산한다. 이는 전체 하교량을 추가하는 조건이 아니라 고정된 전체에서 윗공대의 몫을 높이는 조건이다.
2. **승차 선택.** 윗공대 출발 건물·출발 좌표·목적지·건물 출발 30분대가 모두 같은 집단에서 제2공학관 시내버스를 첫 차량으로 선택한 기존 비율을 구한다. 선택 오즈가 두 배가 되도록 다른 선택자 중 p/(1+p)의 확률로 전환한다. 선택 확률이 원래 0 또는 1인 집단에는 그대로 적용되며, 대상자의 보행속도로 운행 종료 전에 목적지까지 닿을 수 있는 원래 경로만 쓴다. 수업 종료·건물 출발 시각과 개인의 보행속도는 그대로다. 모든 조건에 같은 표본 난수를 쓰고 결합 조건에도 동일한 경로 변경을 적용한다. 줄을 본 뒤 경로를 바꾸거나 만차로 못 타는 행동은 엔진에서 다시 계산한다.
3. **고정 조건.** 별도로 정해 둔 신림선행 집단은 모든 조건에서 사람별 통행 무게·최초 경로·시각을 유지한다. 기준·피크 각각 실제 차량 공급 원장의 운행 시각·정원·셔틀 승차 가능 시간과 대조한다. 승객별 무게, 대기열, 선착순, 탑승과 하차도 기존 독립 검산으로 확인한다.
4. **비교.** 목요일에 두 배차에서 세 조건을 모두 실행한다. 11월 5일 15~19시 제2공학관에서 승차하여 교외에서 하차한 시간당 카드 건수, 4시간 합계와 오차를 평가한다. 같은 시간의 제1공학관·공대입구·나머지 정류장도 비교한다. 결합 조건은 월~금 두 배차로 실행하여 현장 대기 관측, 다른 날짜의 동일 노선·순번·정류장 하루 승차(모든 하차지), 장시간 대기를 확인한다.

모의 윗공대 출발 인원, 최초 계획에서 제2공학관을 고른 비율, 실제 모의 통행에서 첫 차량을 그곳에서 탄 비율을 각각 기록한다. 카드 승차 비교에서는 출발 건물이나 첫 차량 여부를 제한하지 않는다. 카드와 분모·집계 단위가 다르기 때문이다. [실험 코드](experiment.py) · [이전 체류 실험](../261127155542/README.md)

추가로 실제 줄을 관측한 월·화·수요일의 피크 배차에서 인원 단독·승차 선택 단독을 각각 돌린다. 두 조정이 기존 대기줄 예측에 각각 얼마나 영향을 주었는지 분리하기 위한 비교다.

## 재현

프로젝트의 NumPy가 설치된 Python으로 이 폴더에서 `python -B experiment.py thu peak origin`처럼 실행한다. 요일은 `mon`부터 `fri`, 배차는 `regular` 또는 `peak`, 연구 조건은 `origin`(인원), `choice`(승차 선택), `both`(결합)이다. 결합 조건은 5일×2배차 10개, 단독 조건은 목요일 2배차×2요인 4개와 월·화·수 피크×2요인 6개다. 종료한 실행은 `runs/조건/배차-요일/summary.json`에 저장된다. 20개가 준비되면 `python -B evaluate.py`, `python -B verify_thursday.py`, `python -B report.py` 순서로 실제 카드·현장 대조표, 독립 검산, 연구 보고서를 재생성할 수 있다.
