# 실험실 대기모델 자동 연동

사용자 지정 이름은 **한국시간 `YYMMDDHHmmss`**(예: `261109145204`)입니다. 알고리즘 ID, 입력 스키마, 시뮬레이션 버전은 별도 필드로 유지합니다. 같은 이름의 내용은 변경하지 않습니다. 입력이 같으면 기존 이름을 재사용합니다.

1. 시뮬레이션과 독립 검증을 완료합니다. 원본·감사 자료를 보존합니다.
2. 새 소스 디렉터리/공개 재생 버전으로 바뀌면 `deployment/queue_source.json`을 수정합니다. 현재 어댑터는 검증된 v5 FIFO 계약을 지원합니다. 다른 알고리즘·노선·정원·운행 시계 변경은 호환 어댑터를 먼저 개발해야 합니다.
3. 시뮬레이션 루트에서 `python deployment/prepare_static.py`를 실행합니다. 이 단계가 전체 월~금 감사 자료에서 대기모델을 생성하고, 질량 보존·정원·정류장 대응·공개 재생 버전 일치를 확인합니다. 앱 파일과 원본 시뮬레이션은 수정하지 않습니다.
4. `deployment/static_site`를 기존 `snu-shuttle-simulation` 프로젝트에 배포합니다. 미리보기에서 `/routing-model/latest.json`과 해당 릴리스의 해시를 확인한 뒤 운영에 반영합니다. 로컬 생성만으로 운영 앱의 모델이 바뀌지는 않습니다.

공개 파일은 `public/routing-model/latest.json`과 `public/routing-model/releases/<모델이름>.json`입니다. 후자는 수업·보행 결과에서 집계한 가중 유입·OD·이탈 시각이며, 학생별 원본이나 실측 대기 인원을 공개하지 않습니다. 기존 릴리스는 보존합니다. 원본 검증과 집계 검증은 예측 정확도의 현장 검증과 구분합니다.

시내버스 8개 노선은 `city_wait` 구성요소를 함께 발행합니다. 정류장 ID와 원문 순번·방향을 대조하고, 원본 v5의 상류 재차와 조건부 대기 흐름에서 가상 1인 FIFO 승차를 5분마다 3개 위상으로 조회합니다. 정문 공동노선은 같은 물리 대기줄에서 호환되는 노선만 함께 처리합니다. 후속 새 유입은 앞서 끼어들지 못하며, 원본 경로 전환 이탈은 원본 시각에 제거합니다. 이 계산이 원래 전체 집단을 다시 시뮬레이션하는 것은 아닙니다. 일부 위상이 막차 전에 승차하지 못하면 승차한 위상만 평균 내지 않습니다. 시내버스 참조 정원 50/24는 원본 시나리오 가정이고 실제 차량 여석이 아닙니다.

경로 앱은 실제 도착예정을 먼저 사용하고 시뮬레이션의 추가 승차 지연과 이전 날짜의 만차 플래그 위험을 결합합니다. 두 지연은 같은 용량 손실을 중복 반영하지 않도록 큰 값을 사용합니다. 지연을 반영한 예상 승차시각에 실제 차량 ID를 붙이지 않습니다. 원래 실제 버스 도착정보는 따로 유지합니다. 혼잡등급을 인원이나 여석으로 환산하지 않습니다. `calibrated=false`이며 혼잡등급·만차 플래그는 실제 줄 길이나 탑승 실패의 관측과 구분합니다.

공용 수집기의 `route_stats`에는 동일 차량·운행·구간에서 중복을 제거한 혼잡등급, 알려진 만차 플래그, 확인된 정류장 통과간격을 기존 저장 행에 묶습니다. 플래그 미제공은 여유 차량 표본으로 기록하지 않습니다. `/history`가 완료된 이전 날짜의 집계만 앱에 제공하며, `/recording`은 실제 저장 건수를, `/aggregate`는 기존·새 저장형식 모두의 혼잡 집계를 반환합니다. 원본 30일·집계 365일 보관과 호출 예산은 유지합니다. 객체별 저장 용량은 900MB 기준으로 별도 감시하고 기존 90% 중단 규칙을 적용합니다. 실제 계정 공유 사용량은 별도일 수 있습니다.

대기 정확도가 실측으로 입증됐다고 표시하지 않습니다. 기존 혼잡 예측의 28일(14일 보정·7일 선택·7일 최종 검증) 승격 기준을 유지합니다. 실제 대기시간 정확도에는 대기 시작·실제 탑승 등 추가 대기 결과 관측이 필요합니다.

경로 앱의 서버 인스턴스는 요청이 있을 때 최대 60초에 한 번 발행 목록을 확인합니다. 새 릴리스만 본문을 다운로드하며, SHA-256·스키마·노선/시계·질량 보존을 검증한 새 객체로 교체합니다. 진행 중인 요청은 기존 객체로 끝까지 계산합니다. 접속·검증 실패 때는 마지막 정상 객체(새 서버 시작 시 내장 모델)를 사용하고 다음 확인 때 재시도합니다. 알고리즘 코드는 다운로드하지 않습니다.

경로 앱 재배포는 호환 데이터 업데이트마다 필요하지 않습니다. `/api/queue-model`과 `/api/plan`의 `prediction_model.queue_release`에서 실제 적용 이름·해시·확인 상태를 확인할 수 있습니다. 서울시 API 호출·수집 장부·SQLite 쓰기는 추가하지 않습니다. 캐시는 서버 메모리이므로 새 서버가 시작되면 다시 확인합니다. 로컬 개발에서도 연동하려면 `SNU_QUEUE_MODEL_SYNC=1`을 설정합니다.
