## 무엇이 느렸나

1. 공통 지도 자료(해석 전 원문 19.76MB)와 전체 그래프 자료를 먼저 받고, 그 뒤에 선택 요일 이동 자료(월요일 19.09MB)를 요청하는 두 단계 구조였습니다. 선택 요일 다운로드가 늦게 시작했습니다.
2. 3.26MB 그래프 JSON을 처음에 읽고 요일 선택 함수에서 다시 읽었습니다. 실제 그래프는 별도 30분 통계와 요일별 대기열을 사용하므로, 이 파일에서는 이전 참고표 16.7KB만 필요했습니다.
3. 선택 요일/정책을 바꿀 때마다 그래프·30분 통계를 다시 요청했습니다. 과거 요일 재생자료는 계속 메모리에 쌓이고 있었습니다.
4. 웹 글꼴 3개, 합계 2,271,380바이트가 모델 파일과 동시에 회선을 사용했습니다. 글꼴 자체가 JSON을 막는 것은 아니지만, 제한된 다운로드 대역폭을 나눠 썼습니다.
5. 버전별로 내용이 고정된 데이터도 매번 서버 재확인을 요구했습니다.

## 적용한 변경과 이유

- 공통 지도·선택 요일·30분 통계를 동시에 받습니다. 독립된 파일 사이의 기다림을 없앴습니다.
- 큰 charts.json 두 번 대신, 원래 참고표와 값이 같은 작은 공유 파일을 사용합니다. v3~v7의 참고표가 모두 같은지 비교했습니다. 원래 charts.json은 공개 주소와 로컬에 보존했습니다.
- 같은 URL의 진행 중 요청과 해석 결과를 공유하고, 완료된 재생자료는 최근 4개, 메타자료는 최근 8개까지만 보관합니다. 불러오는 중인 요청은 중복 실행하지 않습니다. 실패한 요청은 재시도할 수 있도록 캐시에서 제거합니다.
- 처음에는 운영체제 글꼴로 표시하고, 모델 사용이 가능해진 뒤 기존 웹 글꼴을 적용합니다. 최종 글꼴·배치·기능은 유지했습니다.
- 버전별 /data 파일은 브라우저에서 장기 재사용합니다. HTML·JS와 routing-model/latest.json은 계속 새 버전을 확인합니다. 이후 수치 자료를 바꿀 때는 새 데이터 버전/경로를 사용해야 합니다.
- 이후 패키징에서도 유지되도록 prepare_static.py의 파일 목록·캐시 설정과 city.html 생성기의 초기 표시 속성을 수정했습니다. 자동 모델 발행기는 실행하지 않았습니다.
