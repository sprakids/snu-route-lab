# 대기줄을 보고 경로를 바꾸는 하교 시뮬레이션 v4

이 문서는 2026-11-07 지도 시뮬레이터에 추가한 행동과 자료를 설명한다. 실제 학생들의 행동을 조사해 적합한 예측모형은 아니다. 기존 수강 편람·목적지 비중·기숙사 비율의 출처와 한계는 `팀공유_시뮬레이션_설명서_자료출처.md`의 v3 설명을 함께 읽는다.

## 사용 방법

Windows 공유 ZIP을 모두 압축 해제한 후 `시뮬레이션 실행.exe`를 실행한다. Python·Node·Codex 설치는 필요 없다. 기존 로컬 서버 사용자는 기본 지도 또는 `adaptive.html`에서 볼 수 있다.

1. **대기줄을 본 뒤 → 경로 변경**을 선택한다. **기존 경로 유지**는 이전 v3를 그대로 재생하는 비교 조건이다.
2. 요일·배차·승차 정류장·시각을 선택한다. 1초/초 재생을 유지한다.
3. **경로 변경 장면**을 누르면 실제로 모형의 변경 사건이 발생한 시각과 보행 경로로 이동한다. 청록색 점은 변경 뒤 걷는 흐름이다. 빨간 점은 현재 만차로 남은 흐름이다.
4. 그래프에는 탑승한 흐름의 평균 대기 외에 **경로 변경 가중치**를 별도 표시한다. 줄을 떠난 사람을 탑승자 평균에 넣거나 미탑승으로 세지 않는다.

## 무엇을 보고 언제 바꾸는가

최초 출발 경로와 이동량은 v3와 동일하다. 셔틀 정류장에 도착해 승차 준비 20초를 마쳤을 때, 대기 중 60초마다, 만차로 못 탄 뒤에 다음을 비교한다.

> 현재 경로를 유지할 때 예상 목적지 도착시각 vs. 지금부터 다른 경로를 택할 때 예상 목적지 도착시각

이미 기다린 시간은 되돌릴 수 없으므로, 두 선택의 **앞으로 남은 시간**을 비교한다. 목적지는 원래 배정된 목적지로 유지한다.

| 항목 | 구현한 가정 | 이유·한계 |
|---|---|---|
| 현재 셔틀 예상 대기 | 자기 앞 줄의 가중치, 예정 차량 도착시각, 차량별 정원, 모형 내 현재 차내 승객과 앞서 하차할 승객을 바탕으로 가능한 차량을 찾음 | 평균 배차간격의 절반만으로 만차를 설명할 수 없어서 추가. 실제 학생이 여석을 이 정도로 아는지는 확인하지 않음 |
| 미래 유입 | 현재 이후에 새로 올 학생은 예측에 넣지 않음 | 미래 대기열을 미리 알고 최선의 선택을 하는 방식은 아님. 이 때문에 예상보다 늦게 탈 수도 있음 |
| 대안 | 목적지까지 직접 도보, 다른 시내버스·셔틀 직행/최대1회 환승, 서울대학교 정류장 5개 노선 공동 이용 | 실제 보행망과 운행 방향을 따름. 재탐색 구간별 최대1회 환승이며 전체 여정의 누적 환승 제한은 별도 없음. 정류장·목적지별로 제한된 후보를 사용 |
| 최소 개선 폭 | 예상 도착이 **120초 이상** 빨라질 때 변경 | 작은 차이로 줄을 계속 옮기는 현상을 줄이기 위한 사용자 조정 가능한 시나리오 값 |
| 재판단 | 대기 중 **60초 간격**, 만차 뒤에도 재판단 | 기다리다 줄 상황이 달라져 다른 선택을 하는 행동 포함 |
| 변경 후 유지 | **180초** 동안 추가 변경하지 않음 | 왕복 변경 완화 |
| 변경 횟수 | 이동 흐름 하나당 최대 **2회** | 과도한 재탐색 방지. 떠난 셔틀 승차지로 다시 돌아오는 대안도 제외 |
| 보행 속도 | 기존 첫 보행시간과 같은 보행망의 기준시간으로 입자별 배율 복원 | 새로 뽑지 않으며, 좌표·시간 반올림 때문에 원래 배율과 소폭 차이가 있을 수 있음 |
| 선택의 선호 | 최초 경로는 기존 난수 선호를 유지. 재선택은 남은 시간과 최소 개선 폭으로 판단 | 무료 셔틀 선호·요금·날씨·피로·개인 선호는 별도 추정하지 않음 |

120초·60초·180초·2회는 실측 설문에서 얻은 계수가 아니다. 실제 수단 선택 비중에 대한 검증은 아직 없다.

## 서울대학교 정류장 환승 대안

사용자께서 알려주신 다섯 노선의 현재 공개 노선 순서를 서울시 공식 모바일 버스정보에서 다시 조회했다. **서울대학교 `정류장 ID 120000029 / ARS 21128` → 서울대입구역2번출구 `120000150 / ARS 21252`** 구간을 사용한다. 반대편의 같은 이름 정류장 21127·21376과 구분했다.

| 노선 | 공식 노선 ID | 해당 구간의 진행 방향 | 공개 노선 순번(승차→하차) | 공개 평일 배차간격 |
|---|---|---|---:|---:|
| 5511 | 100100250 | 중앙대학교 | 21→25 | 7분 |
| 5513 | 100100251 | 벽산블루밍아파트 | 9→13 | 9분 |
| 5515 | 100100252 | 청림동현대아파트 | 7→11 | 9분 |
| 5528 | 100100263 | 사당역 | 30→34 | 12분 |
| 6515 | 100100521 | 양천공영차고지 | 70→74 | 10분 |

공식 조회 엔드포인트:

- `http://m.bus.go.kr/mBus/bus/getBusRouteList.bms`, 공개 POST 인자 `strSrch=노선번호`
- `http://m.bus.go.kr/mBus/bus/getRouteAndPos.bms`, 공개 POST 인자 `busRouteId=노선ID`
- 수집 원문과 SHA-256: `adaptive_model/route_sources/`, `adaptive_model/route_verification.json`

5개 노선의 승차→하차 사이 정류장 ID 순서가 동일함을 확인했다. 새로 추가한 5515·5528·6515는 이번 목적에 필요한 이 구간만 노선망에 넣었다. 이 도로 구간은 보존된 5513의 동일 정류장 순서 도형을 재사용했고, 직선으로 이어 붙이지 않았다. 노선의 전체 운행구간을 새로 모형화했다는 뜻은 아니다.

이 대안을 고른 흐름은 정류장까지 실제 저장된 보행망을 따라 이동한 뒤, **5개 중 먼저 도착하는 노선**을 탄다. 각 노선의 공개 평일 간격에 노선·요일별 고정 난수 위상을 적용해 공통 도착시각을 만든다. 이는 실시간 도착 예측이나 실제 배차표가 아니다. 정류장별 실제 첫차·막차 통과시각은 미확보로, 시내버스 계산 창은 기존 모형의 08:00~23:10 가정을 유지한다.

## 그대로 유지한 조건과 새 계산

- 대형 셔틀 정원 **60명**은 사용자 가정, 역순환 **25명**. FIFO 승차·상류 정류장 점유·하차 후 여석·만차 잔류를 유지했다.
- 교내 최고 **40km/h**, 교외 목표 **65km/h**, 가감속 **1m/s²**, 정류장 정차 **15초**. 새 도로 경로에도 같은 속도 곡선을 계산했다.
- 15~19시 기준 배차는 입구역 4분·순환 6분, 피크 최소간격은 3분·5분. 대학동 10분·역순환 20분은 유지했다.
- 최초 경로 선택은 이전 18km/h 가정으로 정한 대표 반복(seed 20261106)을 유지했다. **줄에서의 재선택 예상시간과 새 이동에는 최신 속도를 사용**한다. 새 속도에서 최초 선택 전체를 다시 최적화한 것은 아니다.
- 현재 경로를 유지하는 비교 자료는 기존 `capacity_v3` 그대로다. 경로 변경 자료는 `capacity_v4`로 별도 생성했다. 두 배차 × 다섯 요일이며 독립적인 몬테카를로 10회가 아니다.
- 시내버스 정원, 다른 용도의 배경 승객, 실제 교통 신호·정체·회차·기사 근무는 추가하지 않았다. 특히 시내버스 수용력이 충분하다는 가정은 대체 경로를 유리하게 만들 수 있다.

## 통계 해석

각 셔틀 정류장 대기 사건은 **탑승 / 경로 변경 / 운행 종료까지 미탑승**으로 끝난다. 도착 가중치 = 세 결과 가중치의 합이다. 변경 전 기다린 구간도 지도 대기열과 전체 이동 기록에 남긴다.

`mean_wait_min`과 `p90_wait_min`은 해당 셔틀에 **탑승한 흐름** 기준이다. 경로 변경 뒤에는 평균의 분모가 달라지므로, 평균 대기가 줄었다고 전체 학생의 귀가시간이 그만큼 개선됐다고 계산하면 안 된다. `switched_weight`는 해당 승차지에서 줄을 떠난 사건 가중치이며, 같은 흐름이 두 승차지에서 바꿀 수 있다. `switched_trip_weight`는 최종 흐름 중 한 번 이상 바꾼 가중치다. 둘 다 실제 고유 학생 수가 아니다.

`gate_boarding_weight`는 위 5개 공동 노선 대안을 택해 서울대학교 정류장에서 승차한 가중치만 센다. 기존 5511·5513 이용자 전체를 의미하지 않는다.

검증 파일:

- `test_adaptive_model.py`: 최소 개선 폭·횟수·유지시간, 현재 여석 예측, 도보 전환, 변경량 분리, 75명 중 60명 먼저/15명 다음 차, 공통 시내버스 시각 사례.
- `adaptive_model/run_verification.json`: 10개 실행, 정원 상한과 가중 이동량 보존.
- `adaptive_model/independent_verification.json`: 원래 이동 입자별 가중치 보존, 차량 승하차와 대기열, 탑승·변경·미탑승 분리, 시간별 평균, 새 속도 곡선 검산. 공개 대기열의 시각은 밀리초 단위라 경계 직전·직후 표본은 같은 정밀도로 비교하고 나머지는 반올림 전 시각으로도 대조. 변경 기능을 끈 계산이 기존 v3 사건·대기열과 일치하는지도 대조.

이 검증은 구현·계산의 일관성을 확인한다. 실제 학생의 경로 변경 행동, 실제 대기시간, 배차 실행 가능성의 검증과는 구분한다.
