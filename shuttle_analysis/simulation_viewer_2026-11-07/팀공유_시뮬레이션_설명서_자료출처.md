- 분자와 분모의 기준일·캠퍼스·모집단이 일치하는지 확인되지 않았으므로, **현재 관악 수강생의 실측 기숙사 거주율이 아닙니다.**

### 3.4 배분식과 예시

한 종료 사건의 수강신청인원을 `N`, 직후 이동 비율을 `q=0.5`, 기숙사 비율을 `r`라고 두면:

```text
기숙사 이동 가중치 = N × q × r
서울대입구 이동 가중치 = N × q × (1-r) × (55.7/99.9)
낙성대 이동 가중치 = N × q × (1-r) × (27.2/99.9)
대학동 대표점 이동 가중치 = N × q × (1-r) × (17.0/99.9)
```

가상의 수강인원 100명인 수업이라면 직후 이동 가중치 50을 기숙사 약 9.75, 서울대입구 약 22.44, 낙성대 약 10.96, 대학동 대표점 약 6.85로 나눕니다. **100명의 실제 학생에게 목적지를 조사해 배정한 예시가 아닙니다.**

`q=50%` 역시 개인의 마지막 수업이나 실제 귀가 여부를 관측해 학습한 비율이 아닙니다. 각 강좌 집단에 공통 적용한 조건입니다.

## 4. 이동·정원·대기열 계산

1. **수업 종료 → 건물 이탈:** 종료시각에 이탈 지연을 더합니다. 최소 1분·최빈 3분·최대 8분의 삼각분포 가정으로, 수업 종료와 정류장 도착을 구분합니다.
2. **보행:** 저장된 OSM 보행망의 거리·계단을 사용합니다. 평지 속도는 최소 0.9·최빈 1.2·최대 1.5m/s의 삼각분포이며 계단은 기본 0.7m/s와 입자별 배율을 적용합니다. 건물 대표점의 보행망 연결부는 최대 110m이며 현장 출입구 검증값은 아닙니다.
3. **경로 후보:** 직접 도보, 버스/셔틀 직행, 최대 1회 환승을 비교합니다. 시내버스는 5511·5513·5516·관악02-1·관악02-2, 셔틀은 행정관·대학동·교내 순환·역순환이 포함됩니다.
4. **경로 선택:** 예상 이동시간에 환승당 2분의 선택 비용과 Gumbel(scale 90초)의 취향 차이를 넣었습니다. 실제 학생의 선호를 조사해 적합한 모수는 아닙니다.
5. **현재 재생의 경로 고정:** 기존 10개 난수 반복 중 seed `20261106`의 대표 1회 경로 선택을 재사용합니다. 새 정원·속도 조건에서 경로를 다시 최적 선택하거나 만차 후 다른 노선으로 바꾸지는 않습니다.
6. **정원 제한:** 대형 60명은 사용자 가정이고 공식 25인승 역순환은 25명으로 구분합니다. 먼저 도착해 준비 20초를 마친 흐름부터 FIFO로 태웁니다. 앞 정류장에서 탄 흐름이 뒤 정류장의 자리를 차지하며, 하차 후 남은 자리에 승차합니다.
7. **만차와 환승:** 자리가 없으면 잔류시키고 다음 버스를 기다립니다. 실제 계산된 탑승 시각으로 하차·다음 보행·환승 도착도 늦춥니다. 빨간 점은 한 번 이상 만차로 남은 흐름입니다. 막차 뒤 잔류도 처리합니다.
8. **관측하지 않은 승객:** 수업 외 승객·교직원·방문객이나 실차의 출발 지점 기존 탑승객은 추가하지 않았습니다. 시내버스 정원은 제한하지 않습니다. 순환 노선의 두 번째 펼친 구간은 이미 탄 흐름의 하차만 처리합니다.

다른 시간대와 막차 조건은 두 시나리오에서 같습니다. 15~19시는 공식 오후 운행 구간을 사용한 비교 조건이며, 데이터에서 최적 피크 구간을 자동 탐색한 결과가 아닙니다. 실제 회차별 출발표는 없어 공유 예시 출발위상 1개를 사용했습니다.

비교는 정규학기의 일반 평일 조건입니다. 9~10월 한시 증차나 시험기간 추가 증차를 현재 재생에 상시 적용하지 않았습니다. 월~금 표시는 특정 날짜의 실제 운행·혼잡 예보가 아닙니다.

야간은 이전 계산의 **2대 동시 출발 가정**을 유지하되 각 차량 정원을 60으로 처리합니다. 공표된 대수만으로 내부 동시 출발표가 확인된 것은 아닙니다. 차량 ID도 개별 출발 회차를 식별하는 것이며 고유 실차 수와 다릅니다. 실제 차량 회전·기사 근무·추가 차량 필요량까지 검증한 운행 최적해는 아닙니다.

### 최신 차량 속도 조건

- 교내 최고 **40km/h**, 교외 목표 **65km/h**: 교외 요청 범위 60~70의 중간값입니다. 실제 속도나 법정 제한속도를 조사한 값이 아닙니다.
- 저장된 OSM 관악캠퍼스 경계(relation `11917142`)로 안/밖을 구분하고 저장된 도로 도형의 거리를 사용합니다.
- 가속·감속 **1m/s²**, 정류장당 **15초 정차**를 적용합니다. 최고속도와 평균속도는 다르며 짧은 구간에서는 최고속도에 도달하지 않을 수 있습니다.
- 시내버스 이동시간도 갱신했습니다. 화면만 빨리 움직이게 한 것이 아니라 하차·보행·환승·대기열을 다시 계산했습니다. 보행 속도는 바꾸지 않았습니다.
- 화면의 **1초/초~15분/초 재생 배율**은 차량의 km/h 속도 조건과 별개입니다.

## 5. 지도 점과 그래프의 단위

이 모형의 입자는 실제 학생 ID가 아니라 **가중 통행 입자**입니다. 강좌·목적지당 12개를 사용하므로 입력 6,201 × 4집단 × 12 = 297,648개 입자가 됩니다. 각 입자의 가중치가 달라 수강인원과 목적지 비중을 반영합니다. 정원 처리에서 입자의 가중치를 나누어 부분 승차시킬 수 있으므로 개별 인원에 대한 정수 모형과도 구분합니다.

표시 점은 정원 계산 후 줄여 뽑은 표본이며 점 1개가 약 2명 상당입니다. 따라서 **점 개수로 실제 학생 수나 버스 탑승 인원을 세면 안 됩니다.** 정원·통계·대기량은 표본 점이 아니라 전체 가중 흐름으로 계산합니다.

| 화면 값 | 의미 |
|---|---|
| 현재 대기량 | 해당 노선·승차지에 아직 탑승하지 못한 가중 흐름 |
| 만차로 남음 | 대기 중 한 번 이상 정원 때문에 못 탄 가중 흐름 |
| 버스 `차내/정원` | 해당 모형 회차의 차내 가중치와 정원 가정 |
| 시간대별 평균·90백분위 대기 | 그 승차지에 해당 시간대 도착한 흐름 중 **탑승 완료 흐름** 기준. 미탑승량은 별도 표시 |
| 만차 경험 비중 | 같은 승차지 도착 흐름의 반복 실패를 한 번만 세는 가중 비중 |
| 대기열 비교선 | 두 배차 조건의 5초 간격 대기량 표본. 지도 대기량은 실제 사건 누적에서 조회 |

환승 승차는 추가 승차 사건이지 새로운 학생이 아닙니다. 지연으로 도착 시간대가 바뀔 수 있어 시간대별 표의 코호트가 배차 조건 사이에 조금 달라질 수 있습니다.

**현재 계산의 ‘2개 배차 × 5요일 = 10회 실행’은 10회 몬테카를로 평균이 아닙니다.** 현재 지도는 대표 경로 반복 1회·예시 출발위상 1개입니다. 별도 탭의 이전 대기시간 표는 평균 유입량·20개 출발위상·이전 속도 조건의 계산으로 보존했습니다. 신구 표의 차이를 순수한 배차 개선 효과로 해석하면 안 됩니다.

## 9. 팀원이 실행하고 해석하는 방법

1. Windows 공유 ZIP **전체를 압축 해제**하고 `시뮬레이션 실행.exe`를 실행합니다. 보기에는 Python·Node·Codex 설치가 필요 없습니다. 배경 지도는 인터넷 연결이 필요합니다.
2. 요일·배차 조건·승차지를 선택합니다. [만차 장면]은 잔류가 발생한 승차지로 이동할 수 있으므로 선택된 승차지도 함께 확인합니다.
3. 재생 배율을 1초/초부터 조절합니다. 빨간 점은 만차 경험이 있는 잔류 흐름이고 버스의 차내 가중치·정원·현재속도를 함께 봅니다.
4. [그래프]에서는 현재 모형 결과와 이전 계산 탭을 구분합니다. 대기시간 표는 정류장 **도착 시간대** 기준입니다.
5. 실행기 창을 닫으면 로컬 서버가 종료됩니다. 다른 사람에게 localhost 주소만 전달해서는 공유되지 않으며 ZIP 파일을 전달해야 합니다.

**공유 ZIP은 결과 재생 패키지입니다.** 화면 코드·계산된 자료·실행기 소스가 포함되지만 원본 XLS, 전체 분석 입력·모형 실행 환경을 모두 담은 완전한 재계산 패키지는 아닙니다. 원자료를 변경해 다시 실험하려면 위 프로젝트 보존 파일과 Python 분석 환경이 필요합니다. 단순 시청과 모형 재계산의 요구사항을 구분해야 합니다.

원래 작업공간의 재계산 진입점은 `speed_capacity_model.py`이며, 독립 검산은 `verify_capacity.py --dataset capacity_v3 --work capacity_model/speed_40_65`, 속도 검산은 `verify_speed.py`입니다. 이는 공유 ZIP을 보기 위한 필수 실행 절차는 아닙니다.

## 10. 실제 수요를 더 잘 추정하려면

우선 필요한 것은 익명화한 **마지막 수업 종료 건물·시각 × 목적지 방향 × 실제 선택 교통수단**의 교차 집계입니다. 기숙사 거주와 당일 기숙사행도 따로 조사해야 합니다. 개인의 상세 주소 없이도 구간별 조사로 핵심 가정을 보완할 수 있습니다.

같은 날짜·요일·정류장·방향·시간 단위의 도착 인원, 탑승 인원, 못 탄 인원, 버스 기존 탑승객을 관측해야 대기열을 검증할 수 있습니다. 실제 출발·도착 기록과 회차·휴게·차량 전환 조건까지 확보해야 최소 간격의 실행 가능성도 평가할 수 있습니다.
