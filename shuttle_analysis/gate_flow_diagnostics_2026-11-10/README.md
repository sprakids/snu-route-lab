# 정문 대기열 오차의 수요·승하차 흐름 분석

분석일: 2026-11-10. 저장된 월요일 peak 실행 기록만 재집계했습니다. 시뮬레이터를 새로 실행하거나 수요·용량·시간표·계수·운영 모델·배포를 변경하지 않았습니다.

## 결론

실측 위치에서 정류장 근접 시각을 추출해 적용한 후보에서 정문 대기열이 커진 직접적인 이유는, 17:03 이전의 정문 탑승 처리량이 줄었기 때문입니다. 같은 기간에 정문에 유입된 수요는 세 실행에서 같습니다. 따라서 이 사례를 수업 종료 인원이 갑자기 늘거나 셔틀 환승객이 몰린 결과로 설명할 수 없습니다.

이는 저장된 모형 내부에서 확인한 차이입니다. 실제 정문 유입량·승차량·하차량·차량별 잔여 정원이 함께 관측되지 않았으므로 현실에서 어느 입력이 얼마나 잘못됐는지까지 확정한 것은 아닙니다.

## 비교 대상과 단위

- v7: 기존 보정 모형. 원본 `gate_access_calibration_2026-11-09/candidates/alpha_075`.
- v8: 요일별 운행 시각을 반영한 모형. 원본 `weekday_operations_2026-11-10`.
- 시각 교정 후보(docked): 위치 관측에서 정류장 근접 시각을 추출한 한 번의 후보. 원본 `gate_clock_repair_2026-11-10`. 기존 판정은 기각, v7 복귀였습니다.
- 정문은 서울대학교 정류소 ID `120000029`, ARS 21128, 서울대입구 방향 공유 대기열(내부 node 62)입니다.
- 모형의 수요·줄·탑승 수는 모두 **가중 이동 사건의 명 상당량**입니다. 실제 고유 학생 수나 실측 차량 승객 수가 아닙니다. 소수점은 가중치 때문에 생깁니다.

세 실행의 초기 경로 계획 전체가 동일합니다. 계획 레코드 67,920개, 총 가중 이동량 18,885.5이며, 전체 계획 SHA-256은 `17a077f5540bdfdd424692be4dae87cbe3b5440cafb0ebea2fc3abc35f815f09`입니다. 차량 정원 가정도 동일합니다. 이후 경로 변경은 각 실행 안에서 별도로 발생할 수 있으므로 실제 정류소 유입을 추가로 비교했습니다.

실행 간 차량 번호는 다시 부여되므로 위 표는 동일 실차의 이동을 매칭한 표가 아닙니다. 각 실행의 서비스 기회 비교입니다.

v8에서는 유입이 쌓인 뒤 5515가 관측 전에 33.68명 상당을 태웁니다. 후보에서는 그 시간의 유효한 탑승 기회가 관측 뒤에 있고, 앞선 16:55:42 차량은 유입이 아직 적어 1.50명 상당만 태웁니다. 5528·6515의 기회도 관측 시각과 수요 유입에 대한 위치가 바뀝니다. 후보에서 17:04:04의 5528이 50명 상당을 처리하는 것도 이 지연된 배출 구조와 일치합니다.

5511은 두 실행 모두 해당 시각에 모형 내 재차량 50, 하차 0, 정원 가정 50이므로 승차 가능량 0입니다. 후보의 16:57:47 5513도 같은 상태입니다. **시각을 관측으로 바꾸어도 차량 내 승객과 정문 하차량이 함께 실측으로 바뀐 것은 아닙니다.**

엔진은 모든 차량을 모형 시작 지점에서 재차량 0으로 만들고 모형에 포함된 사람만 태웁니다. 5515·5528·6515는 정문이 모형 첫 정류소라 그곳에 빈 차로 진입하는 가정입니다. 반면 5511·5513은 교내 유입을 먼저 태워 정문에 도착합니다. 외부 배경 승객은 포함되지 않고 실제 차량별 정원도 검증되지 않았습니다. 이 경계 조건의 차이는 실제 승하차 흐름을 확인해야 할 핵심 항목입니다.

## 3. 줄에 남은 수요의 출처

16:50~17:03 외부 유입 59.589028 중 58.242383(약 97.74%)은 기존 alpha_075 보정에서 처음부터 정문 도보 접근으로 재배정한 수요입니다. 이는 원래 계획에서 이동량을 옮긴 것이며 추가 수요가 아닙니다.

후보의 17:03~17:04 평균 줄 61.382840 중 60.036195(약 97.81%)가 이 재배정 집단의 최초 정문 대기입니다. 같은 분에 실제 셔틀에 탔다가 내려서 만든 줄의 기여는 0입니다. 따라서 이 사례의 주된 진단 대상은 셔틀 하차 파동보다 **수업 종료 후 정문으로 직접 걷는 비율·출발 시각·보행 도착 분포와, 해당 시각의 승차 가능량의 결합**입니다.

후보의 큰 기여 집단에는 58동 출발이 평균 25.286995명 상당 포함됩니다(기존 5511·5513 최초 이용 계획에서 정문 도보 접근으로 재배정한 두 집단의 합). 이것이 실제 58동 학생의 관측 유입이라는 뜻은 아닙니다. 상세 출처는 `building_source_flows.csv`에 보존했습니다.

기존 수요 보정이 이전 운행 시각·승차 가능량의 오차를 함께 흡수했을 가능성이 있습니다. 이번 고정 수요 비교는 그 가능성을 보여주지만, 적은 현장 대기열 관측만으로 수요 과다와 공급 과소 중 하나를 확정하거나 수요를 임의로 낮출 근거는 아닙니다.

## 4. 관찰값과 시각의 정합성

17:03 관찰된 줄은 33~39명이며 초 단위 관측 시각은 미상입니다. 이에 대응하는 저장된 17:03~17:04 균등 시각 평균은 v7 31.898865, v8 21.144411, 후보 61.382840입니다. **분 평균과 관측 순간의 줄은 같은 통계량이 아닙니다.** 후보의 해당 분 전체 범위는 58.092756~66.621505라 관측 범위보다 계속 높지만, v7의 전체 범위는 28.410462~37.201060으로 일부 겹칩니다.

기존 판정의 오차 지표는 각 순간의 줄이 보고 구간에서 떨어진 거리를 해당 분 전체에 적분한 평균입니다. `abs(분 평균-실측 중간값)`이 아닙니다. 이 오차는 v7 1.597088, v8 11.855589, 후보 22.382840입니다. 이 세 현장 사례는 기존 보정에 이미 사용했으므로 독립 검증 결과로 제시할 수 없습니다.

또한 후보에서 추출한 시각은 GPS가 정류소에 가까웠던 시각입니다. 문이 열리고 승차가 시작된 시각의 직접 관측이 아닙니다. 5511은 검출 범위 기준을 만족하지 않아 v8 시각을 유지했습니다. 모든 노선의 시각이 완전한 실측으로 바뀐 실험은 아닙니다.

## 5. 모델을 바꾸기 전에 필요한 확인

1. 같은 정류소·방향·초 단위 시각으로 줄과 외부 보행 유입을 함께 기록합니다. 기존 재배정 수요가 특히 많이 기여하는 건물·수업 종료 직후 구간을 우선 확인합니다.
2. 차량별 도착·문열림·출발 시각, 도착 당시 차내량, 하차, 승차, 남은 줄을 연결합니다. 혼잡 등급만으로 정확한 승차 가능 인원을 확정하지 않습니다.
3. `이전 차내량 - 하차 + 승차 = 이후 차내량`과 `이전 줄 + 외부 유입 - 승차 - 실제 이탈 = 이후 줄`을 같은 시간축에서 검증합니다.
4. 그 뒤 유입 분포와 정원·배경 승객 가정을 각각 검토합니다. 이번 사례에 맞추어 임의로 수요를 줄이거나 버스 빈자리를 늘리는 수정은 하지 않았습니다.

## 현재 경로 화면의 줄·대기시간 기준

`app/routing.py`에서 최초 도보 후 시각에 기본 준비시간 20초를 더한 `ready`를 만들고, `app/automatic_queue.py`는 그 `ready`의 줄을 `queue_at_arrival`로 반환합니다. 화면 `static/app.js`는 `queue_now`가 아니라 `queue_at_arrival`를 표시합니다.

따라서 17:00 출발, 행정관까지 도보 8분이면 17:08:20의 예상 줄입니다. 이미 정류소에서 준비를 마치고 기다리는 조건을 충족하면 추가 20초는 0입니다. 예상 대기는 준비가 끝난 `ready`부터 모형상 탑승 시각까지이고, 총 경로 시간에는 도보·준비·대기·승차 시간이 각각 들어갑니다.

검색 후 실제 보행 속도에 맞추어 출발지부터 계속 다시 계산하는 방식은 아닙니다. 도착정보 갱신은 원래 계획의 준비 시각과 현재 시각을 사용하므로 실제 출발이 늦어지거나 이동 속도가 크게 다르면 재검색해야 합니다.
