# V11 유지·R 병행 비교와 셔틀 운행 이력

현재 상태: **2026-11-16 22:20 KST 운영 반영·실제 저장 확인 완료**. [하교길](https://snu-route-lab.vercel.app/)은 V11을 유지하며 R을 별도로 계산·기록합니다. 서울시 8개 노선과 일일 호출 상한은 변경하지 않았습니다.

## 계산과 기록

- 운영 대기 모형은 V11 `261110162302`입니다. 개발 모형은 `R261116185534`이며, 시내버스 교통 보강 후보 `R261116170142`를 바탕으로 합니다. 새 후보에서 검증이 나빠졌던 차내시간 항목은 기존 R 부모의 구간 통과시간 모형을 유지합니다.
- 먼저 기존 V11 결과를 표시합니다. 그 뒤 브라우저가 별도 요청으로 R을 계산합니다. 출발 시각, 관측 기준시각, 버스 도착 응답, 셔틀 위치, V11 대기 모형의 버전과 보행 경로를 고정하여 같은 입력으로 비교합니다.
- R은 교통 공급자 API를 추가 조회하지 않습니다. 일일 500건까지 공용 장부에서 먼저 예약하고, 중복 요청과 재시작으로 같은 비교를 반복하지 않습니다. 시험 서버에서는 브라우저 검색 후 실제 기록 저장과 중복 차단까지 확인했습니다.
- 상위 40개 후보의 도보·대기·차내·총시간, 순위, 노선·승하차 구간을 기록합니다. 화면의 임시 후보 번호 대신 경로 구성으로 짝을 맞추며, 새로 생기거나 상위 40개에서 빠진 경로도 구분합니다.
- 이는 **예측과 예측의 비교**입니다. 실측 정확도가 좋아졌다는 검증이 아닙니다. 실제 탑승 결과와 독립 검증 자료를 확보하기 전에는 우수 모델로 선언하거나 자동 승격하지 않습니다.
- 정확한 출발 좌표와 보행 경로는 같은 서버의 임시 계산에만 사용합니다. 비교 저장소에는 좌표, 경로 도형, 이름·계정·IP, 서명된 계산 입력과 인증키를 넣지 않습니다. 개인정보 안내도 수정했습니다.

## 셔틀 수집

대상은 운영사 노선도에 연결된 학생 셔틀 10개 노선입니다. 자료는 GPS가 아닌 **운영사 노선도의 정류소 부근·구간 위치**이며, 원본 시각이 제공되지 않아 수신 시각의 구간으로 도착·출발을 추론합니다.

| 구분 | 수집 주기 |
|---|---:|
| 15~19시 행정관·교내 순환·역순환 | 30초 |
| 위 세 노선의 나머지 시간 | 120초 |
| 나머지 7개 학생 셔틀 | 120초 |

매일 11:20~23:10 KST에 수집합니다. 정확히 시간표대로 실행되는 경우 하루 **4,640회**의 노선 조회이며, 오류를 포함한 기존 BUSIN 보호 상한 6,000회 안에서 운영합니다. 조회 전 예약하므로 재시작 때 남은 예약을 낭비할 수는 있어도 상한을 초기화하지 않습니다. 서울시 위치 API의 기존 8개 노선과 일일 상한은 변경하지 않았습니다. 공급자가 서로 다르므로 BUSIN 조회를 서울시 한도에 합산하지 않습니다.

방문자는 공용 캐시만 읽고 수집은 예약 작업이 담당합니다. 수집 시작 이후 방문자 때문에 BUSIN 조회 횟수가 늘지 않습니다. 공급자 연결은 기존 서울 리전 서버의 인증된 전용 통로를 이용합니다. Cloudflare 운영 환경에서 두 차례 예약 수집을 확인했습니다. 10개 노선의 총 20회 조회와 차량 위치 표본 8개가 원본에 저장됐고 조회 오류는 0건이었습니다. 위치 표본 8개를 독립적인 차량 8대나 운행 8회로 세지 않습니다.

## 배차간격·이동시간 보강

1. 처음 보였을 때 이미 정차 중인 버스는 도착시각을 알 수 없으므로 새 도착 표본으로 세지 않습니다.
2. 정차→이동과 이동→정차를 따로 기록합니다. 오랫동안 같은 곳에 세워 둔 시간을 계속 새 표본으로 세지 않습니다.
3. 출발 구간 `[d₀,d₁]`와 도착 구간 `[a₀,a₁]`로부터 주행시간을 `[max(0,a₀-d₁), a₁-d₀]`로 보존합니다. **출발지의 주차·대기는 차내 주행시간에 포함하지 않습니다.** 중간 정류소의 체류는 완성된 출발→도착 구간에 포함됩니다.
4. 같은 관측 또는 서로 겹치는 관측 구간에서 잡힌 두 차량을 분리된 0~30초 배차로 취급하지 않습니다. 관측 묶음과 개별 차량을 함께 보존하며, 기존 44명 정원·피크 2대 가정을 임의로 변경하지 않습니다.
5. 180초가 넘게 관측이 끊기면 그 사이를 완성된 이동 표본으로 만들어 내지 않습니다.
6. 보정에는 조회 기준시각 이전에 완료된 날짜만 사용합니다. 최근 28일 중 같은 요일 자료가 충분하면 그 자료를, 부족하면 같은 평일·주말 유형 자료를 사용하며 둘을 구분합니다. 정류장·방향·시간대와 공식 배차 구간을 구분해 18시 피크 배차를 19시 이후에 그대로 적용하지 않습니다.
7. 최소 **2개 날짜·5개 유효 표본**과 관측 구간 폭 기준을 통과한 항목만 R의 배차·구간 시간과 FIFO 공급 계산에 반영합니다. 고정 출발 시간표, 막차, 차량별 정원과 묶음 운행은 유지합니다. 근거가 부족하면 기존 모형과 시간표로 돌아갑니다.

배포 직후의 짧은 운영 기록은 이 기준을 충족하지 않습니다. 아직 실제 셔틀 배차·차내시간이 보정됐다고 주장하지 않습니다. 조건을 충족한 기록도 R에만 적용하며 V11을 자동 교체하지 않습니다.

## 보관과 한도

- 셔틀 원본과 개별 V11/R 비교: 날짜별 저장 공간에 gzip 형태로 30일 보관합니다.
- 셔틀 일별 통계와 비교 일별 합계: 365일 보관합니다. 셔틀 통계도 날짜별로 나누어 한 객체에 일 년치가 집중되지 않도록 했습니다.
- 보정 표본은 횟수와 날짜를 함께 확인합니다. 같은 차량이 멈춰 있는 동안 여러 번 조회한 것을 여러 승객·여러 운행으로 취급하지 않습니다.
- 쓰기 사용량이 60,000회에 이르면 R 비교 예약을 중지하고, 65,000회 부근에서는 셔틀 추가 수집을 중지하여 기존 시내버스 수집을 보호합니다. 기존 전체 사용량·객체 크기 보호장치도 유지합니다. 실패 상태는 별도로 기록합니다.
- 사용량은 앱에서 관측하는 SQL·요청 추정치로, 계정 전체의 다른 프로젝트 사용량까지 확인한 값은 아닙니다. 무료 한도를 무제한 저장으로 해석하지 않습니다. [Cloudflare 공식 요금·무료 한도](https://developers.cloudflare.com/durable-objects/platform/pricing/)
