2026-11-06 업데이트된 3장 계획서를 바탕으로 만든 실행 가능한 첫 구현입니다.

**공개 주소: https://snu-route-lab.vercel.app**

사용자는 출발지·목적지·출발 시각·우선순위를 고릅니다. 키 입력 화면은 없습니다. 외부 API 인증, 키 공급, 호출량 관리, 경로 계산과 기록 저장은 백엔드가 담당합니다.

## v0.2 현재 위치와 셔틀 수정

- 페이지에서 기기 위치를 요청하고, 권한 허용 시 출발지에 연결합니다. 파란 점과 기기 제공 오차 원을 경로와 별도 레이어로 유지합니다. 좌표를 이동 기록에 저장하거나 IP 위치로 대체하지 않습니다.
- 권한 거부·시간 초과·교외 위치·250m 초과 오차를 각각 안내합니다. 위치 확인 중 새 출발지를 선택하면 늦게 온 위치 응답이 선택을 덮어쓰지 않습니다.
- 학교 캠퍼스맵의 행정관 승차점과 입구역 승차·하차 지점을 구분합니다. 301동·302동·정문 교내 셔틀 정류소도 출발지에 추가했습니다.
- 정차 차량은 실제 출발시각이 제공되지 않아 근처 출발지에서만 30초 뒤 출발 가정으로 비교하고 이를 표시합니다. 접근 중 차량은 구간 추정의 빠른 도착보다 보행 준비시각이 앞설 때만 연결합니다.
- 셔틀을 타고 도착했을 때 조회된 시내버스 두 대가 이미 지난 경우, 그 이후의 시내버스만 배차간격 시나리오로 구분해 연결합니다. 실제 셔틀 관측을 대체하거나 새로운 차량 ID를 생성하지 않습니다.
- 운영사 노선 순서, 학교 공개 정류소 좌표, 명칭 대응·미확인 지점은 `data/shuttle_network.json`에 기록했습니다. 역순환 교수아파트 좌표 미확인 지점은 승하차 계산에서 제외합니다.
- 45개 백엔드 테스트, 19개 가상 DOM 조작 및 실제 Leaflet을 가상 DOM에서 실행한 5개 레이어 검증을 통과했습니다. 대표 출발지 17곳 × 두 목적지 34개 연결도 확인했습니다. 실제 기기 위치 권한과 브라우저 화면 픽셀 검증은 Work 브라우저 사용 제한으로 확인하지 못했습니다.

## 구현한 기능

- 관악캠퍼스 주요 건물·정류소 출발 및 지도 핀 선택, 서울대입구역·낙성대역 비교.
- 카카오 지도/도보 API 어댑터. 서버에 설정된 플랫폼 키를 자동으로 읽습니다. 현재 실제 카카오 키는 미확보 상태이며, 그동안 검토 화면은 Leaflet와 OpenStreetMap으로 실행됩니다.
- 실제 보행망 탐색. 보행 금지·사유 접근·조건부 접근 구간을 제외하고 `oneway:foot` 방향을 반영합니다. 그래프가 끊어지면 직선 보행 경로를 만들어 대체하지 않습니다.
- 서울시 버스 위치 OpenAPI: 로컬에서는 기존 Windows 암호화 저장소, Vercel에서는 서버 Secret 환경변수로 인증합니다.
- 서울시 공식 모바일 웹 도착예정: 노선 ID·정류소 ID·정차 순번을 검증하고, 걸어 도착한 뒤 탈 수 있는 다음 차량을 선택합니다.
- BUSIN 셔틀 실시간 조회: 행정관(41841), 교내 정순환(41946), 역순환(41914)을 각각 조회합니다. 활성 화면에서 노선별 15초 공동 캐시를 사용하며 차량·오류·빈 응답을 섞지 않습니다.
- 셔틀 원 좌표를 보여주는 실시간 노선도와, 지리 지도에 랜드마크 구간을 표시하는 레이어. 노선도 x/y를 GPS로 변환한 것처럼 표시하지 않습니다.
- 셔틀 관측 위치로 정류소 도착 범위를 추정하고, 보행 후 연결 가능한 관측 차량을 비교합니다. 시내버스·행정관·교내 순환 간 최대 1회 환승 시 실제 보행망의 환승 이동도 포함합니다. 통과 지점 승차와 오래된 위치·시간표 차량 대체를 허용하지 않습니다.
- 시간 의존 후보 탐색, 최대 1회 환승, 최소–최대 정규화와 가중합 비교. 서로 다른 셔틀·버스 정류소는 직선 180m 및 보행망 300m 이내일 때 실제 보행 경로로 연결합니다.
- 네 가지 선호 프리셋과 사용자 가중치. 미확인 혼잡도는 0으로 채우지 않고 전체 종합 비교에서 해당 지표를 제외한 뒤 가중치를 다시 나눕니다.
- 실제 이동시간·만족도·착석 여부의 비식별 기록. 동일한 경로 조건의 실측 10회 이상일 때만 관측 오차 재표집 시나리오를 제공합니다. 데이터가 없을 때 확률·정확도를 만들지 않습니다.

## v0.2.1 저장소 한도 대응 (2026-11-06)

Blob을 실시간 캐시·카운터로 쓰는 구조가 고급 작업 무료 한도를 소진해 **운영 코드에서 Blob 읽기·쓰기를 모두 중단**했습니다. 기존 저장소와 데이터는 삭제하지 않습니다. 기존 Blob 자격증명이 환경에 남아 있어도 이 버전은 사용하지 않습니다.

- `service_state.py`의 인스턴스별 메모리 캐시로 키가 없는 버스 도착정보·BUSIN 셔틀 조회를 유지합니다. 이 캐시는 영구 저장소나 여러 인스턴스가 공유하는 카운터가 아닙니다.
- 서울시 인증키의 전역 일일 호출 한도를 보장할 저장소가 없으므로 운영의 버스 **위치 API 수집은 중단**합니다. 도착정보 및 그 응답에 포함된 혼잡도와 경로 비교는 계속 사용할 수 있습니다. 전역 일일 사용량은 확인 불가(`null`)로 반환합니다.
- 이동 기록 POST는 `503`, `saved:false`로 응답합니다. 기록 조회는 `available:false`로 표시하며 조회 불가를 실제 기록 0건으로 해석하지 않습니다. `/tmp`에 저장한 뒤 영구 저장됐다고 응답하지 않습니다.
- 공개 화면에 중단 범위를 알리고 기록 제출을 비활성화했습니다. 로컬 Windows 실행의 SQLite 기록은 유지합니다.
- 저장 기능 복구에는 공유 카운터와 이력 저장에 적합한 데이터베이스 연동이 필요합니다. 아직 새 서비스 가입·무료 DB 생성·유료 플랜 전환을 하지 않았습니다.

원인: 셔틀 3개 노선을 15초마다 갱신할 때 노선당 갱신 잠금·호출 횟수·결과 저장으로 최소 3번의 Blob 쓰기가 발생할 수 있었습니다. 모든 주기에 갱신한다는 가정에서 시간당 약 2,160번으로 월 무료 고급 작업 2,000회에 맞지 않습니다. 실제 청구 집계는 팀 사용량 화면이 기준입니다.

검증: `python -X utf8 -m unittest -q test_routing.py test_cloud_store.py test_shuttles.py test_service_state.py`. 외부 네트워크를 금지한 상태의 부트스트랩·경로 계산, Blob 주소 접근 없이 셔틀 3노선 조회, 저장 실패의 HTTP 계약을 포함합니다.

참고: [Vercel Blob 요금·Hobby 초과 정책](https://vercel.com/docs/vercel-blob/usage-and-pricing).

- 공유 조회 한도, 실시간 스냅샷, 이동 기록은 서울 리전의 프로젝트 전용 비공개 Blob 저장소를 사용합니다. `/tmp`의 SQLite를 영구 기록으로 취급하지 않습니다.

- 공개 배포는 실측 기록 최대 5,000건으로 제한한 시제품입니다. 한도에 도달하면 과거 기록을 지우지 않고 추가 기록을 거절합니다.
- `.vercelignore`는 `.env*`, 로컬 런타임 기록·DB·테스트·의존성 폴더를 업로드에서 제외합니다. Windows DPAPI 파일은 프로젝트 밖에 그대로 보관합니다.

2026-11-06 배포 서버에서 서울시 위치 43건, 셔틀 노선도 위치 18건과 실시간 셔틀 후보를 확인했습니다. 공개 주소의 익명 접속, 브라우저가 사용하는 지도 파일, 같은 출처의 경로 POST 요청도 확인했습니다. 외부 출처의 변경 요청과 서버 소스 접근은 차단됩니다. 검증 상세는 `runtime/vercel_deployment_validation.json`에 기록했습니다. 실제 브라우저 픽셀 검증과 구분한 HTTP/API 검증입니다.

## 백엔드 인증 설정

인증은 개발자 측 구성입니다. 일반 사용자 화면에는 API 키나 키 입력 기능을 두지 않습니다.

공급 순서:

1. 프로세스 환경변수 또는 개발자 전용 `.env`.
2. Windows 현재 사용자 DPAPI로 보호한 `%LOCALAPPDATA%\SnuTransit\credentials\route_lab_settings.dpapi`.
3. 서울시 키는 기존 `%LOCALAPPDATA%\SnuTransit\credentials\seoul_bus_service_key.dpapi`도 자동으로 읽습니다.

지원하는 서버 변수:

| 변수 | 용도 | 브라우저 전달 여부 |
|---|---|---|
| `SEOUL_BUS_SERVICE_KEY` | 서울시 위치 API | 전달하지 않음 |
| `KAKAO_REST_API_KEY` | 카카오 도보 경로 REST 호출 | 전달하지 않음 |
| `KAKAO_JAVASCRIPT_KEY` | 카카오 지도 Web SDK | 해당 브라우저 SDK 로딩에만 사용 |

`.env.example`은 변수 이름만 담은 개발 템플릿입니다. 실제 키를 명령줄 인수·소스·일반 로그에 넣지 않습니다. `.env`, `runtime/`, `node_modules/`는 Git에서 제외합니다.

개발자가 공급한 환경변수/`.env` 값을 암호화 저장소에 보관할 때:

```powershell
python -X utf8 backend_setup.py --import-env
```

상태만 확인할 때:

```powershell
python -X utf8 backend_setup.py
```

이 도구는 키 원문을 출력하지 않습니다. 키 발급과 카카오 콘솔의 JavaScript 허용 도메인 등록은 제공기관 설정에 해당합니다. 카카오 실제 키로 지도 로딩과 도보 API를 호출하는 검증은 아직 완료하지 않았습니다. 인증 실패 시 OSM 대체 경로임을 출처에 표시합니다.

## API 계약

| 경로 | 동작 |
|---|---|
| `GET /api/health` | 앱·버전 확인 |
| `GET /api/bootstrap` | 출발지, 목적지, 공개 노선, 프리셋, 지도 설정. 서버 비밀 키 제외 |
| `GET /api/status` | 캐시된 실제 버스 위치와 수집시각 |
| `POST /api/refresh` | 위치 갱신. 서버 공동 캐시 최소 60초 |
| `GET /api/shuttle` | BUSIN 실시간 셔틀 위치. 서버 공동 캐시 15초 |
| `POST /api/plan` | 시간 의존 후보와 가중합 비교, 데이터 근거·가정 반환 |
| `GET/POST /api/observations` | 비식별 이동 결과 읽기/저장. 테스트 기록은 실제 통계에서 제외 |

활성 화면에서 버스 위치는 120초, 셔틀은 15초 주기로 요청합니다. 화면이 숨겨지면 갱신을 멈추며, 별도 스케줄러나 예약 수집 작업은 만들지 않았습니다. 시제품 자체의 일일 보호 한도는 위치 900회, 셔틀 2,000회, 웹 도착 조회 1,200회, 카카오 도보 800회입니다. 이는 제공기관 전체 한도나 무제한 이용 허가를 의미하지 않습니다.

- BUSIN 응답은 문서화된 공개 OpenAPI가 아니라 웹 조회 인터페이스입니다. 운영용 재이용 조건과 호출 범위는 제공기관 확인이 필요합니다.
- 셔틀의 차량별 제공시각은 원문 응답에 없어 수신시각을 표시합니다. 60초 이상 오래되거나 조회에 실패하면 추천용 관측에서 제외합니다.
- 셔틀 지도 표시의 의미는 **이름이 확인된 랜드마크 사이 구간**입니다. 대표 지점·직선 구간 강조이며 실제 도로 위 GPS 점이 아닙니다.
- 셔틀 ETA 범위는 실시간 구간 위치와 대표 지점 간 거리, 12~25km/h 속도 가정입니다. 공식 ETA나 측정된 오차 범위가 아닙니다. 셔틀 시간표로 관측 차량을 생성하지 않습니다.
- 버스 차내시간은 동일 차량의 두 정류소 도착예정이 대응될 때 그 차이를 사용합니다. 대응이 없으면 거리·18km/h·정차 15초 가정입니다. 미관측 버스 대기는 등록 배차간격의 절반 시나리오로 구분합니다.
- 일반 보행은 1.2m/s, OSM 계단 구간은 0.7m/s 가정입니다. 끝점과 보행망의 짧은 연결, 실제 출입구, 경사·계단·통행 가능성은 현장 검증 전입니다.
- 건물은 OSM 대표점, 역은 역 앞 대표 정류소를 사용합니다. 건물 입구나 역 승강장까지 정확히 도착한다고 표시하지 않습니다.
- 미래 시각에 현재의 실시간 위치를 외삽하지 않습니다. 정류소에서 걸어 도착하기 전에 떠나는 차량과 만차로 표시된 차량은 탑승 후보에서 제외합니다.
- 착석 확률·수업 종료 혼잡 예측은 아직 검증하지 않았고, 화면에서 수치로 생성하지 않습니다.

# 요일별 과거 이용량 예측 (0.3.0)

기본 이용량 예측은 검증한 `weekday_history` 모형입니다. `data/weekday_history.json`은 학습·튜닝 20일의 요일별 평균을 전체 평일 평균으로 보완한 값이며 API 키를 포함하지 않습니다. 서버가 경로의 각 구간 진입 예상시각에 맞춰 값을 붙이고, 화면에는 시간당 구간 재차합 평균으로 표시합니다. 실시간 혼잡 관측·예상 이동시간·혼잡 가중치와 구분합니다.

지원은 월~금 12~22시, 5개 시내·마을버스 259구간입니다. 주말·시간 밖·셔틀·정확히 일치하지 않는 구간은 예측 없음으로 표시하고 0으로 채우지 않습니다. 예측은 배포에 포함된 읽기 전용 파일을 사용하므로 추가 API·Blob·DB 호출이 없습니다. 학습 기간은 2026-09-07~10-30 중 20일이며 자동 갱신되는 자료는 아닙니다.

`GET /api/forecast`는 기본 모형·기간·지원 범위를 반환합니다. `route_id`, `from_seq`, `from_stop_id`, `to_stop_id`, `at`(Unix 초)를 함께 주면 한 구간의 해당 KST 요일·시간 예측을 조회합니다. `POST /api/plan`에는 각 버스 leg와 candidate의 `historical_forecast`가 기본 포함됩니다. 다수 구간 평균은 값이 있는 구간 수로 합을 나누며 부분 제공 범위를 명시합니다.
