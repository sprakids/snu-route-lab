# 수업 종료 모형의 조건부 구간 통과 출력

이 하위 폴더만 분석 채팅이 소유합니다. 기존 엔진·시나리오 산출물·T-data 수집·키는 변경하지 않습니다. 실제 보정·계수 적합·날짜 평가의 담당은 구현 채팅입니다.

2026-11-07 실행을 완료했습니다. 10회 이중 대조에 526.0초가 걸렸으며 READY와 내부·독립 출력 검산이 통과했습니다. 조건부 평균 27,784행, 기준 비중 적용 15,031행, 반복별 211,888행입니다. 원본 정류장 조건부 평균과 차이는 0이고 기존 원본 122개가 보존됐습니다. 259개 전체 링크 중 양수 모형 특징이 있는 링크는 135개이며 나머지를 관측 평가에서 제거하지 않습니다.

실행 근거는 outputs/validation.json, outputs/export_reconstruction_validation.json, calibration_binding_review.json입니다. 실제 출력은 day_offset0만 포함하므로 자정 이동 검산은 별도 합성 사례임을 구분합니다.

## 실행과 완료 판정

`run_segment_features.py`는 기존 공식 시나리오 실행에 보존된 엔진·입력·노선·보행 그래프를 복사하고, 원본과 같은 계산에 읽기 전용 감사를 추가한 함수와 구간 출력을 추가한 함수를 같은 seed로 대조합니다. 10개 seed 각각에서 경로 선택 fingerprint, 난수 상태열, 정류장 도착 bins, 이동수단, 지연 기록이 같아야 통과합니다. 조건부 정류장 평균은 이전 공식 실행의 CSV와도 대조합니다.

`outputs/READY.json`과 `outputs/validation.json`이 만들어져 PASS가 확인된 뒤 결과를 사용합니다. 출력 폴더는 덮어쓸 수 없습니다. 중간 진행 중인 gzip 파일은 완성된 자료가 아닙니다. 스크립트 문법 확인이나 참고 함수 예제 PASS가 실제 10회 엔진 실행 완료를 뜻하지 않습니다.

## 파일과 단위

- `conditional_segment_hour.csv`: 모든 수강 사건이 해당 목적지를 택해 이동한다고 놓은 구간 통과 가중치의 10회 평균. 기숙사·목적지·즉시 이동 확률은 아직 적용하지 않았습니다.
- `conditional_segment_hour_by_rep.csv.gz`: 같은 값의 반복별 출력. 나타나지 않는 모형 셀은 해당 반복 기여가 0입니다. 이것은 관측 자료의 null과 다릅니다.
- `baseline_segment_hour.csv`: 교외 세 방향 균등, 기숙사 5,772/29,613, 즉시 이동 0.5를 한 번 적용해 목적지를 합친 값입니다. 열 이름은 expected_trip_events입니다.
- `segment_index.csv`: 도시버스 5개 노선의 인접 259구간과 현재 노선 순서, 20261026 관측의 정확한 끝점·staSn 결합입니다.
- `rounding_diagnostics.csv`: 기존 Planner.ride_seconds의 부분 누적 반올림과 반올림 전 누적의 차이입니다. 개별 링크를 각각 반올림해서 더한 값과 전체 승차시간의 차이도 남깁니다.
- `replication_replay_checks.csv`: 반복별 경로·난수·stop bins 대조와 승객·구간 가중치 보존입니다.
- `input_manifest.json`, `output_manifest.json`, `original_inventory_before.json`, `provenance.json`: 실행 입력·원본 보존·시간·해시 근거입니다.

숫자는 예상 통행 가중치입니다. 한 통행이 5개 구간을 지나면 5개 구간에 각각 기여하므로 구간합을 더한 것은 고유 학생이나 고유 탑승자 수가 아닙니다. 차량 정원·배경 승객·탑승 실패·대기열을 새로 모형화하지 않았습니다.

## 시간대 두 정의

`clock=segment_entry`는 선택 경로에서 실제로 계산된 차량 출발 시각(정류장 도착+탑승 여유20초+동일 난수 대기)에 `Planner.ride_seconds(route, board_index, link_start_index)`를 더한 시각입니다. 과거의 정류장 도착 시각을 구간 통과 시각으로 바꾸어 쓰지 않았습니다.

`clock=boarding_hour`는 동일한 승차의 실제 모형 차량 출발 시각을 해당 승차의 모든 통과 구간에 적용한 대안입니다. 정류장에 도착한 시각이 아니며, 환승 승차는 두 번째 차량의 출발 시각입니다.

주 비교 연산자는 segment_entry라는 가정입니다. 공급기관이 이 시간 귀속을 확인한 것은 아닙니다. 두 연산자를 모두 공개하고, 평가 결과를 보고 유리한 연산자만 선택하지 않습니다.

두 clock은 같은 모형 통행의 대안 집계이므로 서로 더하지 않습니다. 같은 관측 자료에 대한 각각의 비교로 유지합니다.

## 날짜·요일 결합 계약

`weekday`는 원래 수업 종료 사건의 요일입니다. `day_offset=floor(초/86400)`, `hour=floor(초/3600) mod 24`입니다. 원래 수업 종료 날짜가 d이면 관측 귀속 날짜는 d+day_offset입니다. 예컨대 금요일 종료 통행이 자정을 넘으면 weekday는 금, day_offset은1, hour는0입니다.

날짜에 결합할 때 weekday를 단순히 실제 도착 요일로 바꾸고 offset을 또 적용하면 두 번 이동시킬 수 있습니다. 원래 요일에 대응하는 날짜를 먼저 정한 뒤 offset을 한 번 적용하거나, 같은 관계를 만족하는 명시적 키 변환을 사용해야 합니다. 이번 12~22시 평가 창 밖의 시각도 원 CSV에 남기므로 창 선택은 구현 채팅의 고정된 관측 마스크에서 처리합니다.

## 구간 결합 계약

현재 노선의 current_link_index0는 배열의 0-based 링크 위치이며, current_from_seq/current_to_seq는 보존 노선의 순서 필드입니다. observed_sta_sn은 20261026 관측에서 끝점과 현재 출발 순서가 함께 일치한 값입니다. 확인한 259구간에서 일치하지만 다른 날짜·다른 노선의 일반 정의가 확정됐다는 뜻은 아닙니다.

route_id + from_stop_id + to_stop_id만으로는 245개 조합이어서 259구간이 구분되지 않습니다. 반복 구간을 합치지 않도록 순서를 함께 사용합니다. 날짜·시간도 함께 맞추며, 키가 맞지 않으면 근접 정류장·이름으로 임의 보완하지 않습니다.

## 상태의 한계

이 출력 생성과 재현 검증의 성공은 관측 재차합 적합, 미사용 날짜 평가, 차내 혼잡률 검증의 성공과 다릅니다. 조건부 목적지 비중이나 기숙사 비율은 여전히 참고 가정이며 현재 학생의 실측 목적지 비율을 추정하지 않습니다. 배경 승객이 섞인 전체 버스 통행에 맞춘 계수는 유효 크기 보정으로만 해석해야 합니다.
