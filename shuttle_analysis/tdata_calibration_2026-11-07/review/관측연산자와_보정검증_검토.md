## 2. 비교 단위와 관측 연산자

한 행의 비교 키는 `(날짜, routeId, staSn, fromStaId, toStaId, 시간)`입니다. 방향 문자열이나 정류장 이름을 키로 대체하지 않습니다. 같은 구간을 되풀이하는 순환 노선에서는 양 끝 정류장 ID만으로도 불충분할 수 있어 순서를 포함해야 합니다.

구간 재차합을 통과 차량별 재차인원 합으로 해석할 수 있다면, 모형의 비교량은 다음입니다.

\[
M_{d,r,j,h}=\frac{1}{R}\sum_{k=1}^{R}\sum_{i,\ell}w_i
 1\{\ell\text{의 노선}=r\}
 1\{b_{i\ell}\le j<a_{i\ell}\}
 1\{\mathrm{day}(t_{i\ell j})=d,\ \mathrm{hour}(t_{i\ell j})=h\}.
\]

- i는 가중 모형 통행, ℓ은 승차 구간(환승하면 별도 승차), j는 인접 정류장 사이의 구간입니다.
- w에는 수강 인원·즉시 이동률·목적지 비중을 한 번만 적용합니다. 또는 목적지 조건부 M을 먼저 만든 뒤 비중을 한 번 곱합니다.
- b와 a는 승·하차의 노선상 위치입니다. 하차한 뒤의 구간에는 기여하지 않습니다.
- t는 실제로 모형 차량이 해당 구간에 들어가는 시각입니다. 정류장에 사람이 도착한 시각이 아닙니다.
- R=10이면 각 반복에서 발생하지 않은 셀도 0의 모형 기여로 평균에 포함합니다. **관측 자료의 null을 0으로 채우는 것과 다릅니다.**

예를 들어 가중치 10인 통행이 두 구간을 지나면 각 구간에 10씩, 구간 합계는 20입니다. 고유 승객 20명을 뜻하지 않습니다. 재차합을 만드는 데 초 단위 체류 시간을 다시 곱하지 않습니다. 그 값은 승객·시간으로 단위가 바뀝니다. 운행횟수가 없는 상태에서 재차합을 운행횟수로 나눠 평균 인원을 얻을 수도 없습니다.

`observation_operator_reference.py`는 실제 통과 링크·시각이 주어졌을 때의 작은 참고 구현입니다. 두 구간 이동, 시간 경계, 같은 끝점의 반복 구간, 자정을 넘는 달력일 처리의 수학 예제를 확인했습니다. **공급기관 시각 정의 확인, 실제 엔진 통합, 실측 보정은 수행하지 않았습니다.** 프로토타입의 calendar_date/segment_entry를 기관 정의로 간주하지 않습니다.

## 3. 기존 엔진에서 필요한 기록

기존 `simulate_stop_inflow.py`는 선택 후보의 board/alight 인덱스를 메모리에 보유하지만, 저장하는 bins는 `(요일, 목적지, 승차정류장, 방향, 노선, 도착5분, 승차단계)`뿐입니다. 도착 시각은 20초 탑승 여유와 대기시간을 더하기 전입니다. 집계된 기존 CSV에서 어느 정류장에 내렸는지나 구간 통과 시각을 복원할 수 없습니다.

원본을 보존한 새 runner에서 선택된 경로에 다음을 기록하거나 바로 M으로 집계하는 방법을 권합니다.

1. 날짜·요일, 반복, 종료 사건 ID, 목적지 집단, 조건부 가중치, 선택 후보 ID를 유지합니다. 이유는 수강 사건·목적지·반복이 중복 적용되는 것을 막기 위해서입니다.
2. 각 승차의 routeId, board/alight 인덱스, 노선의 인접 링크·검증된 API 순서를 유지합니다. 이유는 승차부터 하차 직전까지의 구간만 세기 위해서입니다.
3. 사람의 정류장 도착, 탑승 여유, 동일한 난수로 이미 계산한 대기시간, 차량 출발, 구간별 누적 이동시각을 구분합니다. 이유는 도착 15:59와 차량 출발 16:05가 서로 다른 시간대이기 때문입니다.
4. 기존 `Planner.ride_seconds`의 구간거리/5m/s 및 정류장당15초 가정과 일치하는 이동시간을 사용합니다. 링크별 반올림 누적과 총 승차시간의 차이도 기록합니다.
5. 모형이 고른 도시버스 구간만 T-data와 대조합니다. 교내셔틀 자체는 도시버스 API 관측 대상에 넣지 않고, 셔틀에서 도시버스로 환승한 경우 도시버스 부분만 포함합니다.

모든 입자 경로를 대형 파일로 저장하는 대신 조건부 구간·시간 집계를 실행 중에 누적하고 일부 경로 추적 표본을 남겨도 됩니다. 기존 난수 추출 순서를 바꾸거나 새 난수를 뽑아 경로를 다시 배정하지 않아야 공통 난수 비교가 유지됩니다.

목적지 가중치만 바꿀 때는 고정 경로의 조건부 M을 선형 결합할 수 있습니다. 반면 수업 후 출발 지연을 바꾸면 버스 대기·막차·경로 선택이 달라지므로 기존 5분 CSV를 옮기는 방식만으로 보정하면 안 됩니다. 지연을 적용한 출발시각부터 선택을 재계산해야 합니다.

- 동일 정류장·요일 이름만 맞추지 말고 관측의 실제 날짜·시간·방향·구간과 모형의 귀속을 맞춥니다. 실제 휴강·시험·행사·기상 영향도 별도 표식으로 남깁니다.

## 5. 배경 승객과 계수 식별

관측 전체 버스 구간 통행은 최소한 `Y = alpha*M(theta) + B + 오차`로 나뉩니다. M은 수업 종료 모형의 기여이고 B는 통과 승객·교직원·비수업 활동·수업 모형에 없는 이동입니다. B에는 캠퍼스 안에서 타는 누락 인구도 포함될 수 있어 외부 경계 승객만으로 전부 설명되지 않습니다.

관측 100, 모형 기준 40인 한 셀에서 `(alpha,B)=(0.5,80),(1,60),(2,20)`은 모두 정확히 맞습니다. 따라서 셀마다 자유로운 비음수 B를 두면 alpha나 목적지·즉시 출발 계수가 식별되지 않습니다. B=0을 가정해 맞춘 계수도 실제 학생의 귀가 확률이라고 부를 수 없습니다. 즉시 이동률과 별도 규모 계수를 함께 자유롭게 두면 두 계수의 곱만 식별되는 문제도 있습니다.

권장 순서:

1. 기숙사·목적지 비중은 현재 참고 시나리오로 고정하고, 비교 가능한 M부터 생성합니다. 이유는 여러 계수의 상쇄를 줄이기 위해서입니다.
2. 배경을 외부 경계 구간·독립 승하차/OD 등에서 제약할 수 있는지 확인합니다. 캠퍼스 통과 구간의 전후 차이만으로 귀가 수요를 분리하려면 중간 승하차와 시간 지체도 다뤄야 합니다.
3. 배경 근거가 없으면 총량 적합은 전체 버스 통행에 대한 **유효 크기 보정**으로만 명명하고, 학생 귀가율·거주율 추정은 보류합니다. 시간대 모양의 비교도 배경의 영향을 받으므로 학생 모형의 검증과 동일시하지 않습니다.
4. 규모와 출발 지연을 먼저 제한된 수로 검토하고, 목적지·기숙사 동시 추정은 조건부 구간 설계행렬의 순위·특이값·상관과 날짜분리 성능이 뒷받침할 때만 확장합니다. 윗공대 공통 출발 구간만으로 세 목적지를 구별하기 어려우면 분기 이후 구간이 필요합니다.

## 6. 날짜를 나눈 검증 설계

한 날짜 수집은 가용성·연산자 점검까지입니다. 같은 날짜의 일부 구간으로 맞추고 다른 구간에 점수를 내는 것만으로 날짜 일반화 성능을 주장하지 않습니다.

- 학습·조정·최종 평가 날짜를 먼저 나누고 저장합니다. 날짜의 모든 노선·구간·시간·모형 반복은 같은 묶음에 둡니다. 같은 날짜의 시간 셀을 무작위로 섞지 않습니다.
- 요일별 수업 구조를 고려해 각 묶음에 월~금이 포함되는 주 단위 분리를 우선합니다. 후보는 2026-10-12~16 학습, 10-19~23 조정, 10-26~30 평가입니다. 이는 달력상의 후보일 뿐 정상 수업일·자료 완결성·기존 열람에 따른 평가 오염을 확인한 뒤 확정해야 합니다.
- 이미 평가 날짜의 값으로 계수·시간창·노선·결측 처리·목적지를 선택했다면 그 날짜를 다시 최종 미사용 평가라고 부르지 않습니다. 10건의 스키마 확인과 대상 노선의 실제 값 기반 조정은 구분해 기록합니다.
- 배경 추정·정규화·결측 처리·계수 선택도 학습 자료에서만 정합니다. 최종 날짜 결과를 본 뒤 바꾸면 별도의 새 평가가 필요합니다.
- 수업 종료 가중치만 있는 기준 모형, 시간 지연을 포함한 모형 등을 같은 평가 키·결측 마스크로 비교합니다. 가장 좋은 참고 목적지 비중을 평가 자료에서 고른 뒤 정답 비중이라고 제시하지 않습니다.

## 7. 가능한 지표와 불가능한 결론

구간 시간합의 동일 단위·모집단을 갖춘 비교에는 `MAE = sum|Y-Yhat|/유효셀수`, `WAPE = sum|Y-Yhat|/sumY`를 노선·방향·날짜별로 기록할 수 있습니다. WAPE의 분모가 0이면 결측으로 둡니다. 비교에 사용한 셀 수, null 제외 비중, 0 관측 수를 함께 보고하고, 모든 시간대가 관측된 것처럼 확장하지 않습니다. 시간 피크의 차이는 원 자료가 1시간 간격이라는 해상도 안에서만 해석합니다.

모형 통행만을 전체 Y와 비교할 때는 그 잔차를 학생 수요 예측 오차라고 부르지 않습니다. B가 포함된 총 통행 예측을 만들었는지 먼저 명시해야 합니다. 여러 구간의 재차합을 더한 값은 승객·구간 노출량이며 고유 이용자 수가 아닙니다.

| 조건 | 허용되는 결과 명칭 |
|---|---|
| 목표 노선의 양수·null 분포만 확인 | 자료 가용성 확인 |
| 구간 매핑·시간 귀속 미확인 | 관측 연산자 설계/예비 비교 |
| 동일 단위로 만들고 같은 날짜에 계수를 적합 | 해당 자료에 대한 보정 적합 |
| 미사용 날짜에서 동일 지표·범위로 성능 확인 | 해당 구간 재차합의 날짜분리 검증 |
| 평균·운행횟수·차량정원 또는 차량별 재차 자료 미확보 | 차내 혼잡률 검증 완료라고 표현할 수 없음 |
| 대기·탑승 실패 자료 미확보 | 정류장 대기열·탑승 실패 검증 완료라고 표현할 수 없음 |

## 정합성 및 상태

`probe_review.json`은 원 응답의 null/양수/일합 대조와 목표 노선 포함 여부를 재계산합니다. `operator_reference_check.json`은 참고 연산자의 수학 예제만 확인합니다. 원본 모형·수집코드·키 파일을 수정하거나 인증 API를 호출하지 않았습니다. 공식 안내 페이지는 필드 정의 확인을 위해 읽었습니다. 실제 보정·실측 혼잡 검증은 아직 완료되지 않았습니다.
