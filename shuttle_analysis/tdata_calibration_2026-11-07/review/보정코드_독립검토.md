# 보정 코드의 단위·확률·날짜·평가 분리 검토

2026-11-07. `calibrate_model.py`, `build_report.py`, `verify_artifacts.py`, `analysis_plan.json`을 읽었습니다. 원본/수집/키/구현 측 파일은 수정하지 않았습니다. 이 문서는 코드의 분리·계산 검토이며 아직 결과 오차를 확인한 보고서가 아닙니다.

## 확인한 내용

1. **단위:** 조건부 구간 통과 가중치를 기관의 시간별 구간 재차합과 비교하며 정류장 도착량을 직접 대조하지 않습니다. 귀가율·거주율·차량 혼잡률이 아니라 전체 승객 재차합에 대한 유효 크기 보정으로 명명합니다. 미확인 시간 귀속과 배경 승객 누락도 보고서에 남아 있습니다.
2. **확률:** standardized_features는 확률 미적용 conditional_trip_events에 기숙사·교외 조건부 비중·즉시 이동률을 한 번만 곱한 뒤 목적지를 합칩니다. baseline_segment_hour.csv에 확률을 다시 곱하는 경로는 아닙니다. 두 clock을 서로 합치지 않고 각 연산자별로 평가합니다. 실제 출력과 이 함수의 결합은 별도 calibration_binding_review.json에서 대조합니다.
3. **요일:** 원래 종료 요일을 `(origin weekday + day_offset) mod 7`로 한 번 옮기고 시간은 기존 hour를 유지합니다. 이는 매주 반복되는 시간표 특징을 해당 관측 요일에 붙이는 방식입니다. 공급기관 운행일의 정의를 확정한 것은 아닙니다. 현재 평가 창은 12~22시이며 자정 효과는 원 CSV에 보존됩니다.
4. **계수:** 학습 split의 bbox·관측 non-null 셀만 계수의 M²·MY 계산에 들어갑니다. 관측 Y>0, 모형 M=0인 셀을 제거하지 않습니다. 실제 관측 null은 그대로 두고, 모형의 비어 있는 기여만 0으로 채웁니다.
5. **과거 기준선:** 학습 split에서만 노선·순서·끝점·시간 평균을 계산합니다. 요일을 합친 월~금 평균이며 평가 주 값이 평균 계산에 들어가지 않습니다.
6. **날짜 분리:** 날짜 집합이 서로 다름을 assertion으로 확인하고, 평가 값이 scale(x,y) 학습에 들어가는 코드 경로는 보이지 않았습니다. 범위·비중·두 연산자·네 예측 모형은 계획 파일로 고정돼 있습니다. 이미 일부 관측을 열람한 사실을 기록하므로 맹검·완전 사전등록 평가라는 주장은 하지 않습니다.
7. **독립 산술:** 구현 측 verify_artifacts는 원 JSON과 예측 행의 관측값을 대조하고, 학습에서 계수·기준선 평균을 다시 계산하며, MAE/WAPE/RMSE를 다시 계산하도록 돼 있습니다. 이 검토에서는 인증키를 복호화하는 검증 함수를 실행하지 않았습니다.

## 결과 생성 후 확인할 조건

- 노선별 `sum_xx`가 0인 경우 코드가 반환하는 alpha=0은 식별된 0 계수가 아니라 모형 기여가 없는 상태입니다. 그런 노선이 있으면 추정 불가로 별도 표시해야 합니다.
- 주 평가 6,875셀의 동일 비교 범위를 확인하고, 보조 전체 노선에서는 모형마다 유효 셀 수가 달라지는지 확인해야 합니다. 과거 기준선의 학습 평균이 없는 셀을 제외한 지표와 다른 모형의 전체 셀 지표를 같은 범위인 것처럼 순위 매기면 안 됩니다.
- 주 연산자와 노선별 계수의 소개는 결과를 보기 전에 고정된 비교라는 점을 유지해야 합니다. 평가 오차를 본 뒤 가장 나은 모형만 남기지 않습니다.
- `verify_artifacts`의 raw_observation_prediction_cells_reconciled는 두 연산자에 각각 존재하는 예측 행 수입니다. 고유 관측 셀이나 새로운 표본 수로 해석하지 않습니다.
- `analysis_plan.json`의 날짜가 분리돼 있어도 11월 수강 자료를 10월에 역적용한 정보 차이, 한 학습 주/한 평가 주의 한계, 전체 승객과 수업 종료 모형의 모집단 차이는 해결되지 않습니다.

정적 코드 검토에서는 확률 중복 적용이나 평가 날짜를 계수에 직접 넣는 경로를 발견하지 않았습니다. 실제 출력·학습 결과까지의 검증 상태는 실행 후 생성되는 증거와 구분합니다.

## 출력 생성 후 확인한 범위

- 실제 조건부 특징을 구현 측 standardized_features 함수에 넣어 별도 baseline 출력과 15,031행을 대조했습니다. 확률·요일 결합의 최대 차이는 1.71e-13입니다. 확률을 한 번 적용한 값과 일치했습니다.
