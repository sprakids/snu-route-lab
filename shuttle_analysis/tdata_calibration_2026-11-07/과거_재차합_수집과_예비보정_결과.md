# T-data 키 발급·과거 구간 재차합 수집과 예비 보정 결과

작성일: 2026-11-07. 할루시네이션 방지 O: 직접 수집한 관측값, 모형 가정, 수행한 검증, 남은 한계를 구분했습니다.

T-data 활용신청과 저작권자 표시 동의를 제출해 처리 완료를 확인했고, 개발 인증키 발급 및 인증된 HTTPS 조회까지 완료했습니다. 키는 저장소 밖에서 현재 Windows 사용자에 묶인 DPAPI로 암호화 보관했습니다. 이 문서·코드·CSV에는 키 원문을 싣지 않았습니다.

5개 노선의 10일치 자료를 확보했습니다. 수업 모형에 노선별 규모 계수를 곱한 뒤 평가 주의 WAPE는 82.51% → 80.05%로 낮아졌습니다. 과거 구간·시간 평균 기준선은 20.15%입니다. 이 비교는 전체 버스 구간 재차합에 대한 예비 평가이며 학생 귀가율·차량 혼잡률·셔틀 줄 길이 검증을 뜻하지 않습니다.

## 1. 어떤 API와 값을 실제로 받았는가

[서울시 T-data 공식 API1025](https://t-data.seoul.go.kr/dataprovide/trafficdataviewopenapi.do?data_id=1025)의 `일자별-시간대별-버스노선별-구간별-승객수`를 사용했습니다. 엔드포인트 서비스명은 `TaimsTpssA18RouteSection/1.0`, 요청은 HTTPS와 기준일·페이지 번호를 사용합니다. 공식 갱신 주기는 월 1회이므로 과거 검증 자료입니다.

| 노선 | 노선 ID | 날짜당 전체 구간 | 주 비교 범위 구간 |
| --- | --- | --- | --- |
| 5511 | 100100250 | 72 | 37 |
| 5513 | 100100251 | 43 | 17 |
| 5516 | 100100253 | 73 | 32 |
| 관악02-1 | 120900011 | 38 | 22 |
| 관악02-2 | 120900012 | 33 | 17 |

학습: 2026-10-19~23(월~금). 평가: 2026-10-26~30(월~금). 각 날짜의 모든 노선·구간·시간은 같은 묶음으로 유지했습니다.

- 목표 노선 원행: 2,590행(259구간 × 10일). 시간 셀: 62,160개.
- 시간별 재차인원 합계: 값 있음 49,173셀, null 12,987셀. null은 0으로 바꾸지 않았습니다.
- 평균 재차인원·최대 재차인원·운행횟수: 62,160셀씩 모두 null입니다.
- 모든 날짜의 259구간이 보존 노선의 출발 순서·출발 정류장 ID·도착 정류장 ID와 정확히 결합됐습니다. 같은 끝점 쌍이 반복되어 순서를 빼면 245조합으로 줄어듭니다.
- 2,590행 모두 일 재차합이 알려진 시간별 값의 합과 일치했습니다. 이는 null을 관측된 0으로 해석할 근거는 아닙니다.
- 수집·프로브를 포함해 로컬 장부에 93회가 기록됐습니다. [공식 일 한도](https://t-data.seoul.go.kr/userguide/guideopenapi.do)는 1,000회입니다. 서울시 실시간 버스 API 예산과는 별개입니다.

재차합은 한 시간에 구간을 지난 차량들의 차내 인원을 합한 것으로 조건부 해석했습니다. 여러 구간 합계는 같은 사람이 여러 번 포함되는 승객·구간량입니다. 고유 승객 수나 버스 한 대의 탑승 인원이 아닙니다. 공개 안내에 정확한 합산 산식·시간 귀속·운행일 자정 처리가 없어 이 해석은 기관 확인 전의 가정으로 남겼습니다.

## 2. 왜 기존 정류장 도착량을 바로 비교하지 않았는가

기존 시뮬레이션의 5분 값은 수업 종료 후 정류장에 도착할 것으로 배분한 수강 사건 가중치입니다. 차내에 탔는지, 어디까지 탔는지, 기다린 뒤 언제 출발했는지를 포함한 재차합과 단위가 다릅니다. 따라서 원본을 보존한 새 실행에서 선택된 경로의 승차·하차 위치와 모형 출발 시각을 기록했습니다.

1. 모형 정류장 도착에 탑승 여유 20초와 기존 대기를 더해 차량 출발을 계산했습니다. 대기 전 도착 시각으로 재차를 집계하는 오류를 피하기 위해서입니다.
2. 승차 구간부터 하차 직전까지의 인접 구간마다 가중치를 한 번 집계했습니다. 하차 뒤 인원을 계속 세거나 승객·초로 단위를 바꾸지 않기 위해서입니다.
3. 구간 진입 시각은 기존 주행시간 함수의 부분 누적으로 계산했습니다. 탑승 시간대 집계도 민감도 대안으로 같이 만들었습니다. 기관의 시간 귀속을 임의로 확정하지 않기 위해서입니다.
4. 기존 10개 난수 반복을 그대로 사용하고 원래 정류장 도착량·경로 선택·난수 상태를 재현했습니다. 기능 추가 자체가 경로를 바꾸지 않았음을 확인하기 위해서입니다.

정합성 결과: 10개 반복의 경로·난수 상태 및 정류장 도착량·교통수단 배분이 모두 재현됐습니다. 이전 조건부 평균과 최대 차이는 0, 부분 누적시간 반올림 차이는 최대 0.453초입니다. 승객·구간량 보존 검사를 통과했고 기존 파일 122개가 변경되지 않았습니다.

## 3. 보정과 평가를 어떻게 했는가

목적지 비중·기숙사 비중·즉시 이동률은 데이터를 보고 정답으로 추정하지 않았습니다. 기존 기준 가정인 기숙사 5,772/29,613=19.4914%, 나머지 세 목적지 균등, 즉시 이동률 50%를 고정했습니다. 기숙사 수와 전체 재학생 수의 기준 연도·모집단 차이가 있어 실제 관악 수강생 거주 비율로 확정할 수 없습니다.

주 평가 범위는 기존 잠정 직사각형(lat 37.444~37.468, lon 126.944~126.962) 안의 출발 정류장을 가진 125구간, 양방향 모두입니다. 이는 공식 캠퍼스 경계가 아닙니다. 11:20~23:10 안에 완전히 포함되는 12:00~22:59의 11개 시간대를 택했습니다. 평가 5일 × 125구간 × 11시간 = 6,875셀은 관측 결측 없이 모두 비교했습니다. 전체 259구간 평가도 metrics.csv에 별도로 공개했습니다.

`Y`를 관측 전체 재차합, `M`을 기준 모형의 구간 통과 가중치라 할 때 `Yhat = alpha × M`으로 계산했습니다. alpha는 학습 자료의 제곱오차를 최소화하는 비음수 계수이며, 공통 1개와 노선별 5개를 각각 맞췄습니다. 식은 `alpha=max(0, sum(MY)/sum(M²))`입니다. 절편·자유로운 배경 승객을 동시에 맞추면 학생 계수와 구분하기 어려워 이번에는 추가하지 않았습니다.

공통 계수는 0.580675입니다. 전체 버스 이용에는 비수업 학생·교직원·통과 승객 등이 포함되므로 이 계수는 귀가 확률이나 실제 기숙사 거주율이 아닙니다. 모형이 0인데 관측이 양수인 셀도 제외하지 않았습니다. 평가의 그런 셀은 2,013개이고, 모형 0 셀에 들어 있는 관측량은 전체의 18.51%입니다.

과거 기준선은 학습 주 월~금의 동일 노선·구간·시간 유효값 평균입니다. 요일은 합쳐 계산하며 평가 값은 사용하지 않습니다. 평가 주로 모형·목적지 비중·계수를 다시 선택하지 않았습니다. 다만 10월 26일을 스키마·결합 확인에 먼저 사용했으므로 엄격한 사전등록 맹검 실험이 아닌 날짜 분리 탐색 평가로 명명합니다.

## 5. 해석의 한계와 적용 상태

- 관측은 전체 승객이고 모형은 수업 종료 사건의 일부입니다. 그 잔차 전체를 학생 모형의 오차로 해석하지 않습니다. 규모 하나를 맞춰도 모형 0 구간이나 배경 승객의 시간 모양을 복구할 수 없습니다.
- 평균·운행횟수·차량 정원 자료가 없어 한 대당 차내 인원, 만차율, 정원 초과율은 검증하지 못했습니다. 실제 셔틀 줄·탑승 실패 관측도 없어 버스와 셔틀 줄의 상관계수는 보정하지 않았습니다.
- 원 자료는 1시간 집계입니다. 수업 직후 5분 몰림, 혼잡이 몇 분 지속되는지, 15초 갱신이 실제로 더 정확한지는 이 자료만으로 검증하지 못했습니다.
- [서울대 2026 학사일정](https://snu.ac.kr/academics/resources/calendar)상 10월 20일은 수강신청 취소 마감입니다. 11월 6일 수강 자료를 그 이전에 역적용하면 당시 수강생이 빠질 수 있습니다. 개별 중간고사·휴강·실제 출석·기상·행사도 반영되지 않았습니다.
- 한 학습 주와 한 평가 주만 사용했습니다. 날짜를 나눴다는 사실만으로 다른 학기·방학·특수일에 일반화된다고 할 수 없습니다. 같은 시간표의 요일 반복과 실제 경로 변경 가능성도 남아 있습니다.
- 보정은 로컬 분석 산출물입니다. 운영 앱·Vercel·실시간 수집 스케줄·저장소는 이 작업에서 변경하지 않았습니다. 수업 수요, 과거 전체 버스 패턴, 실제 현재 혼잡 정보를 별도 근거로 결합하는 후속 설계에 사용할 수 있습니다.

## 6. 재현과 파일

- analysis_plan.json: 계수 적합 전 고정한 범위·가정·날짜 분리.
- collected/YYYYMMDD/: 변경하지 않은 API 페이지 gzip, 페이지 영수증, 목표 노선 JSON.
- observations/quality_audit.json: 자료 결측·정류장 순서 결합·날짜 중복·일합 검사.
- observations/hourly_observations.csv: null을 보존한 62,160개 시간 셀.
- review/segment_model/outputs/conditional_segment_hour.csv: 확률 적용 전 목적지별 10반복 평균 구간 통과량.
- review/segment_model/outputs/validation.json: 난수·선택경로·도착량 재현 및 원본 보존 검사.
- calibration/coefficients.csv, metrics.csv, cell_predictions.csv: 학습 계수·날짜/노선/범위별 오차·모든 셀 예측.
- calibration/evaluation_segment_hour_profile.csv: 평가 구간·시간별 관측과 모형 평균.
- api_request_ledger.json: 키를 포함하지 않는 호출 장부. 수집 코드는 암호화 키를 프로세스 안에서만 복호화하며 자동 재시도하지 않습니다.

제공: 서울특별시 서울교통 빅데이터 플랫폼 / 교통정책지원시스템(TAIMS). 원 자료 저작권자 표시(BY) 조건에 따라 출처를 표시했습니다. 가공·모형·해석 및 오류의 책임은 본 프로젝트에 있습니다.
