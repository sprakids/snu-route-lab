작성일: 2026-11-10, 한국시간.

## 사용자 지시와 실행 범위

사용자는 전달한 MATSim·Visum·OTP·BusMezzo 관련 설계 정보를 참고하여 **기존 모형과 별도의 새로운 프로토타입을 개발하고, 실측과 비교해 기존보다 잘 맞으면 교체하고 그렇지 않으면 폐기하는 개발 과제**로 시뮬레이션 에이전트에게 전달하라고 명시했습니다.

이는 이전 승하차 계획의 ‘계획 검토만’ 범위를 **새 프로토타입 개발·오프라인 실행·실측 검증에 대해서 확장**한 최신 지시입니다. 조사 보고서 본문의 ‘조사만 했고 적용하지 않았다’는 문장은 과거 조사 상태이며, 이번 개발 지시를 제한하는 문장이 아닙니다. 설계 검토만 하고 종료하지 말고 분리된 프로토타입 구현과 비교까지 진행해 주세요.

조건을 만족한 경우에는 사용자가 요청한 교체까지 진행할 수 있습니다. 다만 승격 전까지 기존 운영 입력을 바꾸지 않으며, 실측 부족이나 비교 불가능 상태를 개선 증거로 취급하지 않습니다.

## 2. 가져올 설계의 핵심

| 모듈 | 구현 방향 | 단위와 구분 |
|---|---|---|
| 실제 이동시간 | 실제 도로·보행망, 버스 운행시각, 구간 속도·정차, 보행 경사·계단·횡단 지연 | 화면에 보여줄 물리적 시간 |
| 선호 비용 | 도보·대기·차내시간·환승·요금·혼잡 불편·추가 경로 변경 부담을 분리 | 합성 여행자의 선택을 설명하는 비용. ETA와 구분 |
| 차량 용량 | 도착→하차→여석→적격 FIFO 승차→잔류·탑승 실패→다음 정류장 | 실제 모형 차량별 정원과 재차 수지 |
| 확률적 행동 | 합성 여행자마다 일관된 선호와 개인차, 대기·만차·새 정보에 따른 재판단 | 목적지별 고정 포기시각을 사용하지 않음 |
| 경로 후보/전략 | 도보·시내버스·셔틀·호환 노선 공동 대기·환승 후보와 유사 경로 묶기 | 후보 중복으로 선택 확률이 부풀지 않게 함 |

MATSim에서는 개인별 효용·경험에 따른 계획 수정, Visum에서는 일반화비용과 용량 제약, OTP에서는 보행·시간표를 연결한 경로와 물리시간/비용 구분을 참고합니다. 각 제품 자체로 전체 플랫폼을 이관해야 한다는 요청은 아닙니다.

## 3. 실제 시간과 선택 비용

- 평지 보행 기준은 사용자 지정 **4.8km/h = 약 1.3333m/s**입니다. 경사·계단은 해당 보행 구간의 실제 시간에 반영하고, 추가적인 피로 선호는 별도 비용으로 둡니다. 경사·계단 시간 보정을 경로 전체에 일괄 적용하거나 같은 효과를 중복 가산하지 않습니다.
- 도보 부담 배율이 2라고 해서 도보 5분을 ETA 10분으로 표시하지 않습니다. 승차 비용 600도 실제 대기 600초를 추가하는 값으로 쓰지 않습니다.
- 실제 추가 요금을 사용합니다. 이미 낸 요금·환승 할인과 관계없이 매번 전액을 더하지 않습니다.
- 무료 셔틀을 5~7분 더 기다린다는 값, 목적지별 5~8·10~12·12~15분, 건물군별 15~20분 등은 서울대 실측으로 확인한 표준값이 아닙니다. 필요하면 이름 붙인 민감도 시나리오로만 사용합니다.

분 단위 선택 비용의 검토식은 다음과 같습니다. 계수는 학교 실측으로 확정된 값이 아닙니다.

\[
G_{i,r}=T_{ride,r}+a_iT_{walk,r}+b_iE[W_r\mid t_{stop-arrival}]
+c_iN_{transfer,r}+60F_{incremental,r}/VOT_i
+K_i(n)\mathbf1_{change}+D_{crowding,i,r}.
\]

`VOT`는 원/시간, `G`는 분 상당의 선호 비용으로 정의합니다. 정원 때문에 못 타서 발생한 실제 추가 대기와 차내 혼잡의 불편 비용은 별개이며 같은 지연을 두 번 더하지 않습니다.

최종 ETA는 실제 사건시각으로 계산합니다. 앱의 ‘가장 빠른 경로’는 실제 예상 총시간을 기준으로 유지하고, 합성 여행자의 비용 최적 경로나 사용자 선호 경로와 구분합니다. 시뮬레이션 행동확률을 이유로 실제 사용자가 볼 경로를 무작위로 숨기지 않습니다.

## 4. 대기열과 승차 처리

단순한 `floor(앞의 인원/잔여 정원)×배차간격+다음 도착` 식을 주 엔진으로 쓰지 않습니다. 일정 배차·일정 여석의 단순 사례 검산에만 사용합니다.

1. 차량이 정류장에 도착합니다.
2. 하차를 먼저 반영합니다.
3. 정원에서 남은 차내 인원을 빼 여석을 계산합니다.
4. 해당 차량·방향·구간을 탈 수 있는 사람들 사이에서 FIFO로 태웁니다.
5. 못 탄 사람, 새 탑승 실패, 계속 대기·도보 이동·다른 정류장 이동을 기록합니다.
6. 탑승·하차·환승·회차가 뒤 구간 재차와 대기에 미치는 영향을 이어 계산합니다.

자료 계약에 다음 시각을 분리합니다: `stop_arrival_at`, `ready_at`, `boarding_at`, `leave_at`. 기존 준비시간 20초는 운영 가정이며 명시적으로 버전 관리합니다. 정류장 체류 대기와 준비완료 후 적격 대기를 구분하고, 총시간에서 준비시간을 이중 합산하지 않습니다.

준비 완료 전 떠난 방문은 적격 유입이 아니지만 실제 이동·방문 기록에서는 보존합니다. 기존 어댑터의 준비 전 취소 처리·검증을 완화하거나 종료시각을 ready로 잘라 해결하지 않습니다. 현재 검증된 어댑터 코드는 보존하고 프로토타입에서도 같은 의미를 지킵니다.

검산 예시는 만차 차량, 하차 후 여석 발생, 노선 자격이 다른 공동 줄, 두 대를 보내고 세 번째 탑승, 준비 전 이탈, 회차 후 잔류입니다. ‘두 대를 보냄’과 ‘세 대를 보냄’을 구분합니다.

## 5. 개인차와 사건별 선택

- 합성 여행자의 시간·요금·도보·혼잡 민감도는 한 통행 동안 일관되게 유지합니다. API 갱신 때마다 다시 추첨하지 않습니다.
- 출발 시 걸어갈 정류장, 차량이 왔을 때 승차/계속 대기, 대기 중 다른 정류장/도보 전환을 순차적으로 판단합니다. 현재 시각에 이용 가능한 정보와 예측만 사용하고 미래 실측을 알고 행동시키지 않습니다.
- Log-normal·Weibull의 잠재 성향 분포, 랜덤 효용, 시간에 따른 이탈 확률 등은 비교 후보입니다. 많은 분포·계수를 한꺼번에 넣어 적은 관측에 맞추지 않습니다.
- 시간 간격을 바꾸면 같은 확률을 더 자주 뽑게 되는 문제를 점검합니다. 필요하면 경과시간에 맞춘 전이 확률/위험률을 사용하고, 선택 빈도가 지도 재생·API 폴링 주기에 종속되지 않게 합니다.
- 가중치가 큰 이동 집단 하나를 통째로 이탈시키지 않도록 선호 이질성을 분할하거나 적분하되 전체 가중 통행을 보존합니다. 표시용 지도 표본 점을 실제 수요·탑승인원으로 세지 않습니다.
- 최신 사용자 조건인 **경로 변경 횟수 상한·예산·소진 없음, 두 번째 변경부터 기본 성향 감소, 반복 만차·긴 대기 시 재판단 가능**을 유지합니다. 0~500m의 같은 기본 도보 고려도, 1km 이후 급감 조건도 초기 제약으로 유지하고 다른 효과와 구분합니다.
- 20분 대기·약 40명 줄은 원인 점검/비교 지표이며, 강제 이탈·수요 삭제·줄 자르기 조건이 아닙니다. 보존된 관측 상한이라고 부르지 않습니다.
- 실제 앱 개인 재추천 정책과 합성 여행자 행동 엔진은 별도 범위입니다. 앱의 별도 변경 횟수 분기를 이번 행동 모델과 동일하다고 설명하지 않습니다.

## 6. 경로·목적지·공급의 일관성

- 기존 네 목적지(서울대입구역·낙성대·대학동·기숙사)와 같은 출발지·출발시각·수요를 사용해 기준과 비교합니다.
- 관악산역/신림선과 다른 역을 비교하려면 이후 최종 귀가 목적지와 연결편까지 일치시킬 입력이 필요합니다. 서로 다른 끝점의 도착시간만 비교해 빠른 귀가라고 판정하지 않습니다.
- 출발 건물 효과는 가능한 한 실제 접근 도보시간·경사·교통 대안으로 나타나게 합니다. 건물군별로 임의의 고정 최대 대기를 넣지 않습니다.
- 비슷한 노선·경로를 중복 열거한 수만큼 선택 확률을 늘리지 않습니다. 공동 대기 전략의 실제 탑승 자격과 경로 유사성을 고려합니다.
- 셔틀 예정 운행은 사용자가 지정한 공식 두 페이지를 우선 확인합니다. 학기·계절학기·방학 및 임시 공지의 적용 기간을 섞지 않습니다. 시간표와 실측 출발은 구분합니다.
- 원인 비교 단계에서는 공급·정원·속도·수요 총량·보행망·난수를 양쪽에 맞춥니다. 별도 실측 개선 입력을 넣는 실험은 단계적으로 분리해 어느 변경 때문에 결과가 달라졌는지 남깁니다.

프로토타입을 만들고 경계 사례를 검산한 뒤, 보정·설정 선택·마지막 검증의 날짜와 지표를 **마지막 정답을 보기 전에** 기록합니다.

- 기존 11월 9일 3관측은 v9 선택에도 사용됐으므로 독립 검증에 쓰지 않습니다. 이 기준 모형으로 11월 4~6일을 비교해도 전체 구성요소가 시간적으로 독립인 운영 backtest는 아닙니다.
- 현재 과거 자료는 예비 사후 정합성 분석에 사용합니다. 독립 판단에는 기준·후보를 동결한 뒤 사용하지 않은 새 날짜를 확보합니다. 원칙은 28일의 14일 보정·7일 선택·마지막 7일 검증입니다. 11/11~24, 11/25~12/1, 12/2~8은 앞서 제안한 예시이며, 실제 범위·자료 이용 가능성·누락 상태를 확인해 시작 전에 확정합니다.
- 각 예측의 `available_at`을 기록합니다. 미래 하루 합계·나중에 공개된 월 자료·미래 실측 도착을 알고 과거를 예측한 실험을 실시간 예측 성능으로 부르지 않습니다.
- 날짜 전체를 분리합니다. 같은 차량·같은 대기열의 연속 15초 기록이나 같은 승하차 원천의 두 표를 독립 표본처럼 늘리지 않습니다. 난수 반복 횟수도 실측 표본 수가 아닙니다.
- 여러 무작위 반복을 비교하되 기준/후보의 같은 조건에는 같은 난수를 사용하고, 계산량은 작은 파일럿 후 정한 유한 실험표로 관리합니다.
- 모델을 나눠 시험합니다: 기준, 물리 시간 분리, 용량/탑승 처리, 개인차/비용/순차 선택, 결합 프로토타입. 동시에 바뀐 요소가 만드는 개선을 하나의 원인에 귀속시키지 않습니다.

## 9. ‘더 잘 맞음’의 판정

판정표를 사전 작성합니다. 실제 정답과 범위가 맞는 지표만 성능 지표로 사용합니다.

| 대상 | 비교 항목 |
|---|---|
| 실측 대기시간이 있는 통행 | 도보 후 해당 정류장 도착시점의 대기 예측 오차, 준비 포함/제외 정의, 중도 이탈·관측 종료 시 미승차 처리 |
| 실제 대기인원 관측 | 정류장·방향·시각별 인원 오차. 초 미상은 분내 분포로 비교하고 가장 유리한 초를 고르지 않음 |
| 승하차 | 정렬된 노선·정류장·시간별 승차/하차 MAE·WAPE, 총량과 노선별 악화 |
| 이동시간·선택 | 실제 도보·차내시간·총시간 오차, 확인 가능한 선택/이탈 방향·탑승 실패 |
| 모형 수지와 운영성 | FIFO·정원·질량·준비 전 취소, 미완료 통행, 시간분해 합계, 경로 도로 일치, 계산시간·응답 성능 |

자료가 있으면 대기시간 오차를 핵심 지표로 두고 대기인원·승하차·총시간을 함께 확인합니다. 대기시간 정답이 없으면 어떤 관측으로 무엇만 검증 가능한지 먼저 제한하고, 승하차 오차 감소로 대기시간 정확도까지 입증했다고 하지 않습니다.

‘허용할 악화 폭’과 핵심 지표를 마지막 값을 본 뒤 바꾸지 않습니다. 수치가 소폭 좋아 보이는 것만으로 승격하지 말고 날짜별 변동·표본 수·관측 해상도와 핵심 정류장 악화를 확인합니다. 실용적 개선의 기준은 관측 단위·정밀도에 맞춰 시험 전에 근거와 함께 정합니다. 특정 관측 3건을 맞추기 위해 기준을 사후로 완화하지 않습니다.

## 10. 교체·폐기 규칙과 사용자가 승인한 후속 조치

1. **개발/파일럿:** 분리된 프로토타입 구현과 내부 검산을 실행합니다. 아직 운영을 바꾸지 않습니다.
2. **보정/검증:** 위에 고정한 자료 분리와 같은 조건으로 기존과 비교해 결과·제외 범위·불확실성을 보고합니다.
3. **승격:** 미사용 실측에서 사전 판정 기준을 충족하고 핵심 지표 악화·수지 위반·운영 회귀가 없으면 사용자가 요청한 교체 조건을 충족한 것으로 처리합니다. 검토 가능한 비교 결과를 남긴 뒤 새 모형과 경로 대기 입력을 일치시켜 발행·공개 확인·운영 반영까지 진행할 수 있습니다. 이미 승인된 이 조건부 교체에 대해 같은 허가를 다시 요구하지 않습니다.
4. **탈락:** 충분히 비교 가능한 자료에서 개선이 없거나 악화하면 `DISCARDED`로 표시해 운영 후보에서 폐기합니다. 기존 모형은 유지하며 원본·실험 코드·실패 근거·비교 결과는 보존합니다.
5. **판정 불가:** 실측 부족·비교 범위 불일치면 `NOT_EVALUABLE`로 표시하고 교체를 보류합니다. 자료가 없는 상태를 성공이나 열등함으로 판정하지 않습니다. 필요한 추가 관측과 남은 작업을 구체적으로 보고합니다.

승격 시 데이터 계약·단위·호환성·모형 ID·입력 해시를 검사하고 기존 릴리스를 복구 가능하게 보존합니다. 호환성 의미가 달라졌는데 기존 호환성 해시를 그대로 붙이지 않습니다. 후보를 운영 latest에 쓰는 행위도 실제 승격에 포함됩니다. 실제 추천 응답의 모형 ID와 도보+준비+대기+승차 합계를 확인합니다.

## 11. 개발 산출물과 진행 요청

- 별도 프로토타입 엔진과 설정·출처 기록, 고정 입력 manifest.
- 경계 사례 검산과 전체 수지·개인차·반복 변경·도보거리 확인.
- 사전 고정한 분할·지표·계수 범위, 기준과 후보 비교표, 구성 요소별 실험 결과.
- `PROMOTE / DISCARDED / NOT_EVALUABLE` 판정과 근거, 데이터 부족 항목.
- 승격할 때만 발행 모형 ID·payload/입력 SHA·추천 응답·공개 확인·복구 기준.

우선 별도 디렉터리를 정하고 구현에 착수해 주세요. 물리 시간·효용·용량·확률 행동의 인터페이스를 먼저 정리한 뒤 작은 파일럿을 실행하고, 그 다음 사전 고정한 비교로 확장합니다. 기존 운영 작업과 파일 소유권이 충돌하지 않게 진행 상황과 필요한 자료를 회신해 주세요.
