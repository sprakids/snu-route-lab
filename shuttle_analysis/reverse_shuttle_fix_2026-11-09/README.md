# 전체 셔틀 실시간 위치 복구

2026-11-09 17:36 KST 공개 서비스 검증 완료. 앱 0.21.2.

## 원인

BUSIN 원문은 역순환 차량 2대를 정상 반환했다. 좌표 해석과 해당 도로 구간도 유효했다. 반면 공용 캐시의 claim/publish와 조회 예산 차감은 모두 같은 `auxExec` 보호장치를 사용했다. 보조 쓰기 수가 8,989에 도달하자 `8,989 + 12 > 9,000` 조건으로 이후 쓰기를 차단했다. 전체 DB 쓰기는 약 2.4만 회였으므로 전체 저장소가 가득 찬 상황은 아니었다.

캐시 claim 실패를 앱이 빈 결과로 처리하고, 지도는 오래된 관측을 제외해 모든 셔틀 위치가 사라졌다. 세부 노선이나 API 인증 문제가 아닌 공통 경로의 장애였다.

## 수정

- 등록된 10개 BUSIN 노선의 짧은 캐시·조회 잠금은 단일 Durable Object의 공용 메모리에서 처리한다. Vercel 인스턴스별 독립 조회로 우회하지 않는다.
- 마지막 관측은 노선을 묶어 최대 분당 한 번 DB에 저장한다. 서버 재시작 때 복원하며 관측 시각을 새 시각으로 바꾸지 않는다. 최근 1분 이내의 미저장 캐시는 재시작 시 다시 조회할 수 있다.
- BUSIN 호출은 최대 32건씩 먼저 영구 예약한다. 서버가 재시작되면 사용하지 못한 예약도 차감된 채 남으므로 하루 6,000건 상한을 넘길 수 없다. 서울시 위치 API의 기존 상한·수집 정책은 변경하지 않았다.
- 전체 쓰기 여유와 영구 장부가 확보되지 않으면 신규 호출을 허용하지 않는다. 보조 쓰기 9,000회 보호장치는 나머지 용도에 유지된다.
- 캐시 잠금 요청이 실패하면 읽기 가능한 마지막 관측을 사용한다. 캐시 publish 실패가 이 인스턴스의 정상 원문 수신 결과까지 버리지 않도록 한다. 아무 자료도 없으면 빈 정상 응답 대신 갱신 상태를 알린다.

## 검증

- 수집기 26개 테스트, 앱 50개 테스트 통과.
- 지도 10개 검증 통과: 역순환 독립 표시, 오래된 위치 제외, 선택 경로 필터 등.
- 보조 쓰기 상한 도달, 동시 claim, 잠금 소유자 충돌, 서버 재시작, 한국시간 자정, DB 오류, 전체 쓰기 보호를 재현했다.
- 가상 12시간·10개 노선 캐시 갱신 시험에서 캐시 관련 보조 쓰기는 0, 전체 추가 쓰기는 보수적 로컬 집계로 3,000행 미만이었다. 실제 계정 전체의 과금 수치가 아닌 테스트 어댑터 추정이다.
- 공개 `/api/shuttle`에서 10개 노선 모두 fresh/오류 없음 확인. 당시 행정관 19건, 순환 6건, 역순환 2건, 대학동 1건이 수신됐다. 운영사 노선도 위치이며, 모든 행정관 원문 레코드가 지리 지도에 매핑되는 것은 아니다. 빈 노선 6개도 성공적으로 조회된 빈 응답이다.
- PC 지도에서 행정관·순환·역순환·대학동 마커 표시, 모바일 역순환 노선도에서 차량 2대와 위치 변화 표시를 확인했다. 브라우저 콘솔 오류 0건.
- 기존 앱 데이터 75개 파일 SHA256 변경 0건. 별도 실험실 모델 승격 작업은 이 버그 수정과 분리된다.
