# 서울대정문·법대.사회대입구 v7 대기열 진단

2026-11-10. 실험실 에이전트 요청에 따른 읽기 전용 분석입니다. 원본 v7 alpha_075의 저장된 peak 월~금 audit만 사용했습니다. 시뮬레이터 import·새 시뮬레이션·모델 수정·배포는 모두 0건입니다.

## 정류소 구분과 최대 줄

아래 수치는 실제 고유 인원이나 관측 줄이 아닌 **가중 이동 사건의 명 상당량**입니다. 각 요일의 11:20~23:10 범위에서 처음 최대에 도달한 순간을 사용했습니다. 반대편 방향은 별도 노드이며 합산하지 않습니다. `서울대학교 21128`(node62)은 이 분석 대상에서 제외했습니다.

| 정류소 | 내부 노드 | 월 | 화 | 수 | 목 | 금 |
|---|---:|---:|---:|---:|---:|---:|
| 서울대정문 21269 | 46 | 0.103 | 0 | 0 | 0 | 0 |
| 법대.사회대입구 21270 | 47 | 2.569 | 1.627 | 2.934 | 1.595 | 1.107 |
| 법대.사회대입구 21298 | 60 | 127.034 | 130.917 | 112.348 | 123.133 | 45.670 |
| 서울대정문 21299 | 61 | 93.747 | 106.378 | 101.896 | 74.196 | 4.695 |

사용자의 약 40명 기준은 현장 실측 상한이 아닌 기억에 따른 가정입니다. 이 분석에서는 40명으로 잘라내거나 수요를 바꾸지 않았습니다. `seconds_over_40`는 그 가정과 비교하기 위한 기술 통계입니다.

## 확인된 대기 구조

### 1. 21299는 5511만 탈 수 있는 정류소

최대 줄의 탑승 자격도 5511 단일 노선입니다. 월요일 최대는 13:12:23.548의 93.747명 상당입니다. 그 전 5511은 다음과 같습니다.

| 시각 | 모형상 도착 차내량 | 하차 | 승차 | 호환 승객 중 남은 양 |
|---|---:|---:|---:|---:|
| 12:47:38.868 | 50 | 0 | 0 | 50.019 |
| 12:54:38.868 | 50 | 0 | 0 | 52.076 |
| 13:01:38.868 | 50 | 0 | 0 | 78.878 |
| 13:08:38.868 | 50 | 0 | 0 | 88.903 |

최대 줄에서 78.878명 상당은 현재 대기 에피소드 안에서 호환 차량의 만차 통과를 2회 이상 경험했고, 63.990명 상당은 경로 변경 2회를 이미 사용했습니다. 이들은 서로 겹치는 집단이므로 더하지 않습니다.

월요일 최대 줄 전량인 93.747명 상당은 앞서 5516을 탄 뒤 5511로 환승하려는 집단입니다. 월~목 최대 줄에서 직전 탑승 노선이 5516인 양은 각각 93.747, 100.823, 94.228, 71.615명 상당입니다. 21128에서 발견했던 초기 정문 도보 재배정 집단의 문제와 구분해야 합니다.

### 2. 21298은 다른 버스가 와도 현재 경로의 탑승 자격이 맞지 않을 수 있음

화요일 최대는 14:14:30.321의 130.917명 상당이며, 전량이 그 시점에 5511만 기다리고 있습니다. 5511은 14:03:51과 14:10:51에 모형상 차내량 50·하차 0·승차 0입니다. 반면 14:14:19.935의 5516은 49.963명 상당을 내려주고 0.580명 상당을 태웁니다. 이 버스에서 내린 사람까지 5511 대기에 합류합니다.

이 최대 줄 중 49.963명 상당은 아직 준비시간 20초 안에 있습니다. 준비 중인 사람도 공개 지도에 보이는 물리적 줄에는 포함하지만, 내부 탑승 준비 완료 줄에는 아직 포함하지 않습니다. 그 시점 두 줄의 차이를 실제 탑승 거부로 오해하면 안 됩니다.

화요일 최대 줄 130.917 중 직전 탑승 노선이 5516인 양은 125.990명 상당, 경로 변경 2회 소진량은 85.030명 상당입니다. 다른 노선이 정차했다는 것만으로 이들의 줄이 줄어드는 구조가 아닙니다.

### 3. 현재 후보 목록에 인근 시내 정류소로 걷는 대안이 없음

저장된 prepared 자료에서 네 노드의 모든 목적지 대안을 확인했습니다. 목적지까지 직접 도보와 현재 정류소에서 시작하는 다른 노선/경로 대안은 있지만, **다른 시내 정류소까지 걸어가 첫 차를 타는 대안은 없습니다.** 모든 대중교통 대안의 최초 접근 도보가 0초입니다.

이는 `prepare_city.py`의 대안 생성 방식과 일치합니다. 직접 목적지 도보를 넣은 뒤 `by_node_dest[node,dest]`에 등록된 동일 정류소 경로 suffix만 추가합니다.

### 4. 변경 2회 소진 뒤 직접 도보도 검토가 중단됨

기존 설정은 60초 재검토, 최소 이득 120초, 변경 후 유예 180초, 최대 변경 2회입니다. `city_capacity_model.py`의 `reschedule`과 `maybe_switch`는 이 횟수를 소진하면 직접 도보를 포함한 대안 검토를 종료합니다. 같은 장소에서 노선만 바꾸어도 history가 늘어나는 구조입니다.

최대 줄에서 횟수를 소진한 양:

| 노드 | 월 | 화 | 수 | 목 | 금 |
|---|---:|---:|---:|---:|---:|
| 21298 | 91.424 | 85.030 | 64.676 | 45.276 | 0 |
| 21299 | 63.990 | 62.806 | 71.615 | 48.666 | 0 |

사후 비교에서 21299의 월·목 최대 줄 전량은 그때 목적지까지 바로 걸었다면 실제 모형 완료보다 2분 이상 빨랐습니다. 화요일 103.722, 수요일 100.867명 상당도 해당합니다. 계산에는 기존 경로의 직접 도보시간과 개인별 보행 배율만 사용했습니다.

이 비교는 새 시뮬레이션이 아니라 이미 완료된 이동과의 사후 비교입니다. 당시에 미래를 알 수 있었다거나, 횟수 제한을 바꾸면 그 양이 전부 도보로 이탈한다는 인과 효과를 뜻하지 않습니다. 다만 탈출 대안이 더 나았던 상태와 그 검토를 막는 코드 조건이 공존함을 보여줍니다.

### 5. 미래 차량의 빈자리 전망은 확정 원인으로 집계할 수 없음

`first_boardable`은 현재 큐와 현재 탑승자만 사용하고 앞으로 상류 정류장에서 탈 수요는 포함하지 않습니다. 아직 비어 있는 미래 차량을 낙관적으로 볼 수 있는 구조입니다. 그러나 저장 audit에는 선택되지 않은 대안의 매 재검토 예측값이 없어, 실제로 어느 입자에서 이 낙관 때문에 걷지 않았는지 읽기 전용 기록만으로 정확히 분리할 수 없습니다. 새 후보 검증 시 별도 전망·결정 로그가 필요합니다.

## 새 후보 검증에 전달한 범위

사용자 전달 기준에 따라 같은 만차 노선을 뒤 정류장에서 다시 타는 회피와, 다른 노선 또는 셔틀로 이동하는 대안을 구분해야 합니다. 동일 장소 노선 변경과 실제 도보 이동도 구분하고, 횟수 소진 뒤 최종 직접 도보를 계속 검토하는 후보는 별도 검증해야 합니다. 이 분석에서는 그러한 수정이나 새 계산을 수행하지 않았습니다.

약 40명 기준과 기존 실측 3건은 성격을 구분해야 합니다. 전자는 가정이고, 기존 3건은 이미 보정에 사용된 관측이므로 독립 검증이 아닙니다. 전체 이동량·승하차 수지·노선 방향을 보존한 후보를 실험실에서 따로 평가해야 합니다.

## 검증·재현·자료

`python -X utf8 shuttle_analysis/stop_queue_audit_2026-11-10/analyze_saved_queues.py`

- 최댓값은 원시 대기 시작·종료 사건을 같은 시각에 합산한 뒤 계산했습니다. 구간은 `[arrival,end)`입니다.
- 대기 기록은 종료 때 분할 출력되므로 행 수나 UID 수를 인원으로 쓰지 않았습니다. 최종 분할 이동의 가중치를 합산해 각 최대 줄을 독립적으로 재구성했고 1e-5 이내 일치했습니다.
- 만차 통과 경험은 현재 대기 에피소드에서 자신의 노선·승차 순서와 호환되는 서비스를 대상으로 계산했습니다. 과거 대기까지의 누적 거부 횟수는 아닙니다.
- 각 차량의 `이전 차내량 - 하차 + 승차 = 이후 차내량`을 검증했습니다.
- prepared와 5요일 audit의 분석 전후 SHA-256이 일치했습니다. 원본 해시는 `analysis.json`에 있습니다.
- `peak_causes.csv`의 원인별 양은 중복 가능하므로 합계나 인과 기여율로 쓰면 안 됩니다.
- `weekday_peaks.csv`: 20개 요일·정류소 최댓값과 대기 통계.
- `peak_causes.csv`: 최대 시점의 만차 경험·횟수 소진·사후 도보 비교.
- `peak_vehicle_events.csv`: 최대 30분 전~10분 후 차량 승하차 기록.
- `existing_alternatives.csv`: 기존 정류소·목적지별 대안 목록.
- `analysis.json`: 최대 줄의 탑승 자격·목적지·출발 건물·직전 탑승 노선별 가중량과 한계.
