# 실측 운행 보강 개발 후보 R261116170142

이전 운행 후보 R261116162001의 별도 자식입니다. 이번 범위는 사용자가 선택한 **배차·차내시간·혼잡도·정문 비교 네 항목**입니다. 수요 생성·체류시간·정류장 선택·50회 자동 보정은 구현하지 않았습니다. 행동 후보 R261116161819와 공개 V11도 변경하지 않았습니다.

## 개선한 계산

| 항목 | 새 후보의 처리 |
|---|---|
| 배차·대기 | 같은 방향·정류장의 2개 날짜 자료를 시간대별로 좁혀 조회합니다. 과거에 확인된 최근 간격으로 속도를 제한적으로 보정합니다. 긴 공백으로 위상 근거가 사라지면 정확한 차를 꾸며 내는 대신 관측 분포로 돌아갑니다. |
| 차내시간 | 같은 차량·회차의 구간 통과시간을 사용합니다. 이미 주행을 끝냈고 그 사실을 조회 시각에 알 수 있었던 최근 구간만 반영합니다. 개발용 날짜에서 작은 공통 통과시간 편향을 보정했습니다. 정차시간은 중복 가산하지 않습니다. |
| 혼잡도 | 기대 등급과 실제로 표시·비교할 예측 등급을 구분합니다. 혼잡 누락과 오탐을 함께 제한하고, 최근 확인된 혼잡 차량을 새 근거 없이 곧바로 여유로 바꾸지 않는 보수적 규칙을 둡니다. |
| 정문 비교 | 21128에서 서울대입구역으로 이어지는 노선만 함께 분석합니다. 동일 시각 도착군을 보존하고 새 자료 분포와 이전 후보 분포를 혼합합니다. 각 노선 차내시간은 공통 예상 승차시각에 다시 계산합니다. |

신선한 실시간 도착정보·혼잡도·구간속도가 우선합니다. 도보 후 **승차 준비가 끝난 시각**으로 대기를 계산합니다. 추정에 서울시 원본 API를 추가 호출하지 않습니다.

정문 과거 분포가 이미 만차 표시 차량을 제외한 경우, 만차 위험을 다시 시간으로 더하지 않습니다. 기존 FIFO 모형의 줄 지연은 별도로 유지합니다. ‘만차 표시 아님’은 실제 여석이나 승차 보장의 뜻이 아닙니다.

## 자료 역할과 검증

- 과거 분포 학습: 2026-11-10, 11-11.
- 설정 선택: 이미 결과가 공개·탐색된 11-12. 이 날짜를 새 독립 검증으로 부르지 않습니다.
- 코드·자료·평가 규칙을 고정한 다음 신규 평가: 11-13.
- 11-14와 11-15 원본은 열지 않습니다. 주말에 평일 모형을 그대로 검증하지 않습니다.
- 주 비교 대상은 **이전 R261116162001**입니다. 같은 2일 자료를 기존 알고리즘에 넣은 대조와 기존 로컬 계산도 함께 비교합니다. 실제 배포 V11의 동적 입력까지 복제한 비교가 아닙니다.
- 모든 방법에서 표시 수치가 1.5 이상이면 ‘혼잡’으로 판정합니다. 실제 혼잡 정답은 등급 2·3입니다. 평균오차, 혼잡 누락률, 오탐률, 혼잡 표본 오차를 분리합니다.
- 차량·회차·구간과 반복 조회 시각은 서로 상관돼 있습니다. 표본 수를 독립 승객 수로 해석하지 않습니다.
- 정류장 통과 검출은 정차 표시·60m 근접·이전 갱신 120초 이내 조건입니다. 검출 누락과 시각 오차가 있어 실제 학생 대기시간 정답과 같지 않습니다. 정차 표시 없는 근접 기록과 수집 간격도 품질 자료에 남깁니다.
- 한 주 일부 평일의 자료만으로 요일 효과나 28일 정확도를 검증했다고 주장하지 않습니다. 운영 승격은 자동으로 하지 않습니다.

## 경로 계산 연결

`candidate_runtime.py`가 기존 Planner의 운행·주행·혼잡·정문 비교에 연결하는 어댑터입니다. `install_candidate`에는 모델 객체, 켤 구성요소, 같은 방향 노선망의 해시를 명시하며 반환된 `undo()`로 원복합니다. 최종 구성요소 판단은 `artifacts/final_component_policy.json`을 사용합니다. 이미 이전 R을 연결해 둔 검토용 Planner 위에 새 통과 항목을 연결하면, 꺼진 항목은 이전 연결을 유지합니다.

`recent_history.py`는 기존 스냅숏에서 확인되는 시내버스 통과·완료 주행을 메모리에 보관합니다. 차량·회차의 반복 정차 표시를 새 통과로 세지 않고, 미래 자료·늦게 수신돼 아직 알 수 없는 자료를 제외합니다. 메모리는 시간·행 수로 제한하며 새 저장소 쓰기나 외부 호출을 발생시키지 않습니다. 서버가 재시작하면 이 짧은 메모리는 사라지고 과거 분포로 돌아갑니다. 지속 보관되는 원천은 기존 수집 저장소입니다.

셔틀의 연속 운행 이력이 없는 한 실제 셔틀 배차·교통 지체를 실측 보정했다고 표시하지 않습니다. 셔틀 쪽은 기존 시간표·대기 모형을 유지하며, 이번에는 개선한 시내버스 쪽과 비교합니다. 혼잡 등급은 승객 수·여석으로 환산하지 않습니다.
