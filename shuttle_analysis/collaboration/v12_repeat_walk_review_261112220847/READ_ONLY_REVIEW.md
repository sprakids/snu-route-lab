# 반복 경로 변경 후 목적지 도보 확률 규칙의 정적 검토

2026-11-12. 후보 `261112220847`, 부모 `261112210916`. 검토 범위는 `repeat_patch.py`, 후보 `preferences.py`·`policy.py`의 확률식·참조 수수료·정규화 및 호출 연결입니다.

**현재 사용 중인 사건별 iid 선택 조건에서, 포화되지 않은 구간의 목적지 도보 그룹 확률은 요청한 식과 일치하도록 구현돼 있습니다.** 코드 읽기와 아래 수식 대조에서 새 차단 사유를 찾지 못했습니다. 실제 선택 함수·시험·패치·모델은 실행하지 않았고 실행 소스·입력도 수정하지 않았습니다. 새 날짜 관측이나 새 모형 실험도 수행하지 않았습니다. [소스·설정·AST·시작 영수증 대조](evidence.json)는 성능 승인과 구분합니다.

## 1. 무엇의 확률을 올리는가

`is_terminal_walk`는 `option`이 있고 `stages`가 빈 대안만 고릅니다. 현재 경로 자료의 의미로는 버스를 더 타지 않고 목적지까지 걷는 대안입니다. 다른 정류장에서 버스를 타는 `walk_transfer`는 단계가 남아 있으므로 이 그룹이 아닙니다. 이 분류는 경로 자료가 빈 단계의 끝점을 실제 목적지로 구성한다는 기존 계약을 전제로 합니다.

두 결정 지점에서 변경 **완료 횟수**를 전달합니다.

- 대기 중 재검토: `count=len(state['history'])`.
- 차량 도착 시 공동 승차/대기/도보 선택: 같은 `len(state['history'])`.

로그는 경로 변경을 기록하기 전의 횟수를 사용합니다. 재검토 횟수나 API 조회 횟수를 변경 횟수로 세는 코드가 아닙니다. 초기 출발 선택은 기본값 n=0을 사용합니다. 현재의 `joint_board_wait_walk_choice=True` 경로를 확인했으며, 사용하지 않는 legacy 선택 분기까지 같은 횟수 전달이 구현됐다고 확대하지 않습니다.

## 2. 참조 수수료 처리

실제 비용 함수의 변경 부담은 다음과 같습니다.

\[
C_{\rm change}=\beta_{\rm change}(1+0.5n).
\]

정류장을 바꾸는 대안과 목적지까지 걷는 대안에는 이 부담이 있고, 그대로 대기/즉시 승차하는 대안에는 없습니다. 호출자는 `reference_change_increment=0.5*β_change*n`을 전달합니다. 참조 확률을 계산할 때만 모든 `option!=None` 대안의 log utility에 이 증가분/temperature를 더합니다. 기본 변경 부담 `β_change`, 도보 거리·시간, 현재 대기 경험, 혼잡, 요금·선호는 그대로 둡니다.

즉 **n 때문에 추가된 변경 수수료만 참조값에서 중립화**합니다. 목적지 도보만 따로 할인한 참조가 아니며, 다른 정류장으로 가는 변경 대안도 같은 증가분을 중립화합니다. 실제 기록할 `candidate.cost`나 `Prediction`을 바꾸는 처리는 없습니다.

참조 확률은 현재 원래 확률과 다를 수 있습니다. 목적지 도보의 원래 질량을 W, 다른 변경 대안을 A, 그대로 대기/승차를 B, 중립화 배수를 k≥1로 두면:

\[
p_{\rm raw}=\frac{W}{W+A+B},\qquad
p_{\rm ref}=\frac{kW}{kW+kA+B}
=\frac{W}{W+A+B/k}\ge p_{\rm raw}.
\]

같은 후보·거리·기다림·선호 조건에서 n에 따른 비용 변화가 위 증가분뿐이라면, 이 중립화로 참조 확률이 고정됩니다. 실제 여러 경로 상황에서는 그 나머지 맥락도 달라지므로 참조 확률 자체가 달라질 수 있습니다.

## 3. softmax 정규화가 목표 그룹 확률을 만드는지

온도를 τ, 원래 비용을 C, 거리 등의 고려 가중치를 π라고 두면 코드의 결정론적 log utility는 다음입니다.

\[
u_i=-C_i/\tau+\log\pi_i.
\]

목적지 도보 그룹 T와 나머지 R의 질량을 각각 `Z_T=Σ_T exp(u_i)`, `Z_R=Σ_R exp(u_i)`로 둡니다. 코드는 참조 log odds로 아래 목표를 계산합니다.

\[
q_n=1-(1-p_{\rm ref})^{g^n},\qquad g=2.
\]

목적지 도보 대안 모두에 공통 shift δ를 더하면 그룹 확률은:

\[
P(T)=\frac{e^\delta Z_T}{e^\delta Z_T+Z_R}.
\]

따라서 필요한 shift는:

\[
\delta=\operatorname{logit}(q_n)-\log(Z_T/Z_R).
\]

`exponential_walk_shift`가 이 차이를 구하고, `choose`가 **온도로 이미 나눈 log utility에 그대로 더합니다.** shift를 비용 단위로 혼동해 온도를 다시 곱하거나 나누는 처리는 없습니다. 현재 호출에서는 참조 확률이 원래 확률보다 작지 않아 `max(0,shift)`가 목표를 역전시키지 않습니다.

정확한 키 중복 제거는 그룹 질량 계산 전에 수행합니다. 같은 후보를 같은 키로 여러 번 넣어 그룹 확률이 부풀지 않게 합니다. 다른 키를 가진 기하 중복까지 제거하는 증거는 아니며, 이는 기존 구분을 유지합니다.

동일 그룹 안의 상대확률은 그대로입니다. **다른 정류장으로 가는 도보를 증폭하지 않는다는 것은 그 절대확률도 그대로라는 뜻은 아닙니다.** 목적지 도보의 몫이 커지면 나머지 대안은 같은 비율로 정규화돼 줄어듭니다. 같은 n에서 새 shift를 적용하기 전후 R 내부의 상대비율은 유지됩니다. n 자체가 바뀌면 기존 변경 수수료 때문에 R 내부 비율도 달라질 수 있습니다.

예를 들어 같은 맥락의 참조 확률이 10%라면 목표는 n=0부터 약10%→19%→34.4%→57.0%→81.5%입니다. 이는 수식 설명용 예시이며 학생 관측치가 아닙니다. 기하급수적으로 증가하는 양을 정확히 쓰면 `−log(1−q_n)=2^n[−log(1−p_ref)]`입니다. 확률 자체를 계속 두 배로 만들어 1을 넘기는 규칙은 아닙니다.

## 4. n=0·수치 안정성·불가능한 대안

n=0에서는 `target=actual`, shift=0을 명시합니다. 두 호출의 참조 증가분도 0이며, 기존 난수 키와 비용·고려 가중치를 유지합니다. 목적지 도보의 하한 가지치기 생략도 n>0에만 작동하므로 n=0에서 선택을 바꾸려는 경로는 발견하지 못했습니다. 반환값에 진단이 추가되는 것과 선택 결과를 바꾸는 것은 구분합니다.

큰 n은 `2**n`을 직접 계산하지 않습니다. `h0=−log(1−p_ref)`를 log 공간에서 만들고 `log(h_n)=log(h0)+n log(g)`로 진행합니다. `softplus`, `expm1`, log-sum-exp를 사용해 매우 작은 참조 확률과 1에 가까운 확률을 처리합니다. log odds가 −36보다 작은 곳의 근사는 부동소수점 정밀도에서 작은 값에 대한 근사입니다.

수치 포화 상한은 `max(reference_log_odds, logit(1−ε))`, ε=10⁻¹²입니다. 원래 참조 확률이 이 상한보다 높으면 그 참조를 낮추지 않습니다. 포화가 걸린 구간은 이상적인 확률식을 무한정 정밀하게 계산한 값이 아니라 수치 관례이며 `numeric_saturation`에 표시합니다. 확률 진단이 float에서 1.0으로 반올림될 수 있어 log odds와 함께 읽는 편이 정확합니다.

목적지 도보가 없거나 가중치가 0이면 새 확률을 만들지 않습니다. 다른 가능한 그룹이 없으면 기존의 유일 그룹 확률을 유지합니다. ‘확률 상승’이 물리적으로 불가능한 경로를 새로 만들거나 특정 횟수에 강제로 걷게 하는 처리라는 뜻은 아닙니다.

## 5. 가지치기·비용 기록·재검토 시계

n>0의 목적지 도보에만 기존 비용 하한의 근사 가지치기를 생략합니다. 그렇지 않으면 새 확률 규칙을 적용하기 전에 먼 목적지 도보가 사라져 목표 그룹이 존재하지 않을 수 있습니다. 거리 비용과 거리 가중치는 실제 후보에 그대로 남아 있고, 다른 정류장으로 걷는 대안의 같은 가지치기는 유지됩니다.

기록 비용은 원래 값을 보존하고 실제 선택 utility에 별도 shift를 적용합니다. 따라서 원래 비용 순위만 보고 선택 전체를 설명하면 안 되며, 추가된 `terminal_walk_rule`의 원래/참조/목표 확률과 shift를 함께 읽어야 합니다. 기록된 ETA나 실제 이동시간에서 비용을 빼는 수정은 없습니다.

재검토 시계의 반복 승수0.3ⁿ, 무제한 변경, 기존 물리 경로·수요·공급은 유지합니다. 이미 많은 변경을 한 사람이 재검토하는 횟수 자체는 줄 수 있습니다. 이 규칙은 **해당 판단 기회가 실제로 발생했을 때**의 조건부 선택확률입니다.

## 6. 해석 범위와 남은 검증

위 softmax 도출은 현재의 `persistent_strategy_utility=False`와 사건별 iid Gumbel 선택이라는 전제입니다. 개인 계수의 이질성은 유지되지만, 이후 상관된 오차 모드로 바꾸면 같은 그룹 확률 도출을 그대로 주장할 수는 없습니다.

성장 배수2는 새 시나리오 가정이며 실측으로 추정한 값이 아닙니다. 실제 집단에서 n별 도보 비율이 단조 증가한다고 보장하지도 않습니다. 각 n의 장소·대기·후보·참조 확률·재검토 기회가 다르고, 일찍 도보로 나간 사람은 이후 위험집단에서 사라지기 때문입니다. `repeat_walk_choice_statistics`의 질량도 결정 기회 단위이며 고유 학생 수가 아닙니다.

추가 시험 정의는 읽었지만 실행하지 않았습니다. 시험의 12,000개 UID는 `range(12000)`으로 실제 선택 함수를 호출하는 **합성 UID 표본**이며 실제 서울대 학생 12,000명 자료가 아닙니다. 큰 n·중복·참조 수수료·n=0·두 결정 지점 등의 시험이 정의돼 있다는 것과 통과 결과·현장 정확도는 구분합니다.

이번 정적 검토를 실제 대기열 적합성이나 긴 여정 개선의 승인으로 해석하지 않습니다. 새 후보의 결과는 별도 모의 원장·분포와 비교해야 하며, 운영 V11과 앞 후보들은 보존합니다. 새 사용자 명시 승인 전 운영 활성 경로·기본값·`latest.json`을 전환하거나 배포하지 않습니다.
