# R7의 예측상 대기열 청산과 실제 승차 거절: 독립 읽기 검토

작성일: 2026-11-10, 한국시간. 검토 주체: 하교길 길찾기 앱 담당 에이전트.

## 범위와 결론

`prototype_validation_261110182218`의 `engine.py`, `policy.py`와 제공된 `thu_peak_long_wait_reconstruction.json`, `thu-failure-details.log`를 읽었다. 목요일 peak 실행 receipt 및 source_snapshot과 현재 두 소스의 해시도 대조했다. 런타임, 기존 산출물, 수요, 운영·수집기 파일은 수정하지 않았으며 새 실험이나 재실행도 하지 않았다. 아래 수치는 제공된 감사행을 읽어 산술 재계산한 값이며 실제 학생의 현장 관측이 아니다.

**판정:** ‘예측은 물리적으로 적격이면 앞사람이 승차한다고 간주하지만, 실제 승차에서는 자발적 거절이 가능하다’는 구조적 불일치는 확인된다. 다만 이 불일치가 UID 674864의 21분 대기를 일으킨 단독 원인이라고는 현재 감사만으로 확정할 수 없다. R8에서 실제 승차 자격과 예측상 승차 의향을 분리하는 방향은 타당한 검토 후보다. 미래 의사를 미리 읽거나 실제 승차 자격을 제한하는 수정이 되지 않도록 해야 한다.

## 1. 코드에서 확인한 구조적 불일치

1. `engine.py:243–260`의 `waiting_before`는 현재 단계의 모든 물리적 적격 `(rid, board)` pool을 기준으로 앞줄을 묶고 `cache.services`를 구성한다. 자발적 승차 거절 이력이나 예측상 의향은 key에 없다.
2. `engine.py:83–116`의 indexed 경로는 이 `cache.services`를 이용해 앞사람 질량을 `served`로 청산한다. `engine.py:120–144`의 목록 경로도 `stage_choice`가 있으면 앞사람이 그 차량에 탄다고 간주한다.
3. 실제 차량 사건은 `engine.py:481–489`에서 같은 물리적 적격 승객에게 `policy.accept_boarding`을 적용하고, 거절한 승객은 실제 줄에 남긴다.
4. `policy.py:187–203`의 현재 승차/계속 기다리기 선택과 거절 기록은 예측상의 앞줄 청산 로직에서 사용되지 않는다.

따라서 미래의 5513이 아직 기다리는 앞사람을 태워 다음 관악02-2의 줄을 줄여 줄 것이라고 예측하면서, 실제로는 그 사람들이 5513을 거절하고 남을 수 있다. 예측에서 이런 청산이 일어나는 경로 자체는 존재한다. 실제 FIFO와 용량 수지가 맞더라도 이 **예측과 행동의 불일치**는 별도로 남을 수 있다.

## 3. R8 설계 시 지켜야 할 경계

### 실제 자격과 예측 의향의 분리

물리적 pool, `stage_choice`, 실제 차량 정원, 실제 승차 허용, FIFO ticket·줄 순서, 가중 질량은 유지한다. 예측에서 특정 서비스가 앞줄을 줄일 것으로 기대하는 정도만 별도 상태로 둔다. 이를 해당 노선 이용 금지나 실제 승차 거절 강제로 바꾸면 안 된다.

자기 자신이 앞서 거절한 사실은 당시부터 사용할 수 있지만, focal 개인의 거절을 앞줄 전체의 의사로 확대해서는 안 된다. 다른 승객의 세부 traits·목적지·선택확률이 모두 여행자에게 보인다는 가정도 자동으로 허용되지 않는다. 관찰 가능 범위 밖 정보가 필요한 보정이라면 시뮬레이션 전용 가정으로 명시한다.

### 인과적 갱신

거절 사실을 기록할 때 `observed_at`, 정류장·방향·승차 순번, 같은 방문의 식별자, 근거 사건을 함께 둔다. 예측 시점까지 발생한 거절만 반영한다. 나중에 일어난 17:22의 거절을 17:12의 판단에 사용하면 안 된다.

미래 차량에 대해 `accept_boarding`을 미리 호출하거나 고정 난수·향후 개인 선택을 읽어 실제 거절 여부를 선취해서는 안 된다. 한 번의 거절을 영구적인 의향으로 바꾸는 것도 근거가 부족하다. 같은 방문에서 물리적 자격은 유지하며, 새 정보나 실제 행동에 따라 예측 의향이 바뀔 수 있어야 한다.

‘강한 열등’은 focal 승객의 현재 비용과 선택에 관한 것이다. 하나의 큰 비용 차이를 모두에게 공통된 열등 노선의 증거로 취급하지 않는다. 거절 뒤 예측상 청산을 0으로 두는 규칙은 보수적 시나리오로는 검토 가능하지만, 보정된 행동확률이나 정확한 미래 의사로 표시해서는 안 된다.

### 캐시와 두 예측 경로

현재 `group_cache` key는 실제 적격 pool이고 `queue_versions`는 이 사건에서 승차가 있을 때 증가한다(`engine.py:508`). 승차 0·거절만 있는 5513 705 사건에서는, 새로운 의향 상태를 추가해도 기존 캐시에 그대로 남을 수 있다.

예측상 의향이 바뀌면 별도 forecast-view version을 무효화하거나 그 정보를 예측 key에 포함해야 한다. 실제 FIFO용 `LiveMass`·positions와 예측상 의향을 혼합해 실제 수지를 바꾸지 않도록 한다. indexed/Fenwick 경로와 목록 fallback은 동일한 예측 의미를 가져야 한다. 같은 시각의 두 차량도 각각의 실제 승차 기회가 보존돼야 한다.

## 4. 후속 후보에서 필요한 근거

검토자는 아래 실행을 시작하지 않았다. 현재 동결 후보의 기존 결과도 수정하지 않는다.

- 예측마다 판단시각, owner·visit, physical/forecast cache version, 선택된 첫 차량, 예측 여석과 그 과거 근거, 앞줄 유형별 질량, 어떤 노선이 얼마를 가상 청산했는지 남긴다.
- 완료 후 실제 결과를 대조하되 예측 입력에는 미래 실제 여석·거절을 넣지 않는다.
- 여석이 있지만 앞사람이 과거에 해당 서비스를 거절한 사례, 거절 후 의향 변경, 다음 서비스 실제 만차, 거절 이력 없음, 서로 다른 목적지·의향이 같은 실제 pool에 있는 경우를 구분한다.
- 승차 0 사건 뒤 예측 캐시 갱신, indexed/fallback 일치, 실제 승차 가능·FIFO·질량·준비 20초·대기 시작시각 보존을 확인한다.
- 청산 가정 보정과 여석 예측 보정을 분리해 비교한다. 20분 기준을 넘지 않도록 수치만 조정하거나 관측되지 않은 대기를 잘라서는 안 된다.
