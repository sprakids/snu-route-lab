2026-11-15. 최종 검증 대상은 비운영 후보 `261115153406`, 직접 부모는 `261115151942`입니다.

**요청된 정문 대기 규칙,5개 서비스 pool,예측 설정과 비교 실험의 연결에서 추가 차단 사유를 찾지 못했습니다.** [evidence.json](evidence.json)에 동결·시작 기록을 남겼습니다. 범위 밖의 행동 정책·새 반례를 탐색하지 않았으며 모델·시험·프로젝트 함수를 실행하거나 source·설정·입력·운영을 수정하지 않았습니다.

## 1. 정문에서 다시 교내 경로를 선택하지 않음

`gate_is_final_fallback=True`,목적지snu,node62인 정식 대기에서는 alternatives가 stay만 남기고 maybe_switch/reschedule이 교내 대안으로 재출발하지 않습니다. END까지 남은 대기를 지우거나20분에 강제로 이탈시키는 코드가 아닙니다. 정류장을 떠나는 경우는 실제 호환 차량 승차 등 기존 물리 흐름입니다.

complete는 이 정문에 대해 기존 `compatible_route_policies['62|snu']`를 모아 pool을 구성합니다. frozen 입력의 node62는 서울대학교 정류장 ARS21128이며 호환 목록은 다음과 같습니다.

|노선|내부 board→alight index|후속 환승|
|---|---|---|
|5511|20→24|없음|
|5513|8→12|없음|
|5515|0→4|없음|
|5528|0→4|없음|
|6515|0→4|없음|

다섯 서비스는 같은 플랫폼 wait_path1783과 최종 next_walk1755를 공유합니다. 새로운 길이나 가상의 정류장을 추가하지 않습니다. 방문·목적지 필터는 유지하므로 이 표가 모든 상황에서 실제 빈자리나 승차 성공을 보장하지는 않습니다.

도중 승차의 임시 gate 접근에서는 engine이 일반 complete를 건너뜁니다. 기존 짧은 승차 창과 timeout 후 원래 보행 복원 경로는 engine의 부모와 동일한 코드에 남습니다. 정식 최종 대기와 임시 접근을 같은 흡수 상태로 바꾸는 수정은 아닙니다.

## 2. 과거 최소 여석을 미래 모든 차량에 고정하지 않는 본 실험

본 설정은 `learn_past_residual_seats=False`입니다. engine의 차량별 seat_history 참조를 비워, 최근 최소 여석이0이었다는 이유로 향후30분의 각 차량 여석을0으로 제한하던 주관적 proxy를 이번 본 실험에서는 쓰지 않습니다. 모델에서 현재 확인된 onboard·FIFO·이미 시작한 approach는 유지합니다.

이 onboard는 **모형 상태**이며 API로 관측한 숫자 재차인원이나 실제 여석이 아닙니다. 실제 정원·시간표·가중 승차·full_passes 기록은 그대로입니다. engine·capacity·operations가 부모와 같고 frozen 입력의 바이트도 같다는 범위를 evidence에 기록합니다.

## 3. 본 실험과 민감도 비교의 분리

등록된 전체 case는11개이며 본 실험10개와 월요일 진단1개입니다.

|비교|정문 최종 대기|learn_past_residual_seats|
|---|---|---|
|본 실험 월·화 및 이후10조건|True|False|
|월regular `ablation-gate-only-mon`|True|True|

월요일 본 실험과 진단의 실제 STARTED config를 전체 대조하면 차이는 위 여석 flag 하나입니다. 날짜·scenario·seed·operations와 런타임은 같습니다. run_case의 선언된 config_overrides가 실제 진단 STARTED에 반영돼 있습니다.

동일 후보 안의 본 실험 대 진단 비교는 정문 규칙을 고정한 채 과거 여석 proxy의 민감도를 봅니다. 이름이 gate-only라고 해서 본 실험과 비교할 때 gate 유무까지 함께 달라지는 것은 아닙니다. 부모151942와 진단을 비교하는 해석은 별도로 구분해야 합니다.

coordinator의 observations 선택은 ablation을 제외한 월·화regular2개,ablation 선택은 진단1개,grid 선택은 ablation을 제외한10개입니다. 두 그룹의 시작 표지도 분리돼 있고,실제 coordinator 파일 해시는 각각에 기록된 값과 같습니다. 아직 전체10조건을 실행·검증했다고 주장하지 않습니다.

## 4. 증거와 미확인 범위

런타임16개·평가 동결24개·frozen manifest·본 실험2개+진단1개의 STARTED/source_snapshot/lock/입력/설정을 대조했습니다. 소유 에이전트가 보고한 신규55개+legacy89개,총144개 시험 통과와 준비367집합7489끝점 검사는 독립 재실행과 구분합니다.

이것은 선언된 설정이 사용됐는지에 대한 정적 증거입니다. 새 결과를 보기 전에 고정했다는 순서는 보존된 선언과 STARTED 해시 연결을 근거로 하며, 검토자가 외부 시계로 재구성한 실행 이력은 아닙니다. 실제 대기 개선·재방문0·여정 시간·미완료·정원·FIFO·인원 수지는 담당 에이전트의 실행 원장으로 확인해야 합니다. 새 날짜 실측 정확도도 입증하지 않습니다.
