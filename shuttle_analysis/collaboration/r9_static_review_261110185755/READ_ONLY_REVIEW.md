## 확인한 변경

- `policy.py:58–60`: 설정이 켜진 미래 예측에서만 요청량을 `max(1., state['w'])`로 정하고 `indivisible=True`를 전달한다. 실제 `state['w']`에 값을 대입하지 않는다.
- `engine.py:83–100`: indexed 경로는 기존 여석 추정값에서 앞줄을 처리한 **뒤** 남은 양으로 요청량을 판정한다. `forecast_available`는 R7과 AST가 동일하며 pre-FIFO floor가 없다.
- `engine.py:120–144`: 목록 경로도 앞줄을 먼저 처리한다. 두 경로 모두 `indivisible=True`일 때 `need -= available`을 수행하지 않으므로 서로 다른 미래 차량의 소수 여석을 합치지 않는다. 기본값 False는 기존 fluid 예측 의미를 보존한다.
- `engine.simulate`, `forecast_available`, `stage_choice`, `scaled_stages`는 R7과 AST가 동일하다. 실제 부분 승차·정원·FIFO·ticket·가중 질량·준비시간·대기 시계 처리 분기에 직접 변경이 없다.
- 비교한 실행 소스 13개 중 바뀐 것은 `engine.py`, `policy.py` 두 개뿐이다. 나머지 11개는 바이트가 동일하다. `config.json` 차이는 `forecast_person_requires_whole_seat=True`와 그 해석 설명 두 항목이다.
- 동결 입력 디렉터리의 파일 집합과 17개 파일이 모두 R7과 바이트 단위로 일치한다. `input_manifest.json`, 정원44·피크2대 amendment 및 USER_DIRECTIVE도 동일하다.

## 유지해야 할 해석과 한계

1. **물리 규칙·입력 불변과 결과 불변은 다르다.** 예측이 달라져 선택이 바뀌면 실제 이동량 배분, 줄과 재차량 결과도 달라질 수 있다. 유지되는 것은 fluid 수요·수지 처리 규칙과 입력이며 전체 결과 숫자가 같다는 뜻이 아니다.
2. 이 설정은 선택 예측의 비분할 1인 보수 시나리오다. 현재 관측 차량의 승차 override(`policy.py:52–53`)와 실제 부분 승차는 여전히 fluid 처리로 남는다. 물리 시뮬레이션 전체를 실제 개인 단위로 전환했다고 설명하면 안 된다.
3. 과거 잔여량 추정이 1 이상이어도 미래 실제 여석이 보장되지는 않는다. 미래 실제 여석·개인 선택을 읽지 않는 기존 정보 경계와 예측 오차 표기는 유지해야 한다.
4. `policy.py:197`의 ‘현재/후속 예측이 None이면 현재 승차 허용’과 기존 두 단계 승차 선택은 바뀌지 않았다. R9의 보수 예측으로 후속 None이 늘면 이 기존 fallback의 이용 빈도가 바뀔 수 있다. 이는 새로 숨겨진 코드 변경은 아니지만 이전 리뷰에서 남긴 도보 대안 비교 한계가 해결된 것은 아니다.
5. 고정 actual/perceived 공급 시계 공유 및 일반적인 앞줄 청산/자발적 거절 불일치도 이번 변경의 해결 범위가 아니다. 내부 20분 기준과 실측 정확도는 계속 구분한다.

추가 테스트 소스에는 소수 packet·FIFO 뒤 1인 잔여·여러 차량 소수 여석 누적 금지, indexed/fallback 사례가 추가돼 있다. 검토자는 이를 읽었으며, 보고된 30개 PASS를 독립 재실행하지 않았다. 운영 V11 `261110162302` 유지와 새 사용자 명시 승인 전 교체 금지는 그대로다.
