## 3. FIFO·서비스별 정원 차감

기존 큐는 `waiting_before`의 `QueueView`를 사용합니다. 이미 자신의 순번을 가진 승객은 기존 앞사람까지만 보고, `retained_queued=True`일 때 새 접근은 추가하지 않습니다. 뒤늦게 들어올 승객이 기존 순번을 추월하지 않습니다.

아직 줄에 들어가지 않은 질의자는 준비완료가 자신보다 빠른 현재 접근만 포함합니다. 이 목록은 `(ready,serial)`로 정렬됩니다. `timed_boardable`은 차량 사건 순서대로 다음을 처리합니다.

1. 알려진 차내 잔류를 정원에서 빼고 기존 과거 여석 제약을 적용합니다.
2. 현재 줄에서 해당 차량을 탈 수 있는 앞사람부터 처리합니다.
3. 준비가 그 차량 시각까지 끝난 접근 중 해당 노선을 탈 수 있는 사람을 처리합니다.
4. 본인 준비완료·서비스 자격·남은 정원을 확인해 승차 가능 차량을 정합니다.

모든 차감은 질의의 지역 `served`·`ahead`·`future`에 남습니다. 실차 객체의 차내 인원이나 등록된 접근 질량을 예측 과정에서 줄이는 코드는 없습니다. 본인 질의가 indivisible일 때 이전 차량의 자투리 여석을 여러 차량에 걸쳐 모아 한 명의 탑승으로 만들지 않는 기존 처리도 유지합니다.

부하 projection의 `before`는 같은 차량의 큐/접근 처리 직전 여석이고, 처리 후 `available`을 같은 함수에 넘깁니다. 따라서 알려진 진입 부하 `O+(before-available)+w`에는 이 차량에 예상 승차한 기존 큐와 접근이 함께 들어갑니다. 과거 여석으로 가정한 예약량은 기존 B 방식대로 별도 진단에 남습니다. `committed_candidate_mass`는 해당 질의에서 고려한 접근 후보 전체의 질량이지, 이 차량의 승차 인원이나 실측 줄 길이가 아닙니다.
