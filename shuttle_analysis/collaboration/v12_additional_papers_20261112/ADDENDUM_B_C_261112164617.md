## 1. B: 보수적 예약 용량과 알려진 부하의 분리

`engine.py`의 `boarding_projection`은 현재 알려진 하차 후 잔류 `O`, 선행 큐를 처리하기 전 여석 `a0`, 처리 후 여석 `a1`, 본인 질의량 `w`를 구분합니다.

\[
L_{\rm known}=O+(a_0-a_1)+w,\qquad
R=C-O-a_0,\qquad
L_{\rm upper}=L_{\rm known}+R.
\]

`projected_after_self`에는 알려진 부하만, `quota_implied_load_upper_proxy`에는 예약량을 포함한 부하가 들어갑니다. 두 값은 정원 검산을 거치고 `is_observed_occupancy=False`로 기록됩니다. 고속 `QueueView`와 일반 리스트 분기 모두 **선택된 차량에서 실제로 차감한 선행 큐**의 여석을 전달합니다. 앞선 다른 차량이 처리한 승객을 선택 차량에 또 더하지 않습니다.

독립적인 작은 예시에서 다음을 확인했습니다. 모두 모의 산술이며 실제 차량 재차인원은 아닙니다.

|조건|확인한 결과|
|---|---|
|44석, 앞 40명분, 본인 1|첫 차량의 진입 부하 41|
|44석, 앞 43명분, 본인 1|첫 차량의 진입 부하 44|
|같은 시각 44석 두 대, 앞 44명분, 본인 1|둘째 차량의 진입 부하 1|

현재 승차 기회의 `override` 분기는 이미 `onboard`에 올라간 선행 승객을 사용하므로 큐를 다시 더하지 않습니다. `policy.predict`는 fallback 혼잡 비용에서 알려진 부하인 `projected_after_self`를 사용하며, 실측 등급 기반 시간 프로필의 `exposure`가 있으면 기존 자료 기반 비용을 유지합니다.

선택 시각·차량·정류장 등의 기존 4항 반환은 optional projection을 켜도 같았습니다. 혼합된 A/B 노선 자격·가중 대기열·과거 여석 가정을 가진 가상 입력 150개에서 리스트/고속 분기의 결과가 일치했고, 입력 차량·큐도 바뀌지 않았습니다. 이것은 이번 projection 연결에 대한 검사이며 전체 FIFO 엔진을 새로 검증했다는 뜻은 아닙니다.

**해석상 남는 제한:** 이 부하는 미래 도착자·내 뒤의 추가 탑승·전체 구간 승하차를 모두 반영한 출발 재차인원이 아닙니다. 최소 한 명을 질의하는 설정에서는 `w=max(1,state.w)`이므로, 실제 합성 조각의 가중 질량과 질의량도 구분해야 합니다. 현재 `override` 진단에는 미래 projection과 동일한 세부 필드가 모두 있지는 않으므로 후속 분석은 `basis`별로 읽어야 합니다. 이는 이번 점검에서 확인한 구현 차단 사유는 아닙니다.

## 2. C: 원본 보행 배율은 정확히 한 번 적용되는 구조

`prepare.py:15–46`은 먼저 4.8km/h·경사·계단에 따른 **기준 경로 시간**으로 기존 시간을 바꾼 뒤, 부모의 동결 배율을 초기 접근과 계획 내 모든 `next_walk`에 한 번 적용합니다. `scaled_stages`는 묶음 노선과 이어지는 단계까지 새 구조로 복사합니다. 이후 합성 조각으로 나눌 때 각 조각의 `walk_scales`에 같은 부모 배율을 전달합니다.

연결을 다음과 같이 추적했습니다.

|경로의 종류|배율을 적용하는 지점|중복을 피하는 지점|
|---|---|---|
|원래 선택한 첫 접근·이후 보행|입력 준비 중 기준 시간×부모 배율|`walk_next`는 전달받은 초를 그대로 사용|
|기존 계획을 계속 이용하는 예측|이미 배율이 적용된 단계 사용|`predict`의 기본 `factor=1`|
|새로운 정류장으로 걷는 대안|공유 대안은 기준 시간 유지. 대안 평가에서 개인 배율 적용|실제 전환 때 새 단계와 접근에 각각 한 번 적용|
|같은 정류장의 새 호환 노선|공유 노선 풀은 기준 시간 유지. 새 항목에 개인 배율 적용|기존 단계·기존 풀을 다시 배율화하지 않음|
|자유 출발 대조군의 초기 후보|준비 단계에서 사람 배율을 나누어 공통 후보를 기준 시간으로 복원|선택 평가와 실제 저장에서 선택한 사람의 배율을 한 번 적용|

초기 배분 보존과 자유 출발 두 분기 모두를 모의 `prepare`로 확인했습니다. 부모 2개·질량 4를 합성 조각 5개로 나눈 예시에서 부모 배율·질량이 보존됐고, 초기 접근·계획 단계·공유 대안·공유 호환 노선·자유 출발 후보 정규화가 기대한 시간을 만들었습니다. 자유 출발의 `initial_choice`도 별도로 분리해, 평가하는 시간과 실제 저장하는 시간이 각 개인의 배율을 한 번만 사용하는지 확인했습니다. 실제 부모 자료 전체를 다시 준비하거나 전체 시뮬레이션을 돌린 검사는 아닙니다.

기존 `test_walking_variation.py`는 직접 배율을 넣은 입력과 예측을 점검하므로, 그 시험만으로 `prepare` 연결이 확인되지는 않습니다. 이번 모의 읽기 검사는 이 빈 부분을 보완합니다. 실제 전체 실행의 보행 원장 감사는 여전히 담당자가 완료해야 합니다.

`analyze_followup.py:110–129`에서는 결과에 적힌 배율을 그대로 믿는 대신, 합성 ID→부모 ID 관계를 확인하고 **동결 원본의 부모 배율×기준 경로 시간**으로 각 보행 구간을 재구성합니다. 감사 방향도 수정 취지와 일치합니다.
