## 1. 점수 단위와 계산 의미

`behavioral_policy.py:26-37`, `216-234`, `252`를 대조했습니다. 모든 항목은 초 단위이며 선택기에 넣을 때 한 번 분으로 바꿉니다.

\[
R=\frac{\sum_i h_i^2}{2\sum_i h_i},\qquad
D=\max\{0, W_{\rm first}-P-\phi\},\qquad
S=A+P+R+D.
\]

균등한 시점에 도착한다고 보면 길이가 \(h\)인 배차 구간의 대기시간 면적은 삼각형의 넓이 \(h^2/2\)입니다. 그 면적 합을 전체 구간 길이 \(\sum h\)로 나누므로 위 \(R\)이 됩니다. 정규 배차이면 배차간격의 절반으로 줄어듭니다. 이는 개인의 실제 대기를 단정하는 식이 아니라 빈 대기열의 기본 기댓값입니다.

- \(h_i\): 같은 정류장의 호환 서비스 도착시각 사이의 양수 간격, 초.
- \(R\): 빈 대기열에서 출발 위상을 모른다는 가정의 배차간격 기반 잔여 대기, 초.
- \(A\): 개인별 기존 보행 계수를 적용한 접근시간, 초.
- \(P\): 준비시간, 초.
- \(\phi\): 준비 완료 뒤 첫 호환 차량까지의 정확한 기본 대기, 초.
- \(W_{\rm first}\): 기존 예측기의 첫 승차까지 대기. 새 경로 예측에서는 준비시간도 포함합니다.
- \(D\): 첫 호환 차량 대신 뒤 차량을 타게 되는 기존 FIFO·정원 지연을 남기는 항목입니다.

`policy.py:80-111`에서 첫 경로의 준비 완료 시각과 `first_wait` 의미가 연결됩니다. `sum(h²)/sum(h)`의 단위는 초이며, `S/60`이 분 단위 선택 비용에 들어갑니다. 준비시간이나 접근시간을 다시 분으로 나누어 넣는 오류는 보이지 않습니다.

소스에 있는 단위 검사 예시도 손으로 대조하면 `100 + 20 + 300 + (700 - 20 - 80) = 1020초 = 17분`입니다. 시험 함수를 실행한 것은 아닙니다.

이 점수는 **첫 승차까지의 시간**을 평가합니다. 최초 후보의 차내시간·전체 환승시간을 점수에 더해 최소 총 귀가시간을 직접 고르는 구조는 아닙니다. 실제 화면 ETA나 물리 운행 시각을 이 기댓값으로 바꾸지도 않습니다.

선택기의 `choice_temperature_minutes=2`는 분 단위 Gumbel 선택 오차의 척도입니다. 개인별 오차가 항상 ±2분 안에 있다는 의미는 아닙니다. 거리 prior는 보행 거리(미터)로 계산되어 시간 점수와 별도의 로그 확률 항에 들어갑니다.

## 3. 물리 정류장 중복 확률 억제

기댓값 기반 확률 선택 분기에서 `bystop[node_for(chain[0])]`에 대표 후보 하나만 남깁니다. 이후 선택기에 들어가는 key도 노드당 하나입니다. 따라서 같은 정류장으로 가는 동일 후보나 경로 꼬리를 여러 번 나열했다고 그 정류장이 여러 개의 독립 선택 오차를 받지는 않습니다.

같은 노드 안에서는 점수·접근시간·ETA·키 순으로 가장 좋은 후보를 대표로 삼습니다. 서로 다른 실제 서비스 집합이 더 좋은 승차 기회를 제공해 대표 점수가 달라지는 효과는 남으며, 이것은 단순히 후보 복사 개수에 확률을 더하는 것과 구분해야 합니다. 정류장 identity는 엔진의 `node_for`가 사용하는 물리 대기 노드이며, 이름이나 좌표 반올림으로 묶지 않습니다.

서비스 도착시각은 `sorted({when ...})`로 같은 순간을 하나의 기본 도착 기회로 묶습니다. 이는 기본 잔여 대기의 간격 표본을 만들 때의 처리입니다. 같은 순간에 오는 여러 차량의 실제 정원·FIFO 처리를 합치거나 삭제하는 변경은 아닙니다. 그 영향은 기존 `policy.predict`의 정원 지연에 남습니다.
