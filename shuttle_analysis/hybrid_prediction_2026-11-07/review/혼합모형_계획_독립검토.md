## 2. H에 포함된 평균을 다시 더하는 문제

H에는 이미 수업 학생·비수업 학생·교직원·통과 승객의 평균이 섞여 있습니다. 수업 특징은 해당 target link-hour의 학습 자료에서 실제 유효한 날짜 요일 빈도로 중심화해야 합니다.

\[
\bar C_{l,h}=\frac{\sum_{d\in D_{train,l,h}} C_{w(d),l,h}}{|D_{train,l,h}|},\quad
X^C_{d,l,h}=C_{w(d),l,h}-\bar C_{l,h}.
\]

현재 특징과 lag 특징을 각각 만든 뒤 target 시간 h의 같은 학습 유효 마스크에서 따로 중심화합니다. 전체 학습 날짜의 균등 요일 빈도를 무조건 쓰면 특정 구간의 결측 때문에 실제 학습 셀 평균이 0이 아닐 수 있습니다. 15일이 월~금 각3일이라는 사실만으로 구간별 관측도 균등하다고 가정하지 않습니다.

배경 비율 R은 outside-bbox의 같은 route-weekday-hour 자료만으로 학습하고, 분모의 route-hour pooled mean 역시 학습에서만 계산해야 합니다. 대상 날짜의 outside 관측을 쓰면 당일 관측을 입력으로 쓰는 다른 예측 문제가 됩니다. 명시한 계획에서는 이를 금지합니다.

`B=H*(R-1)`의 학습 평균이 항상 0인 것은 아닙니다. outside 비율의 가중치와 target link-hour의 유효 날짜 가중치가 다르면 1을 뺀 것만으로 중심화되지 않습니다. 완전하고 균형 잡힌 경우에는 확인 가능하지만, 그렇지 않으면 학습 마스크에 따른 B 평균을 실제로 기록해야 합니다. 잔차 특징을 0평균으로 설계하려면 그 동일 마스크에서 B를 중심화하는 정의까지 사전에 명시해야 합니다. 정의를 그대로 유지한다면 비중 차이로 생기는 평균 편차를 숨기지 않습니다.

비율 분모가 0/미관측인 route-hour의 처리도 test 전에 고정해야 합니다. 임의 epsilon으로 큰 비율을 만들거나 대상 날짜의 값으로 채우지 않습니다. 관측 근거가 없으면 비율1(대리 편차0) 등의 사전 규칙과 해당 셀 수를 명시하는 방법이 있습니다. H 자체에 학습 관측이 없는 경우의 예측 규칙도 필요합니다.

중심화가 성공해도 통계적 평균 중복을 줄이는 것이지 실제 사람 집단을 분해하는 것은 아닙니다. 순환 버스는 bbox 밖에서도 서울대 학생을 태우고, 재차합 비율에는 운행횟수 차이도 반영될 수 있습니다. a,b,c는 예측 잔차의 계수이며 비학생 비율·귀가율·수업의 인과 효과가 아닙니다.

## 3. 한 시간 lag와 평가 시간 범위

- 12시 예측의 lag1은 보존된 11시 수업 구간 특징을 사용합니다. 먼저12~22시만 남기고 행 shift를 하면 12시 lag를 잃거나 서로 다른 노선/구간을 연결할 수 있습니다.
- `(원래 요일, day_offset, hour, route, staSn, from,to)`를 보존해 실제 도착 요일·시간으로 바인딩한 뒤, 같은 구간의 시간축에서 lag를 정의합니다. 데이터 행 순서를 한 칸 미는 방식은 금지합니다.
- 이번 target 시간12~22시의 lag 원천은11~21시라 자정은 직접 필요하지 않지만, 일반 구현의 hour0은 이전 날짜23시를 뜻합니다. 원자료에 없다는 사실과 모형 기여0을 구분합니다.
- lag 후 target h의 유효 학습 날짜로 중심화합니다. h-1의 관측 결측 마스크로 중심화하면 h의 학습 평균0이 보장되지 않습니다.
- 보존된 모형 통과량의 lag는 통계적 시간 보정 특징입니다. 실제 학생이 정확히1시간 더 머무르거나 막차·경로를 바꾸는 정책 시나리오로 해석하지 않습니다. 그런 이동 행태 변경은 원래 보행·대기·경로 선택부터 다시 모형화해야 합니다.
- 12~22시의 완전한 시간 구간만 평가한다는 규칙을 유지하고, 11시나23시의 부분 수집 창을 완전한 1시간 관측과 섞지 않습니다.

## 4. Ridge·제약·클리핑의 계산 정의

원 단위 특징 행렬 X와 계수 β=(a,b,c), 잔차 r=Y-H라 하겠습니다. 응답을 별도로 표준화하지 않는다면, 학습 RMS s_j=sqrt(mean_train(X_j²))와 Z_j=X_j/s_j, γ_j=β_j*s_j를 쓰는 표준화 ridge는 다음과 같습니다.

\[
\min_{\gamma}\ \frac{1}{n}\|r-Z\gamma\|^2
+\lambda_B\gamma_B^2+\lambda_C(\gamma_C^2+\gamma_{lag}^2).
\]

이 정의에서 원래 계수 a∈[0,1]의 표준화 경계는 γ_B∈[0,s_B]입니다. s_B=10인데 표준화 계수도[0,1]로 제한하면 원래 a의 상한을0.1로 바꾼 셈입니다. 응답도 s_Y로 나누면 경계는 s_B/s_Y에 맞게 달라집니다. 계획의 bounds가 원 단위 계수인지 표준화 계수인지 코드에 명시해야 합니다.

`ridge를 feature mean square로 정규화`한다는 표현만으로는 곱셈/나눗셈과 표본 수 배율이 불분명합니다. 위 식을 원 단위로 쓰면 ridge 항은 λ_j*s_j²*β_j²입니다. 평균 손실 대신 SSE를 쓰면 동일한 λ 의미를 유지하려면 ridge 항에 n을 곱해야 합니다. train15일에서 train+tune20일로 재적합할 때도 이 정의가 유지돼야 합니다. 모든 척도는 해당 fit의 개발 자료에서만 계산합니다. s_j=0인 열은 제외하거나 계수를0으로 고정합니다.

active-set quadratic 해법은 **클리핑 전 선형 잔차의 제곱손실+ridge**를 최소화하는 경우에 적합합니다. `Yhat=max(0,H+Xβ)`는 그 후 고정된 출력 규칙으로 적용할 수 있습니다. clipped prediction의 손실 자체를 적합한다고 주장하면 같은 QP를 푼 것이 아닙니다. 그 경우에는 다른 목적함수·해법이 필요합니다.

각 노선에서 해의 경계와 KKT 잔차를 기록하는 것이 좋습니다. 내부 자유계수의 기울기는0, 하한0에서는 기울기≥0, 상한에서는 기울기≤0인지 확인합니다. 테스트 오차가 아니라 수학적 최적화의 검산입니다.

클리핑 전 중심화된 조정의 학습 평균이0이어도 최종 예측 평균은 달라질 수 있습니다. 예를 들어 원 예측[-5,25]의 평균은10이지만 clip 후[0,25]의 평균은12.5입니다. 음수 예측 비율과 클리핑으로 바뀐 예측 합도 공개하고, 중심화만으로 최종 총량 보존을 주장하지 않습니다.

## 5. 튜닝·재적합·test 접근의 고정 절차

계획의 2개 lambda가 모든 노선에 공통인지 노선마다 따로 고르는지 명시해야 합니다. pooled tuning WAPE로 선택한다면 공통 lambda 쌍이라는 해석이 자연스럽지만, 노선별16개 후보 선택과는 복잡도가 다릅니다. 다음을 test 접근 전에 고정해야 합니다.

1. 각 ablation과 결합형의 후보 집합, weekday shrink benchmark의 k, 결합형과 benchmark를 각각 선택한다는 단위.
2. 유효 관측 셀 마스크 및 모든 후보의 예측 완결성. 후보별 예측 결측을 임의로 제외해 낮은 WAPE를 얻지 않습니다. 실제 관측 null은 모든 후보에서 동일하게 제외하고, 모형0·관측양수 셀은 유지합니다.
3. 정확한 동률 판단 허용오차와 완전한 후보 순서. `더 강한 정규화`에서 두 lambda가 서로 반대 방향일 때의 우선순위까지 정해야 합니다. 조합형만의 hyperparameter 선택과 ablation 간 승자 선택을 섞지 않습니다.
4. 선택 후 train+tune로 H, 외부 비율, 중심화, RMS, 계수, weekday benchmark를 다시 적합하는 범위. 선택한 설정은 그대로 두며 이 시점에서 test 정보는 사용하지 않습니다.
5. test 관측을 읽기 전에 모든 비교 대상(선택한 결합형·benchmark·ablation)의 6일 예측 격자를 저장합니다. 개발 시점의 정류장/순서·날짜·12~22시의 고정 격자로 만들고 test 관측을 보고 링크나 시간을 고르지 않습니다.
6. selection_frozen.json에 계획·모델 코드·입력 특징·개발 자료·전처리 통계·선택·계수·모든 예측 파일의 해시를 포함합니다. test loader는 이를 확인하고 그 이후에만 처음 test 값을 읽도록 합니다. 테스트 평가 후 같은 파일을 수정·선택하지 않습니다.

기존 test를 개발로 분류한 사실은 숨기지 않아야 합니다. 새로운 6일은 과거 10일과 구분되지만, 이번 계획을 만든 이유 자체가 이전 실패에서 왔다는 것은 정상적인 개발 과정입니다. 독립 test 값에 다시 맞추지 않는 것이 핵심입니다.

## 6. 식별·중복·성과 해석

수업 특징과 lag, 외부 요일 비율은 모두 요일 패턴을 공유하므로 상관될 수 있습니다. ridge가 수치적으로 해를 안정시켜도 학생/배경 계수를 인과적으로 식별하지는 않습니다. 계수의0도 정보가 되는 결과이며 양수나 오차 개선을 강요하지 않습니다.

weekday 역사 benchmark는 반드시 함께 공개해야 합니다. 결합형이 H보다 좋아져도 단순한 요일 효과를 추가한 결과인지, 수업 특징이 더 나은 예측에 기여했는지는 class를 뺀 모형과 weekday benchmark가 있어야 평가할 수 있습니다. ablation 차이는 예측 비교이며 수업 인원의 인과 효과가 아닙니다.

정류장 구간·시간 셀은 같은 날짜·노선 안에서 서로 연관돼 있습니다. 전방 평가 월요일1일의 수천 셀을 수천 개 독립적인 미래 날짜처럼 보지 않습니다. forward1일과 retrospective5일을 각각 보고하고, 날짜·노선별 지표와 관측 합·유효 셀 수를 함께 보존합니다. pooled WAPE는 교통량이 큰 구간·노선의 영향이 크므로 모든 노선이나 윗공대의 개선을 자동으로 뜻하지 않습니다.

주 범위는 공식 캠퍼스 경계가 아닌 출발 정류장 bbox의125구간입니다. 해당 범위 전체의 성능을 윗공대 학생이나 정류장 대기열 성능으로 바꾸어 부르지 않습니다. 평균·운행횟수·차량 정원·셔틀 줄 관측이 없는 한 차량 혼잡률·탑승 실패 검증이 새로 완료되는 것도 아닙니다.

날짜 산술·집합과 계획 문구를 대조했습니다. 모델 코드·실제 학습·튜닝 선택·freeze 파일·test 접근 차단·최종 오차는 아직 이 검토의 확인 범위가 아닙니다. 코드가 준비되면 위 조건과 해당 코드 버전을 짧게 대조할 수 있습니다. 평가 결과를 보며 모형·범위·규칙을 바꾸자는 제안은 하지 않습니다.

## 고정 코드와 예측에 대한 후속 검토

계획 검토 이후 제공된 common.py와 train_and_freeze.py를 읽고 수학 예제를 실행했습니다. 실제 test 관측값을 읽기 전에 frozen_code_review_checks.json을 저장했습니다. 원 모델·계수·범위·선택은 바꾸지 않았습니다.

- 목적함수는 원 단위 X에서 `X'X/n + diag(lambda*mean(X²))`를 쓰는 클리핑 전 선형 MSE+ridge입니다. 계수의 원 단위 경계가 유지돼 표준화 후 경계를 잘못 적용하는 문제는 없습니다. 직교 특징의 내부/상·하한 해, 비활성 성분, 상관열의 ridge 해, 모두0인 열의 최소노름0을 독립 수학 예제와 대조했습니다.
- 11시를 포함한 전체 모형 template에서 lag를 만든 뒤 target12~22시와 결합합니다. 합성 예제에서12시 lag가11시 값을 사용하는 것을 확인했습니다. 실제 보존 특징의 day_offset0 assertion이 있어 다른 시점 이동을 조용히 무시하지 않습니다.
- C0/C1은 실제 유효 target 학습 행의 평균으로 계산합니다. 고정된 최종 모형의125구간에서 current/lag 평균 편차는 각각 최대6.82e-14, 배경 대리지표의 평균 편차도 최대4.98e-14였습니다. 이번 자료에서는 중심화/비율 구조가 평균 수준에서 잘 맞습니다. 일반적인 결측 불균형에서 R-1이 0평균을 보장하지 않는다는 합성 반례도 확인했지만 이를 이번 모형의 오류로 해석하지 않습니다.
- 모든 계수는 학습 또는 선택 후 train+tune에서만 적합합니다. 미래 예측 격자를 만드는 grid는 날짜·정류장·보존 수업 특징만 읽고 해당 날짜의 관측값을 읽지 않습니다. 학습 시작 전에 test 날짜의 collected 경로를 막는 audit hook이 설치됩니다. 이 코드 경로를 확인한 것이며, 임의의 과거 외부 열람까지 증명한 것은 아닙니다.
- selection_frozen.json의 모델·예측·계획·학습 코드 해시가 현재 고정 파일과 일치합니다. 다섯 비교 모형의 예측이6일×259구간×11시간=17,094행 전체에 완성됐고 비음수·유한값입니다. 실제 관측값과 결합하기 전의 예측 파일만 확인했습니다.
- 각 family의 튜닝 선택은 `WAPE 최소 → lambda 합이 큰 것 → k가 큰 것 → 생성 순서`로 재현됩니다. family 사이에서 승자를 골라 다른 family를 버리지 않습니다. 같은 family 안에서는 구조 성분 수가 같으므로 계획의 'fewer components'는 별도 선택 단계가 아닙니다. 정확한 동률과 lambda합 기준이라는 실제 규칙을 문서화하되 test 후 규칙을 바꾸지 않아야 합니다. 모든 후보의 유효 관측 수와 합은 같았습니다.
- 원 freeze receipt에 common.py의 해시는 없었습니다. 그 대신 이번 검토 시점의 해시 `5fbbfed8eee0bbc20451b26dd5687d1e552e2a33c4e83e23aeb4b69a8044f2c9`를 보조 검토 기록에 남겼습니다. 이를 원래 freeze 이전에 고정된 의존성 해시라고 소급해서 부르지 않습니다. 고정 예측 자체의 해시는 원 receipt에 있습니다.

후속 코드 검토는 통과했지만 test 성능·운영상 시점 일치·차량 혼잡률 검증을 뜻하지 않습니다. 이후 수행하는 지표 산술 대조는 별도 파일에 기록합니다.
