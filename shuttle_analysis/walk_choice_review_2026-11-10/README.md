# 새 도보 선택 후보의 읽기 전용 코드 검토

2026-11-10. 실험실 에이전트가 소유한 후보 코드를 수정하거나 실행하지 않고 검토했습니다. 검토 시점 원문 두 개를 `snapshot-*.py`로 보존했고 SHA-256은 `reviewed-source-manifest.json`에 있습니다. 이후 에이전트가 수정하는 최신 코드에 그대로 적용되는 판정은 아닙니다.

## 우선 확인할 문제

1. **같은 노선 뒤 정류장의 8% 고려 필터가 도착 후 무효화될 수 있습니다.** `snapshot-walk_choice_model.py` 279~286행은 낮은 확률로 같은 노선 suffix를 제거하지만, 185행 부근의 `walk_next`가 마지막 stage의 pool을 `compatible_single_stage_pools` 전체로 다시 확장합니다. 준비 자료의 node61→node62 / snu 단일-stage 대안에서 5511을 제거해도 도착 시 확장 집합에 5511이 다시 들어오는 것을 데이터 구조로 확인했습니다. 자세한 전후 집합과 준비 자료 SHA는 `static-pool-check.json`에 있습니다. 수정·시험 시 이동을 선택할 때 허용한 노선 집합이 도착 후에도 유지되는지 확인해야 합니다.

2. **40명·20분 기준이 진단 기준보다 강한 행동 강제 조건입니다.** 개인별 허용 줄 25~40에 도달하면 `forced=True`가 되고 거리 고려 확률·변경 확률·유예·개인 변경 예산 검사를 건너뜁니다(253~257, 266, 298~304행). 20분 타이머도 `assert maybe_switch(...,True)`입니다(354~357행). 강제 모드에서도 거리 점수 벌점은 남지만, 먼 거리를 선택하지 않을 확률과 기존 경로보다 빨라야 한다는 조건은 사라집니다. 기준 만족이 구성상 보장되거나 강하게 유도되므로, 자발적 선택·실측 적합과 구분해서 강제 개입량·개입 전 이상 사례를 보고해야 합니다.

3. **동일 정류소의 다단계 경로 전환은 여전히 history를 소비할 수 있습니다.** 마지막 단일-stage 노선 pool 확장은 history를 쓰지 않지만, `maybe_switch`로 선택하는 같은 장소의 다른 suffix는 323행에서 history를 증가시킵니다. ‘가능 노선 집합의 선택은 횟수 미소진’이라는 정책을 모든 전환에 적용하려는 것인지, 후속 환승 계획 변경은 실제 변경으로 셀 것인지 구분해야 합니다.

4. **20분 초과 검사는 원시 대기 행보다 물리적 연속대기로 해야 합니다.** 같은 장소에서 선택지만 바꾼 대기 행은 나뉠 수 있습니다. `physical_stop_entry`와 최종 이동 구간을 대조해 합쳐 검사해야 합니다. 기존 v7의 기준 집계는 별도 `continuous_wait_audit_2026-11-10`에 있습니다.

## 점검한 보존·정보·거리 조건

- 큐에서 빠진 질량은 `qmass` 또는 `premass`에서 차감된 뒤 새 도보/대기에 같은 `state.w`로 전달됩니다. 부분 승차는 복사한 분기와 잔여 분기로 무게를 나누고 최종 총량을 대조합니다. 정적 검토에서는 새 질량을 만드는 경로를 찾지 못했지만, 이는 후보 런타임 검증 통과 판정이 아닙니다.
- `premass`는 실제 arrive 사건에서만 추가합니다. 현재·과거 큐, 현재 탑승자, 계획 배차로 전망하고 미래 실제 큐/이후 승하차 결과를 직접 참조하는 코드는 발견하지 못했습니다. 앞으로 상류에서 탈 수요를 빠뜨리는 빈자리 낙관은 남아 있으며, 시각 누수와는 다른 문제입니다.
- 거리 선호 함수는 0~500m 동일, 500~1,000m 감소, 1,000m 이후 지수 감소입니다. 이는 고려 가중치이며 실제 선택 거리 분포가 균등하다는 뜻은 아닙니다.
- 거리 입력은 보행 경로 좌표를 따라 합산합니다. 다만 일반 이웃 후보 생성은 기준 도보 600초·최대 6정류소·정류소당 2노선에 제한돼, 1km 이후 선호 꼬리는 후보 생성 단계에서 대부분 사라질 수 있습니다. 특수 정문 접근과 직접 목적지 도보는 별도입니다. 사용자 거리 선호와 후보 탐색 범위를 구분해 설명해야 합니다.
- 사전 변경 예산 분포의 이론 평균은 1회입니다. 혼잡 시 예산이 늘고 확률적 선택도 있으므로 실제 평균 변경 횟수 1회를 보장하지 않습니다.
- 최종 stage pool 확장의 노선 방향·물리적 동일 정류소성은 준비 자료의 node/board 매핑과 함께 검증해야 합니다. 교내 셔틀 플래그가 켜졌다는 것만으로 모든 목적지의 모든 셔틀 대안이 확보됐다는 뜻은 아닙니다.
