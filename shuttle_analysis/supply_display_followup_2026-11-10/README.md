# 차량 정원 후속 연결 패치

현재 운행기회의 정원을 활성 대기모델의 공급 설정에서 가져와 수동 FIFO, 시간표 보완, 경로 응답과 여석 입력에 함께 연결했다. 기존 111파일 reader snapshot은 그대로 보존하고 이 패치를 별도 reader_stage_v2로 고정했다.

- legacy v9 활성 시 기존 60명 의미를 유지한다. 새 계약 활성 시 주간 행정관→설입 44명, 야간은 기존 60명 가정을 유지한다. 다른 노선 정원은 변경하지 않는다.
- ETA가 지연되거나 재조회 시각이 21시를 넘더라도 보관한 원래 터미널 출발시각으로 같은 차량의 정원을 정한다. 사용자 입력은 원래 출발시각만 전달하며 차량 정원 자체를 임의 지정하지 않는다.
- 수동 FIFO도 명시된 batch를 개별 차량으로 처리한다. 실제 관측 차량 목록은 다시 두 배로 늘리지 않는다. 여석은 각 선택 차량의 정원으로 제한한다.
- raw catalogue의 capacity는 종전 기본값으로 보존한다. 실제 계산은 활성 release의 with_vehicle_supply에서 덮어 쓰지 않은 새 응답 metadata를 만들며, 공유 catalogue 객체를 현재 시각에 따라 바꾸지 않는다.
- 공급이 바뀌면 옛 60명 기준 시간대 평균 추가대기를 새 44명 결과로 이름만 바꿔 사용하지 않는다. 최신 FIFO 계산과 순수 시간표 보완을 사용한다.
- 화면 입력 max와 안내는 선택한 운행기회의 vehicle_supply를 우선한다. 기존 25·60명 고정 문구를 제거했다. 이미 지나간 차량 또는 90초가 지난 입력의 종전 만료 규칙은 유지했다.
- 개인 경로 변경의 POLICY·decision·validate_context는 AST 대조로 불변을 확인했다. 시뮬레이션 에이전트가 소유한 별도 행동 모형은 이 패치에서 바꾸지 않았다.

## 검증

Python 120개, 기존 JS 설정 회귀 17개, 새 브라우저 표시/입력 시나리오 8개를 통과했다. 브라우저는 Browser 플러그인 부재로 설치된 Playwright/Chrome headless를 사용했다. 대상은 선택 회차의 수동 대기줄 입력이며 PC1280×960·모바일390×844에서 day44/legacy60/night60/reverse25의 상한, 초과값 거부, 원래 터미널 시각 전달을 확인했다. 앱 콘솔 오류는 없었다. 지도 어댑터와 API는 fixture로 대체했으므로 전체 실시간 길찾기나 실제 정확도 검증은 아니다.

증거와 스크린샷은 verification.json에 기록한 .codex/visualizations 경로에 있다. UI harness의 초기 상태 전환/숨김 실패는 바깥 증거 폴더에 보존했으며, 각 경우를 새 페이지로 격리하고 모바일의 실제 상세 컨테이너에서 다시 검증했다. Browser 플러그인을 설치하면 이후 인앱 브라우저 검증으로 이어갈 수 있다.

## 배포 인수

reader-stage-v2-manifest.json에 모든111파일의 경로·해시·크기를 기록했다. 소스와 기존 snapshot의 차이는6파일이며 추가 의존성 설치는 없다. 환경파일·인증파일·raw자료는 포함하지 않았다. 기존seed와latest는 이 작업에서 바꾸지 않았다. 원본은 before_apply, 패치는 supply-consumers.patch에 있다. 실제 배포와 발행은 ROOT 담당자에게 인계한다.

공급 계약 해시는 실제 compatibility 함수의 결과로 기록했다. 이전 문서의 single/pair 라벨 전도는 별도 보존 후 정정했으며 런타임 허용집합은 원래부터 정상이다.
