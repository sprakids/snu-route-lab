## 사용한 실제 API

혼잡도·차량 GPS는 승인받은 서울시 OpenAPI에서 직접 받았다.

```http
GET http://ws.bus.go.kr/api/rest/buspos/getBusPosByRtid
    ?serviceKey=<본인 인증키>
    &busRouteId=100100250
    &resultType=json
```

위 예시의 키는 자리표시자다. 실제 키는 코드·CSV·JSON·로그에 넣지 않았다. 실제 요청용 임시 키 파일은 읽은 직후 삭제했다.

정류장·노선 ID는 서울시 공식 모바일 버스정보 웹사이트가 사용하는 조회 인터페이스에서 확인했다. 해당 인터페이스를 공공데이터포털의 문서화된 OpenAPI와 구분한다.

```http
POST http://m.bus.go.kr/mBus/bus/getBusRouteList.bms
Content-Type: application/x-www-form-urlencoded

strSrch=5511
```

```http
POST http://m.bus.go.kr/mBus/bus/getRouteAndPos.bms
Content-Type: application/x-www-form-urlencoded

busRouteId=100100250
```

한글 검색은 공식 사이트의 `encodeURIComponent` 후 jQuery 폼 직렬화 과정을 그대로 따른다. `fetch_snapshot.py`에 반영했다. 장기 운영에서는 노선·정류소 OpenAPI의 별도 활용승인 및 해당 인터페이스의 이용 조건을 확인한 뒤 수집 경로를 정한다.

## 필드 해석

- `congetion`은 실제 영문 필드명이다. 문서상 `0=정보 없음, 3=여유, 4=보통, 5=혼잡, 6=매우혼잡`이다. 이번 실제 반환값은 전부 `3`이었다.
- `isFullFlag`는 만차 표시다. 이번 5건은 전부 `0`이었다. 혼잡 등급으로 정확한 승객 수나 남은 좌석을 계산하지 않는다.
- `gpsX`, `gpsY`를 각각 경도·위도로 보존했다. BUSIN 셔틀의 노선도 x/y와 다른 좌표다.
- `dataTm`은 제공기관의 데이터 시각, `captured_at_kst`는 수집시각이다. 이번 반환 차량의 두 시각 차이는 11.9~28.9초였다.
- 같은 정류장이 순환노선에 다시 나오는 경우를 위해 `route_id + stop_sequence`를 유지했다.
- `last_stop_name`은 공식 모바일 사이트의 정류장 목록과 매칭한 이름이며, 제공기관 원 ID `lastStnId`도 보존했다.

## 검증 및 한계

- 노선 ID 5개를 실제 노선 검색 응답에서 확정했다.
- 차량 5행 = 5511번 2행 + 5516번 3행이며, 고유 `노선 ID + 차량 ID`도 5개다.
- 차량 수와 혼잡 등급 합계가 일치한다. 정류장 순서 264건의 `노선 ID + 순번`도 모두 고유하다.
- 모든 대상은 HTTP 200을 받았다. `headerCd=0`과 `headerCd=4(결과 없음)`을 구분했다.
- 차량이 반환된 응답도 헤더 `itemCount`는 0이어서, 본문 `itemList` 배열 길이를 실제 반환 건수로 사용했다. 원본 헤더와 불일치 여부를 보존했다.
- 최초 마을버스 검색의 인코딩 차이로 비어 있던 응답, 최초 인증 조회, 중간 집계도 삭제하지 않았다. 최종 정리 자료의 출처 배치는 `manifest.json`에 명시돼 있다.
- 마을버스는 차량 본문을 받지 못했으므로 혼잡도 지원이 검증됐다고 표시하지 않았다. 5513번도 이번 시각에는 차량 본문이 없었다.
- 현재 노선의 모든 차량을 조회했으며, GPS 기반의 교내 경계 필터는 아직 적용하지 않았다. 정문 밖으로 이어지는 차량도 포함될 수 있다.
- 출퇴근 혼잡, 정류장 대기열, 수업 종료 효과나 경로 추천 정확도는 이번 한 차례 조회로 검증하지 않았다.
- 상시 수집·예약 작업은 만들지 않았다.

## 다시 한 번 조회하는 방법

Python 표준 라이브러리만 사용한다. 암호화 보관된 키가 있으면 자동으로 읽는다. 아직 키를 보관하지 못한 상태에서는 `SEOUL_BUS_SERVICE_KEY`를 실행 환경에 안전하게 공급한 뒤 실행한다.

```powershell
python .\fetch_snapshot.py
```

특정 노선만 조회할 때:

```powershell
python .\fetch_snapshot.py --routes 5511 5513 5516
```

매번 새 `snapshot_날짜_시각` 폴더를 만들고 기존 결과를 덮어쓰지 않는다. 자동으로 반복 실행하지 않는다. 명령줄 인수에 키 자체를 넣지 않는다.

키 없이 위의 주간 도착예정 표본을 다시 조회할 때는 `python .\fetch_public_arrivals.py`를 실행한다. 이 스크립트도 5개 요청을 한 번만 수행하고 새 결과 폴더를 만든다.
