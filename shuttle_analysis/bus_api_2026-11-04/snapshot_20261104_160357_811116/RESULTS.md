# 암호화 보관한 키로 실제 API 호출 검증

수집시각: **2026-11-04 16:03:57~16:03:58 KST**. 기존에 승인된 서울시 버스위치정보조회 OpenAPI를 5개 노선에 호출했다. `SEOUL_BUS_SERVICE_KEY` 환경변수를 제거한 새 Python 프로세스에서 키 파일 인수 없이 실행했으며, `credential_store.py`가 Windows CurrentUser DPAPI 저장소의 키를 읽었다. API 키의 실제 저장과 재사용까지 검증했다.

모든 노선이 HTTP 200, `headerCd=0`이었다. `congetion=0`은 정보 없음, `3`은 여유, `4`는 보통으로 분류했다. 정보 없음은 여유 상태를 뜻하지 않는다. 42건은 노선 전체의 반환 차량이며, 교내 경계로 필터링하지 않았다. 정류장 대기열이나 정확한 승객 수를 나타내지 않는다.

- [차량별 CSV](vehicles.csv), [JSON](vehicles.json): 혼잡도 원값, 차량 ID, GPS, 제공시각, 수집시각 포함.
- [요청·집계 기록](manifest.json): 요청에서 인증키를 제외한 인수와 응답 상태, 노선별 집계.
- `raw/`: 원문 응답. 응답에 키가 포함되면 제거하는 처리를 적용했고 저장 후 키 원문 및 인코딩 변형의 부재도 검사했다.

15:54 공개 웹 조회는 특정 정류소의 다음 두 도착예정 버스이고, 이번 조회는 노선 전체 차량위치다. 표본과 필드가 다르므로 혼잡도 변화량이나 차량 증가량을 직접 계산하지 않았다. 마을버스는 이번 위치 API에서 모든 차량의 혼잡도 값이 0이었다. 앞선 도착예정 응답의 재차인원과 혼잡도 등급을 구분해서 사용해야 한다.

## 키 저장 확인

기존 키는 프로젝트 밖 `%LOCALAPPDATA%\SnuTransit\credentials\seoul_bus_service_key.dpapi`에 암호화돼 있다. 임시 평문 전달 파일은 저장 직후 삭제했다. 실제 키 원문은 코드·문서·명령줄·로그에 출력하지 않았다. [저장 검증 기록](../credential_storage_status.json)에 비밀값을 제외한 상태를 남겼다.

이후 이 폴더의 상위 디렉터리에서 `python .\fetch_snapshot.py`를 실행하면 저장된 키를 자동으로 읽는다. 이번에는 한 차례만 수집했고 예약 작업은 만들지 않았다.

근거: [서울시 버스위치정보조회 OpenAPI](https://www.data.go.kr/data/15000332/openapi.do), 이번 실제 원문 응답과 `manifest.json`.
