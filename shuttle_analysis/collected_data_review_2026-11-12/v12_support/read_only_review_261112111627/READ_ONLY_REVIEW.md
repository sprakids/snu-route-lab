검토 범위는 고정 코드와 입력의 정합성입니다. 시뮬레이션 실행, 계수 적합, 운영 모델 승격, 새 날짜의 관측 정답 열람은 하지 않았습니다. 후보 실행 중인 파일도 수정하지 않았습니다. 입력·코드 해시는 `review.json`에 보존했으며 검토 전후 11개 파일 모두 동일했습니다.

## 확인 결과

- `time_profiles.py`는 각 링크 **진입시각**에서 소요시간을 선형 보간합니다. 모든 프로파일의 벡터 길이·양수/유한값을 확인했고, 최소 링크 도착함수 기울기는 **0.889537326 > 0**입니다. 각 링크 도착함수가 연속·엄격 증가하므로 이들의 합성이 되는 다중 링크 도착도 순서를 보존합니다. 60,975개 경계 전후 스칼라 비교에서 독립 보간과 최대 차이는 약 1.14e-13초였습니다.
- 후보 `operations.py`와 `analyze_followup.py`에서 추출한 도시버스 시계 재구성 함수를 같은 고정 입력으로 대조했습니다. 5개 요일의 **4,635개 도시버스 여정**에서 모든 정류장 시각이 정확히 일치했습니다. 이는 시계 구현 일치이며 현장 도착 정확도 검증이 아닙니다.
- `v12_supply.py`의 통과시각 역산을 8개 노선·6개 시간 경계에서 추가 점검해 오차 2e-5초 이내를 확인했습니다. 고정 입력에 기록된 전체 역산 진단 최대 오차는 약 9.97e-7초입니다. 역산은 기준 정류장 통과를 첫 모형 정류장 시작시각으로 바꾸며, 차고지 실측 출발로 부르지 않습니다.
- 공급 역산 함수가 프로파일 요일 0을 쓰는 부분은 **현재 모든 요일 프로파일이 동일함을 빌더에서 검사**하므로 이번 후보에서는 시계 불일치가 생기지 않습니다. 이후 요일별 프로파일을 다르게 만들 때에는 역산에도 요일 인자를 전달하고 다시 검증해야 합니다.
- API `crowd_code=0`은 `None`, API 3은 정규화 0입니다. CSV 정규화 0은 여유이며 미확인이 아닙니다. 두 마을버스 노선의 관측 혼잡 셀은 비어 있고, 미확인 노선은 관측 여유로 치환하지 않습니다.
- 등급 분포·전이행렬은 음수가 아닌 4개 순서형 범주입니다. 혼잡 확률을 링크별 시간과 곱해 합한 노출 비용은 0과 해당 승차 구간시간 사이였고, 실제 인원·여석으로 환산하지 않습니다. 만차 확률과 임의 도착 기준 대기 참고치는 진단 문맥이며 개인 대기 정답이 아닙니다.
- `policy.py`에서 관측 등급이 없을 때 사용되는 모형 재차비율은 관측 인원이 아닌 시나리오 fallback입니다. 이 구분이 문맥에 유지됩니다.
